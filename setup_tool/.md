# setup_tool/ — 资源配置辅助工具

**作用**：管"主程序管不好的那几件事"——素材/角色卡放在哪、缺什么、key 通不通、数据在哪。
主程序是**玩**的界面，它是**配**的界面，所以是**另一个 exe**（`Live2BeSetup.exe`，
onefile，跟主程序放同一目录就能共用同一份 `settings.toml` / `config` / `assets` / `data`）。

## 核心文件

| 文件 | 管什么 |
|---|---|
| `checks.py` | 体检逻辑（纯函数，**不 import tkinter**）：五个根 / 角色卡 / 素材 / 数据 / 连通性 |
| `ui.py` | tkinter 界面：显示结果 + 选目录 + 写 `[paths]` |
| `main.py` · `__main__.py` | 入口；`--check` 只打报告不开窗口（脚本/排障用） |

跑：`python -m setup_tool`（界面）· `python -m setup_tool --check`（控制台体检，有 BAD 时退出码 1）

## 三条纪律

1. **不手搓判据**：角色卡用 `CharacterLoader`、连通性用现役 `LocalEmbedder`；
   背景缺不缺要按**地点表自己声明的 `files: {day,night}`** 去对磁盘 —— 别拿"文件名索引"
   那套猜（我第一版用 `MediaCatalog.background(地点key)` 查，168 个地点报出 103 个假阳性）。
2. **真源只读**：`data/` 是 append-only 事件流，工具**不写**；要备份只许复制（界面只给路径）。
3. **写只走 `infra.settings.write`**（唯一写入口），且只碰 `[paths]` 的 `config/assets/data`
   三个键 —— `app`/`resource` 是程序的落脚点，不给改。**`[paths]` 是启动时读取的，
   保存后必须重启主程序**（界面会提示）。

## 界面上有什么

六个按钮：重新体检 · 选素材目录 · 选角色卡目录 · 选数据目录 · 打开数据目录 · 清空 `[paths]`。
结果按组显示，等级用颜色分：`OK` / `注意`（会静默降级）/ `问题`（现在就是坏的）。
