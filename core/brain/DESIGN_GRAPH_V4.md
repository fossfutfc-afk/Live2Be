## 2. 仍然生效的两条判据

**① 三种组织形式 + 准入三问**（§1.1，2026-09-23；`experience` / `promise` / `item`
反复定不了调的那次结案）：

| 形式 | 装什么 | 价值来源 | 消费方式 |
|---|---|---|---|
| **图**（`wiki.jsonl` + `edges.jsonl`）| **离散事实**：一次经历 / 一条看法 / 一个对象 | **邻接**（能沿边走）| 常驻注入 + 将来她主动 `recall` |
| **笔记**（`notes.json`）| **跨事件汇总 / 当前状态** | 内容 + 当下有效性 | **常驻**（小、有限）|
| **台账**（`inventory`）| **当前持有** | 内容 + 来源 | 按需查（**只留接口**）|

三问：**1) 引擎要不要处理它？**（要 ⇒ 严格结构化；只搬运 ⇒ 可自然语言）
**2) 它靠邻接定义吗？**（靠 ⇒ 图；不靠 ⇒ 笔记/台账）
**3) 它是痕迹、当前值，还是汇总？**（痕迹 ⇒ episode 字段；当前值 ⇒ 台账 / entity `state`；汇总 ⇒ 笔记）

**② 边的存在理由 = 有一条能走的路**（§2.2）。⚠️ 图没有 traverse 者时 ≈ **带 id 的列表**。
判据的两面：**"永远不会有走法"**（起点 kind 退役 —— `source` 就是这么删的）⇒ 删；
**"还没有走法"**（`contradicts` / `evolved_from` 今天 0 条）⇒ **留着**，别拿真机 0 条当理由删。

## 4. 已否决 / 已结案（**别再提**）

| 项 | 结论 | 理由 |
|---|---|---|
| **节点做成父类 / 子类** | ❌ 不做（2026-09-21 用户裁决）| 要动 ~60 处分派点 + store + 一大批测试，而本仓**没有类型检查**（`isinstance` ≡ `kind ==` 运行时等价）⇒ 拿不到静态分派安全；字段归属用**表驱动**更便宜 |
| **运行时用 networkx（或现成图 API）** | ❌ 不做（2026-09-21）| ① 磁盘格式被它的 schema 绑住（`node_link_data` 的 `links`→`edges` 改名会逼我们迁移，与"旧档宽容读、无迁移脚本"冲突）② 运行时加依赖（`brain` 纯 stdlib）③ 原子写 / 宽容解析仍得自己写。**dev 侧照旧可用**（`tools/wiki_viz.py`）|
| **`aspect` / `same_kind` / 边带属性** | ❌ 已推翻（2026-09-29）| 群 = **节点 + `member_of` 边**；`Edge` **一个字段都不加**（成员各有自己的 `ts`，"什么时候加入的"是信息）|
| **`nature = pattern`**（experience 并入 belief） | ❌ 提案关闭（2026-09-25）| "模式"的落点是 **belief 的模式句**（段内）+ note（跨段）|
| **`degree ≥ 2 浮现`** | ❌ 不做 | 沿 `supports` 数即可 |
| **`fact` / `promise` / `source` 边 / `formed_by`·`from`·`to`** | ⛔ 已退役 | 判据 = **起点 kind 没了 ⇒ 永远不会有走法** |
| **`inventory` 独立成系统** | ⏸ 暂不做 | 接口留着（`DESIGN_RECALL` 的空占位）|

## 5. 能力面：`function_call`（判据仍生效）

`mmt_recall {scope, query, when}` = 计划新增的第 **5** 个动作（契约全文 `docs/DESIGN_RECALL.md`）。
⚠️ **bond 里没有 `function_call`**（VN 是记录流）⇒ bond 侧的"记忆动作"只能靠 digest 事后做。
⭐ **图的价值因此重新定位**：不是"给引擎分桶注入"，而是"**给她自己查**"。

**加动作的判据四条**：① 同族操作 ≥3 ⇒ **合并**成一个动作 + 参数 ② 两个动作模型可能分不清 ⇒
改描述或合并（⚠️ **重叠比数量更致命**）③ 动作名要**意图形状**（`schedule_event`），不要 API 形状
（`create_event`）④ **一次开全**（spec 进 system ⇒ **每次加动作 = 废一次前缀缓存**）。

**"动作 vs 输出字段"的判据**：*"我需要它才能说下一句" → 动作；"我说完了顺手记一笔" → 输出字段。*

**未实现的工程要求**：轮内多步（loop + 步数预算）· 结果**只往尾部插**（不动 system/history 前缀）·
回忆动作要**落事件流**（否则回放丢了"她当时想起了什么"）· `window_messages` 要认 tool 消息。

## 6. 外部参照（四条结论）

| 参照 | 对我们的结论 |
|---|---|
| **AgentGal**（四层 + 零工具）| "笔记层"这条路成立（散文槽 + 类型化清单分家）；⚠️ 但**它的 link 同样没被走** ⇒ 光有边不够 |
| **BaiShou**（按日历分层总结）| ⭐ **"抽象总结不需要图"** —— 任何 flat store + LLM 都能总结 ⇒ **图的价值只在 traverse**；另：**不做去重压缩**（"重复的频率本身就是羁绊的厚度"）|
| **Zep / Graphiti**（边带有效期）| "演化"的第三条路：旧边**失效**而非删除。我们的 append-only 事件流天然是**摄取轴**，缺的是 **valid 轴** |
| **工具面**（AgentGal / Anthropic / Meta）| 工具越多越选不准（最优 **2~7** 个，"语义相似的工具变多"是主要杀手）⇒ 我们 4→5 远在安全区，真风险是**语义重叠** |
