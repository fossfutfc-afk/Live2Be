# core/brain — 角色的记忆（图式 wiki）

**作用**：她记得什么、怎么想起来。图（点 + 边）+ 笔记 + 读路径都在这里，**零 LLM、纯 stdlib**
—— 判定与写作归 `core/digest/`（消化）与主 LLM（创作）。

## 三条边界

1. **零 LLM**：不 import `llm` / `core.digest` / `core.session` 的编排件；契约层只许取纯值常量
   （如 `ENTITY_TAG_PREFIX`）。digest 管线因此住在 `core/digest/`。
2. **读写分家**：写路径（`store` `graph` `revise` `notes` `entities`）与 `read/`（只读、不写图）。
   分家的价值是把"读的不会顺手改数据"从口头纪律变成**包边界**。
3. **`marks.py` 是她眼前那行字的唯一实现** —— 别的模块只许调它，不许手写括号
   （守门 `tests/core/test_marks_guard.py`）。

## 数据在哪（`data/worlds/{w}/characters/{c}/soul/`）

| 文件 | 是什么 | 谁写 | 谁读 |
|---|---|---|---|
| `wiki.jsonl` | 点 —— 一行一条 `BrainNode` | `store.commit()` | 读路径 |
| `edges.jsonl` | 边 —— 一行一条 `{rel, src, dst, ts}` | `store.commit()` | `graph` |
| `notes.json` | 笔记的**派生缓存**（真源 = 事件流的 note 操作） | `store.save_notes()` | 注入 |
| `evolution.jsonl` | 修订审计（append-only；R6 回滚依据） | `revise` | 诊断 |
| `wiki.meta.json` | 水位 `digested_seq` 等 | `store.commit()` | digest |
| `wiki.txn.json` | 提交日志（**只在提交进行中存在**） | `store.commit()` | `store._roll_forward` |

提交是**一个事务**（`store.commit()`, `save()` 同款）: 先把点 + 边 + meta 一次性原子写进
`wiki.txn.json`, 再逐份覆盖真文件, 最后删日志; **加载时若发现日志残留就照它补完**（幂等）。
所以"点新、边旧"和"图新、水位旧"都不会出现 —— 后者会让同一批事件被再喂一遍（正文不同
就多出一份记忆）。`notes.json` 不在事务里: 它的真源是事件流（见 `save_notes`）。
读侧仍然宽容（悬空边保留, 在 `audit()` / `Graph.dangling()` 里可见）: 事务保证的是**写入**完整。

## 点：四种 kind

`KINDS = ("episode", "experience", "belief", "entity")`

| kind | 是什么 | 关键字段 | id 前缀 |
|---|---|---|---|
| `episode` | 一次性经历 | `text`（第一人称浓缩）· `verbatim`（原话的记录行号，唯一通道）· `observer`（空 = 亲历，非空 = 转述者）· `title`（地址）· `event_seq` | `m` |
| `experience` | 一类事的沉淀（"经验"） | `title` = 类名 · `text` = 这一类说明了什么；成员走 `member_of` 边（**不在节点上存列表** —— 成员会生长、各有自己的 `ts`） | `g` |
| `belief` | 抽象认知（看法） | `text` = 结论 · 至少一条 `supports` 入边 · 可选 `growth` · `subject` | `m` |
| `entity` | 人 / 地方 / **她自己**（"我知道的名字"） | `name`（主名）· `aliases` · `text`（她对它的看法；`x0000` 的 `text` = **成长基线**）· `state`（物理状况，一句一行） | `x` |

不留的 kind：`fact`（2026-09-02 退役）· `profile`（玩家画像，2026-10-14 删格式）· `promise`
（2026-09-29 退图 —— "承诺太轻，不足以长期记录"，约定改住笔记）。旧档里认不出的 kind 由
`from_dict` 降级成 `episode`，不炸（无迁移脚本）。

不变量（`validate` / `normalize` 强制）：

- `belief` **不许带 `observer`**（认知不伪装成事实）；
- `belief` 必须有 `supports` 入边 —— 支撑关系住在边表里，字段级校验看不见它 ⇒ 判在 `store.audit()`；
- `significance ∈ 0~1`，珍贵档 ≥ `PRECIOUS_THRESHOLD`（0.8）；越界 clamp；
- 去重键 = (kind, `event_seq` 有交集, 主文本相同)。

## 边：六条 rel

| rel | 方向 | 语义 | 对称 |
|---|---|---|---|
| `about` | 点 → `entity` | 归属（"这条记忆关于谁"） | 否 |
| `supports` | 经历 → 看法 | 证据；两种形状（episode → belief 与 belief → belief） | 否 |
| `contradicts` | 同层之间 | 互相打架 | **是** |
| `evolved_from` | **旧 → 新** | 看法的演化（**时间顺向**；"谁取代了我"是入边） | 否 |
| `akin` | 经历 ↔ 经历 | 她认过的"同一类事"（写者只有她，经 L1） | **是** |
| `member_of` | 经历 → `experience` | 同类兄弟 | 否 |

- **先把方向写成一句话（`X → Y`）再写代码**。`Graph.related` / `Graph.conflicting` 是"两个方向
  都查"的唯一实现；只查一端是历史上犯过四次的错（`supports` 查 `sources` 恒空且不报错）。
- **对称 rel 存进去会被 `canonical_for` 归一**（只留一端序），所以查询必须走 `Graph.related`。
- `REL_UNKNOWN` **只属于推断层**（旧档的 `links` / `contradictions` → 带类型与方向的边，
  `infer_edges`）：丢掉它会让 1-hop 扩展比老的 `links` 更窄（行为回退），所以照发；而"判不出
  类型"在 `stats()["unknown"]` 里可见 —— 写路径落盘后总是知道 rel，那个计数应当归零。
- 三个索引（按 `src` / `dst` / `rel`）+ `Graph.dangling()`（悬空边）。

## 归属：entity 与"面"

- **匹配面**永远是 `surface_forms(node)`（`name` + `aliases`）；**归一** = `entities.form_key`
  （去掉所有空白 + `casefold`）。卡上主名中间带空格（`伊草 遥香`），而 brain 段印的就是她要
  照抄的键 —— 少打一个空白就 miss。同一套归一只有这一处，调用方**不要再 `casefold()`**。
- **保留号**：`x0000 = self`（"我"）· `x0001 = sensei`（老师 / 玩家）。幂等判定查 id，不靠名字
  匹配（"老师"会被玩家改名）。`store.next_id("x")` 因此从 `x0002` 起 ⇒ `ensure_entities`
  **必须在任何"自动建 entity"之前跑**。
- **默认归属** = `graph.DEFAULT_FACES`（`episode` → self + sensei · `belief` → self）。
  它**只当读侧口径，绝不落边**：落边会给真机图加 46 条常数边；更关键的是 `Edge` 里没有位置
  记"这条是默认来的" ⇒ 图里再也分不出"她明确说关于老师"与"按介质默认"，而那个区分正是归属
  这个信号的全部价值。
- 名字从**参数**来：`self` ← `config/characters/{id}/profile.yml`（经 `parsing.names`）；
  `sensei` ← `config/player/profile.yml` + `data/basic/player.json` 的运行时自取名。`core/brain/`
  不读 config。

## 笔记：只有一个槽

`notes.py` 管**她自己挑过的东西**。真源是事件流里的**操作**（`add` / `close` / `update` /
`rewrite`），`soul/notes.json` 只是 `fold()` 的**派生缓存** ⇒ 并发安全（主 LLM 与 digest 同时写
不丢更新）、可回放、可随时重建。本模块**纯函数、零 IO**（落盘归 `store`）。

- 只一列：她随身带着的事（誓约 / 重大的约定）—— 没有"槽"这一层（2026-10-18 塌掉）。
- `close` = **划掉即移除**（没有"结清但留着"的两段式）：本子是**当前抽屉，不是账簿**；结局
  （兑现 / 失约 / 被取代）是图里那条经历的正文。
- `update` 只改两样：`due`（补 / 更正日期）· `text`（重写那句话）—— 不许改 `refs` / `since` / 槽。
- `id` 只增不复用（复用会让旧引用指错条目）；总量上限 `MAX_NOTE_CHARS = 500` 字。
- 注入两处：常驻的【你自己记的备忘录】与召回段里的引用。

## 写路径：谁往图里落东西

`revise.py` 三趟，与 `core/digest/rounds/` 的三轮一一对应：

| 入口 | 轮 | 干什么 |
|---|---|---|
| `apply_relations` | `relate`（L1） | 边行 → 边表（**一个字的正文都不写**） |
| `apply_cognitions` | `cognize`（L2） | 造 `belief` / 覆写沉淀 + 出生自带边；带 `id` = **改**已有的（只改写出来的格子；边只增不减） |
| `apply_attribution` / `apply_stances` | `settle`（R3） | 认人：建 `entity` + `about` 边；改已有的对象（改名 / 写看法 / **改写她自己的成长基线** `x0000.text`） |

- **原子性由编排层保证**（digest 全程快照，任一失败 `restore_state`）；本层抛 `ValueError` → 回滚。
- **水位**：`cognize` / `settle` 的 `text` 要过水位（同一段重跑不许把同一条正文再改写一遍）；
  `name` 天然幂等（不需要水位）。**空值 = 不改**（不是清空）。
- **`akin` 并进证据**：一跳邻域并进 `supports`（零 LLM，额度 `AKIN_JOIN_MAX = 5`）；打架的证据
  不许共撑一个结论（先到先得）。
- 每步都往 `evolution.jsonl` 留痕（`before` / `after` / 包归属）—— 那是"这包改了什么"的唯一账。

## 读路径：她怎么想起来

### 注入视图（`read/render.py`）

会话打开时装填一次，digest 后**下轮**生效。`render_character_view` 四块，顺序即注入顺序：

1. **我记得的事** —— `episode` 一条河（旧 → 新）；
2. **我知道的名字** —— **她认识的 entity**：一行 = 主名 + 有看法就接 `：text`（不印别名、不印类别）。
   这张表同时是她的**键面**：`look(entity=…)` 与 P19 的 `name` 段认的都是 `surface_forms`，
   匹配走 `form_key`；
3. **我心里渐渐觉得** —— `belief`；另有「老师的事」/「我听说的」两个分区（按 `observer`）；
4. **【我是谁（成长基线）】** —— 她自己的那一格（`x0000.text`），整段记忆的**最末**
   （紧随其后就是备忘录）。它是"我此刻是什么样子"，**不是**"我认识的一个人" ——
   所以不跟名表混在一起（混着时模型只能靠名字去猜哪个是自己）。
   写它的只有一个地方：digest 的 `settle`（料 = 【你自己】）。

### 召回：五条链路 → 合成 → 两种形式

| 链路 | `kind` | `raw` 是什么 | 归一 |
|---|---|---|---|
| A 正交矩阵 `SIG·TIME + emo_span·emo_int` | `PRIOR` | `det`（值域 [0,2]） | **不归一**（它是强度轴） |
| B 情绪数组 RAG（`emo_shape` 的 cos） | `SIMILARITY` | cos | 池内 min-max |
| C 地点（素材字面 × 叙事语义） | `GATE` | `magic` ∈ (0,1] | 原样（既准入又当证据） |
| D 既视感（正文 RAG） | `SIMILARITY` | cos | 池内 min-max |
| E 无意识（认知碎片 RAG） | `SIMILARITY` | —— | 未立项 |

合成 = `compose.compose()`：`rel = 1 − ∏(1 − sᵢ)`（noisy-OR）+ `prior` → **调和平均**
（`infra/fuse.py`，与 C 链路的 `magic` 同一个函数）；证据轴按**名次门槛**取 top-k
（`[recall].sim_k`）—— 名次不是分数阈值。

**`SIMILARITY` 必须池内 min-max**：真机实测 cos 的绝对值不可分（域外最大 0.798 > 同角色最小
0.781）；把绝对值当相关度喂进融合，`prior` 会永远是两轴里小的那个，融合退化成"只按 A 排序"。

**两种形式**（`read/modes.py` 的 `MODES` 表 —— 加一个形式 = 表里加一行，别在执行器里写
`if mode == …`）：

- `rank`（`like.like()`）：六路打分 → 池内归一 → 证据轴至少一路命中 → 加权排序 → 最像的 ≤ k；
- `set`（`find.find()`）：**确定的**判据（名字 / 时间区间 / 图上相邻）→ 命中的**全部**
  （不漏即正确；裁不裁归渲染的字符预算）。**两套判据不混成一个分**。

前门（P19 的三段 + 她的显式查询）：

- `name`（set）：玩家这句**提到了一个名字** ⇒ 那个对象 `about` 车道上全部（保留号不算"提到了谁"）；
- `when`（set）：玩家这句里有**时间词** ⇒ 那段时间里全部；**只查 exact，不放宽**；
- `turn`（rank）：每轮兜底的 1~2 条（六路权重在 `like.SPECS["turn"]`）；
- `look`（她的动作）：`entity` / 标题 / 时间窗 —— 标题那一级走 `address`（地址解析）；
- `recall_subgraph`（一跳扩展）与 `walk.py`（`bfs` 找同类 / `chain` 深挖，**接口在、未接线**）。

### 台账（`read/recall_ledger.py`）

两行：**写路径**（候选覆盖率 —— A 链路的候选里有多少对得上她写的内容）与**读路径**（注入了哪几段、
各几条、被预算裁掉几条）。它是**数字不是告警**；`⚠no_candidate` 是留给 grep 的标记。

## 她眼前的括号（`marks.py`）

`【】`段头 · `〔〕`信息头 · `《》`事件名（= **地址**：她照抄进 `{"noticed": …}`，引擎拿它查库）·
`（）「」`正文与原话 · `[]`历史动作前缀 · `{}`JSON 行。字段分隔是 `｜`，`·` 是并列**不是**字段边界。

三条不变量：**一形一义** · **空字段不占位**（位置因此不固定 —— 判"哪一段是名字"要按书名号找）·
**名字只有一处印法**（多一处就多一次静默命中 0）。它零依赖、零 IO，谁都能 import
（`render` 与 `notes` 之间有延迟 import 的环，公共件放进任一方就会反向依赖）。

## 纪律与坑

1. **方向**先写成一句话再写代码；对称 rel 只查一端必然漏一半。
2. **加常量 / 字段前先问"谁读它"** —— 零读者的旋钮是假旋钮（`admit` / `cap` 故意没加）。
3. **退役分两种**：整行死了（`profile` / `promise`）⇒ 认得出、丢行、记账；只是行内一格死了
   （`about_hint` / `items` / `topics`）⇒ 白名单外**静默不落库**。
4. **旧档宽容读**：认不出的 kind 降级成 `episode`、废弃键忽略、无迁移脚本。
5. **真机数据只读**：探针可以读、可以在内存里改，**绝不 `save()`**。
6. **id 空间不能混**：真身 `x…` / `m…` / `g…` 与本地号 `c…` / `u…` 是两套；混了会把"挂谁"与
   "挂在谁身上"写反。
7. **别名 / 名字写错不可逆** —— `ensure_entities` 撞上时**只填空 `text`**，绝不覆盖 digest
   长出来的立场，也绝不合并两个对象。
