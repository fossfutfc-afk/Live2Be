# digest/ — 记忆消化管线

**作用**：把**新事件**消化成图里的记忆。一段事件流（MMT 每 25 轮 / bond 闭环触发）进来，
出去的是 episode 节点、边、看法、对象，外加一本随笔（note 操作）。
它跑在 `core/brain/`（图 + 笔记，纯 stdlib、零 LLM）之上，是本项目**唯一"要钱"的批处理**：
一段 = 5 次 LLM 调用 + 1 次零成本补边。

## 一次 `digest_segment` 的数据流

```
new_all（水位之后全部事件, 含 marker）
  └─ 内容事件 = is_content_event（marker / affection / note 都不算）
       └─ 保险丝: > DIGEST_WINDOW_EVENTS_CAP(120) 条 ⇒ 丢最老的未认领 + 一行 warning
            └─ for spec in ROUNDS: IMPL[spec.key](ctx)      ← 顺序只由表说, 越序当场炸
                 └─ 每轮: 料(material) → system+契约(call) → parse(contract) → 落图
                      ├─ 成: 原子提交（save 一次）+ 水位 = 她这次覆盖到哪（`_next_watermark`）
                      └─ 败: 内存回滚（`restore_state`）+ `reset_result`（按表清字段）
                              └─ 数到 DIGEST_MAX_ATTEMPTS(3) ⇒ 放弃这段 + 留一条 creep 账
                       └─ 关停: 同样回滚, 但**不写盘、不计失败次数**（`aborted`, 见 `_abort`）
```

三个原子性要点：**快照**（`store.clone_state()`，点与边一起）、**回滚清单由表推导**
（`RESULT_FIELDS` / `reset_result`，不许手抄）、**水位只在成功后才动**。

关停为什么单独一条出口：这段代码跑在守护线程里，进程一退就在任意一行被掐死。若把"被杀"
当成失败去计数，**三次 Ctrl+C 就能让这一段被永久放弃**（推水位 + 落账）。所以
`infra/runtime.py` 的信号在**每轮之间**与**提交前**各查一次，命中走 `_abort`（回滚内存、
不写盘、不动 `digest_retry`）。另外提交是"先写图、后写水位"两次原子替换，中间被杀会留下
"图新水位旧" ⇒ `WikiStoreV2._heal_watermark` 在**加载时**按图上的 `event_seq` 把水位补到
正确值（只改内存：探针按只读口径打开 wiki，加载期写盘会污染真机数据）。

## 核心文件

| 文件 | 是什么 |
|---|---|
| `rounds/__init__.py` | ⭐ **轮次表**：步序 / LLM 身份 / prompt / 契约相位 / parse / 料 / 写什么 / 跳过条件 / 预算 / 是否自带快照。**改行为先看它** |
| `rounds/base.py` | `Ctx`（段级上下文 + 六个薄转发）+ `RoundOut`（一轮的交代） |
| `rounds/{split,record,akin,relate,cognize,settle}.py` | 六轮的正文，每个 `def run(ctx) -> RoundOut` |
| `pipeline.py` | 编排与事务：`for spec in ROUNDS` · `DigestResult` · 回滚 / 自吞 / 计数 / 放弃 · 水位 |
| `call.py` | 一轮 LLM 调用：system + 契约装配 · 反馈重试 · 本轮截止 · 带轮次的失败文案 |
| `material.py` | 各轮的**料**（引擎侧零 LLM）：段标题校对拼装 · 视觉记忆 · 情绪标尺 · 约定行 · L1 候选 · 碰撞 · 对象正文 |
| `segment.py` | 这一段是什么：段类型 / 章分组（从 marker 派生）· `span` → `seqs` 展开 · 一章一条收口 |
| `episodes.py` | L1 落节点：字段归属（引擎定，防幻觉）+ 去重 + 自己的时刻 + 逐字原话 + 情绪/地点物化 |

## 纪律

1. **顺序 / 身份 / 料 / 跳过 / 预算只能写在表里**。`pipeline.py` 不许出现第二个轮次清单，
   `_rollback` 的清空清单也由表推导（手抄过一次，漏了字段）。
2. **一轮一个文件**：`run(ctx)` 只干这一轮。跨轮状态只有 `Ctx` 上那三格
   （`episode_ids` / `r2_created` / `resp_a`）—— 加第四格之前先问"它真是跨轮的产物吗"。
3. **失败要能整段消失**：落图全在内存 store 里做，磁盘只在成功后 `save()` 一次。
   事件 append 不可撤销 ⇒ `notes_ops` / `creep_rows` 交给调用方，在 `ok` 之后写。
4. **账不随事务回滚**：失败与放弃各留一条 `creep` 账（`digest_skip` / `digest_gap`）——
   它们记的是"**她少了什么**"这个事实，不是剧情。
5. **宁缺勿错**：任何一轮失败都不阻断主链（MMT 继续聊、bond 继续走），这段记忆留给下次。
6. **料的名字就是靶子**：`_sections_for` 逐字校对"这一轮吃什么"的段标题，对不上当场炸 ——
   比"少给一段料、让模型自己编"便宜得多。

## 改之前先知道的几件事

- **`new_all` 与 `new_events` 不是一回事**：段类型要从 marker 派生，所以窗口含 marker；
  真正喂给 LLM 的只有内容事件。
- **段 ts = 段内最后一条内容事件的时刻**，不是 `now()` —— 那是写库时刻，不是记忆形成时刻。
- **区间会交叠**（`akin` 归属取"起点更大"那条）；**无区间那一行**不是漏了，
  是一条"没有那一刻"的经历（正文 = R0 给的 abstract，不经 R1）。
- **`L1` / `L2` / `L3` 有两个含义**：三段层次（本段 / 跨段 / 实体）与两趟（判关系 / 写正文）
  **同名不同物**，读注释时先看它引的是哪份设计稿。
