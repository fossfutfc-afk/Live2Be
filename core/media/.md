# media/ — 素材查库

**作用**：把 `assets/` 那堆文件变成可查的索引（背景 / 差分 / spine / 画廊 / 情绪词表），
外加**地点语义键表**与它的融合算术。它**不生成**任何东西、不调 LLM、不写图 ——
只回答"这个场景用哪张图 / 这个情绪有哪些差分 / 这个地点叫什么键"。

查不到一律 **`None` / 空表 + `error`，绝不抛**（宁缺勿错：素材缺了要能继续讲剧情）。

## 核心文件

| 文件 | 是什么 |
|---|---|
| `catalog.py` | **总入口** `MediaCatalog`：背景全量 + 差分按角色懒加载（查不到 → `None`） |
| `background.py` | 背景命名派生（`assets/background/`，**零 manifest**） |
| `manifest.py` · `sprites.py` | 角色差分 manifest（真源 = `assets/illustration/{char}/emotions.yml`）与 spine 导出 |
| `sprite_player.py` | 差分的**播放层**（独立于 `tui/`，两者都调它） |
| `emotion_lexicon.py` | 情绪词表逐行解析 + 注入渲染（`build_emotion_injection` / `render_emotion_scale`） |
| `gallery.py` | 画廊：AI 生成的 2D 场景（图 + 文字信息成对） |
| `place_table.py` | **地点语义键表**（`config/settings/world/place_entities.json`）：mtime 缓存 · 重复键检测 · 坏条目逐条丢弃 |
| `place_fuse.py` | 地点**素材轴**的字面相似（`key_similarity` 三件）+ 把 `infra/fuse.py` 的形状原样 re-export |
| `place_rename.py` · `place_renames.py` | 地点改名的工具（扫引用面 + 改表）与台账（`soul/place_renames.jsonl`） |

## 纪律

1. **形状函数只有一份**：两轴融合的真身在 [`infra/fuse.py`](../infra/fuse.py)，
   `place_fuse` 只 re-export（`place_fuse.magic is infra.fuse.magic` 有测试钉着）。
   往 `brain` 方向要用的东西**不许**从 `media` 反向 provide —— 那是层次倒挂。
2. **两张轴必须不同源**：叙事轴走 embedding（语义），素材轴走**字面**（同名 / 别名 / 键名
   token）。两轴都走语义 ⇒ 高度相关 ⇒ 融合退化成单轴。
3. **语义住数据，不住代码**：地名、别名、情绪词、差分名都在 `config/` 或 `assets/` 的
   yml/json 里 —— 代码里不写 `if place == "天台"`，加一个地点 = 加一行数据。
4. **读表要防"静默成功"**：手编 JSON 同一个键写两遍时 `json.loads` 不报错、只留最后一个
   ⇒ 表读入时做重复键检测，变成一条 WARNING + `PlaceTable.error`。
5. **改名要留台账**：`place_rename` 先扫引用面再改，`place_renames.jsonl` 记下每一笔
   （键是记忆与配置共同的地址，静默改名 = 旧记忆再也对不上）。
