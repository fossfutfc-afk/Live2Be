# 世界（World）模型重设计——多角色同框的时空对齐（2026-08-25）

> 状态: **设计定稿（推翻旧"per-角色平行世界"）, 待用户审阅后实施**。
> 触发: 多角色同框暴露旧模型不成立——"遥香找阿露处理任务, 阿露1生病/阿露2有空,
> 用哪个阿露?"——独立平行世界没有跨角色对齐规则。

## 1. 旧模型为什么不成立

**旧模型**: `data/{char_id}/sessions/{session_id}/`——每个角色独立的多条世界线（平行世界）。

```
igusa_haruka/sessions/{sid1, sid2, sid3}    遥香三条线, 互不关联
rikuhachima_aru/sessions/{sid1, sid2}       阿露两条线, 互不关联
```

**矛盾**: 遥香的剧情里阿露登场——这个"阿露"是阿露的哪条线? 没有自然规则。
因为玩家可以独立"重开遥香"而不重开阿露 → 两条角色的世界线**无法对齐**。

**反例（用户）**: 遥香今天要找阿露处理任务; 阿露1（线1）今天生病, 阿露2（线2）有空
去——"用哪个阿露"取决于跨角色世界线匹配, 而旧模型没有这个匹配。

## 2. 第一性推导: 为什么必须引入"世界"

```
公理 A — 同框即共享时空: 角色 A 与 B 同框互动 = 它们处于同一时刻/地点/世界。
公理 B — 状态一致: 同框时 B 的言行反映 B 的当前状态（记忆/好感）,
          该状态是 B 在【这个共享世界】里的状态。
推论 — 世界线必须按"世界"对齐, 而非 per-角色独立漂浮。
```

**世界（World）= 顶层存档单元（周目）**——角色世界线挂靠世界, 同框 = 同世界内对齐。

## 3. 新模型

```
World（世界/周目）— 顶层, 玩家管理的"一个游戏世界"
  ├─ world_id + meta（创建时间）
  └─ 世界线（world 内每角色【至多一条】）
      ├─ igusa_haruka: 遥香在这个世界的一条连续线
      ├─ rikuhachima_aru: 阿露在这个世界的一条连续线
      └─ ...（惰性创建: 该角色在此世界第一次互动时才建）

语义:
  1. 同世界角色同框 = 各自世界线（状态一致）——"遥香找阿露" = 同世界的阿露
  2. 开新世界 = 新周目（所有角色从头）——真·平行世界（旧"平行"语义的正名）
  3. 世界内角色线连续（不重开就是累计）; "重开角色"= 世界内重置该角色线（可选,
     别人不动）——"重开遥香"不改世界, 只清空重建遥香线
  4. "阿露1生病 / 阿露2有空" = 世界1的阿露 / 世界2的阿露——**世界隔离, 不交叉**;
     遥香在世界1 → 只能找世界1的阿露（生病那个）, 不会出现"跨世界选阿露"
```

**对比旧模型**:

| | 旧（per-角色独立平行） | 新（世界组织） |
|---|---|---|
| 顶层单元 | 角色 | **世界（周目）** |
| 世界线归属 | 角色目录下漂浮 | **世界目录下对齐** |
| 同框 | ❌ 无法确定对方哪条线 | ✅ 同世界自然对齐 |
| 好感排序 | ❌ 跨世界线混排怪 | ✅ 列表=当前世界, 可比较 |
| "平行"语义 | 模糊（每条 session 平行） | 清晰（每个世界平行, 世界内连续） |

## 4. 与现有系统的映射

| 现有概念 | 新模型定位 |
|---|---|
| session（`data/{char}/sessions/{sid}`） | **世界线**（角色在某世界的一条连续线） |
| `store.create(char_id)` | **在当前世界创建该角色的世界线**（惰性） |
| `list_open()`（进行中会话） | **当前世界各角色的进行中世界线** |
| MMT 列表（白名单） | **当前世界的角色列表**（各自世界线状态/好感） |
| 好感（affection 事件） | **per 世界线**（该角色在当前世界的羁绊） |
| brain（wiki/digest） | **per 世界线**（该角色在当前世界的记忆） |
| 同框客串（未来） | **同世界角色的世界线**（注入其当前世界线记忆） |
| resume | **恢复该角色在当前世界的世界线** |

## 5. 存储结构（迁移后）

```
data/worlds/
  {world_id}/
    meta.json               # 世界元数据（创建时间/名称?/当前角色）
    {char_id}/
      events.jsonl          # 该角色在世界里的世界线事件流
      meta.json             # 世界线元数据（创建/结束）
      brain/wiki.json       # 该角色世界线的记忆（digest 缓存）
      progress.json         # 轮数
  ...（多世界并存, 供未来回放/多周目）
```

**迁移**: 旧 `data/{char}/sessions/{sid}/` → 视为"默认世界"（一个隐式 world_id）的角色线;
新数据走 world 目录。旧数据读取时按默认世界兜底（兼容, 不破坏已有会话）。

## 6. 关键设计决策（逻辑为先）

### 6.1 玩家需要显式管理"世界"吗?——**隐式默认 + 可选显式**

```
- 玩家有一个"当前世界"（默认世界, 隐式）——MMT 列表 = 当前世界的角色
- 选角色 → 当前世界的该角色世界线（恢复 or 惰性新建）
- "开新周目" = 顶层显式操作（主界面按钮, 未来回放/多周目才需要）
- 玩家日常**不感知世界概念**——只有"重开/切换周目"时才接触
```

### 6.2 "重开角色"语义（调和旧的"新 session=重开"）

```
旧认知: "新 session = 读五件套重开该角色"（per-角色重开）
新模型: 两种重开, 明确区分:
  - 开新世界 = 全部角色重开（新周目）——真·平行
  - 世界里重开某角色 = 该角色线重置（别人不动）——"只重开遥香"
默认（点角色）: 恢复该角色的世界线（连续）; 重开是显式操作
```

### 6.3 同框客串角色的状态

```
遥香世界线里阿露登场 = 同世界的阿露世界线（注入其当前记忆/好感）
- 阿露在这个世界有世界线 → 用她的世界线状态（记得和老师的事）
- 阿露没在这个世界出现过（无世界线）→ 用她的静态人设（初始状态）
——"阿露生病"（她世界线里的事）自然成立, 因为就是同一个阿露
```

## 7. 分阶段落地

```
P1: world 层数据结构 + 默认世界（旧数据映射到默认世界, 零破坏）
    - SessionStore 加 world 维度（world_id 参数, 默认 "default"）
    - 现有功能（momotalk/bond/brain/好感/MMT列表）全部走"当前世界"
P2: 世界线对齐基础（同框客串的地基）
    - 事件流 speaker 段落支持（DESIGN_MULTI_CHAR 已定）
    - 客串角色状态注入 = 同世界角色世界线
P3: 显式世界管理（未来回放/多周目 UI）
    - 开新世界/切换世界/世界列表（回放入口）
```
