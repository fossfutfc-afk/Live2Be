# core/ — 领域引擎

**作用**：这个项目的游戏逻辑。谁跟谁什么关系、记忆怎么消化、什么时候触发羁绊剧情、
时间怎么走、素材怎么查——判定都在这里。它**不含底座**：底座是 `contract/`（契约）与
`infra/`（路径 / 配置 / 原子写），本包只往上建。

**名字说明**：本包 2026-10-15 曾议改名为 `engine/`（`docs/EXEC_RENAME.md` 第 3 步），
最终**不改**——代价约 1400 处引用（含 102 个测试文件的目录名），收益只是"名字更贴"。
⚠️ 所以别被 `core` 这个名字误导：**最底层不是它**，是 `contract/` 与 `infra/`。

## 子包一览

| 子包 | 管什么 |
|---|---|
| `bond/` | 羁绊剧情（VN）：`bond_story/` 引擎 + 标注层（情绪 / 换场 / 选图） |
| `mmt/` | MomoTalk：行协议动作循环、动作执行、白名单、排名 |
| `session/` | 事件流：`events.jsonl` 读写出唯一出口、叙事化渲染、认章与回放 |
| `brain/` | 记忆**数据层**（点 / 边 / 存储 / 笔记）——纯 stdlib、零 LLM；`read/` 是读路径 |
| `digest/` | 记忆消化管线（轮次真源 = `rounds/__init__.py` 的 `ROUNDS`） |
| `creep/` | 世界线的账（一行没有 `seq` 的 JSON，谁也读不到） |
| `worldtime/` | 三层时钟：剧情 / 现实日历 / 壁钟 |
| `promptkit/` | 提示词装配（盒 / 尾 / 任务卡 / 报表） |
| `media/` | 素材：地点表、图库、立绘播放 |
| `director/` | 视觉导演 + `wiring.py`（webgui 与 CLI 共用的接线） |
| `parsing/` | 人设卡与世界观解析、名字接口 |
| `rag/` | 语义检索（embedder 客户端 + 地点） |
| `affection/` | 好感数值 |
| `random_events/` | 随机事件 |

## 根下平铺的三件（展示数据，2026-10-15 从 `core/tui/` 拆来）

`display.py`（三种渲染策略）· `streaming.py`（断句 + 打字延迟）· `text.py`（MomoTalk 文本处理）。
它们**留在 core 里是有意的**：引擎要产出 `DisplayStep` 这类展示数据，若搬去 `tui/` 就成了
`core ↔ tui` 双向依赖。终端渲染在 `tui/`，网页渲染在 `webgui/static/js/`。

## 两条纪律

1. **不 import 表现层**：`tui/` · `webgui/` · `cli/` 一个都不许（`tests/core/test_import_direction.py` 钉着，
   `RULES["core"]` 的禁用表）。
2. **`llm → core` 必须保持零**：所以横切件（路径、配置、原子写）都住在 `infra/`，别往本包塞。
