# session/ — 事件流与会话存储

**作用**：一个会话（周目 × 角色线）的**持久化与恢复**。全项目只有一条事实主线：
`soul/events.jsonl` 是 **append-only 唯一真源** —— 恢复、回放、记忆、账目都从它派生，
没有任何"另存一份状态"的文件。

## 数据流

```
写：append_event(...)  ── 拿 _GLOBAL_APPEND_LOCK ── seq = max(已有 seq) + 1 ── append 一行 JSON
读：parse_events()  ── 逐行宽容解析（坏行丢）── Event 列表
      ├─ renderer.render_timeline / render_events  → 喂 LLM 的文本视图（"哪一板说了什么"）
      ├─ renderer.session_status / filter_bond     → 当前状态（在不在 VN / 在不在纪念）
      ├─ chapters.replayable_chapters              → 回忆册（可回放章节, 纯派生）
      └─ store.digested_seq 水位切窗口             → digest 的输入
```

**状态不是文件，是 marker**：`session_start` / `vn_enter` / `vn_exit` / `vn_state` /
`session_end` / `memorial_image` 都是事件；当前状态由它们**推导**（`session_status`）。
所以"删掉一个状态文件"这种事故在结构上不存在。

## 核心文件

| 文件 | 是什么 |
|---|---|
| `events.py` | 事件模型：`Event` 骨架 + `seq` 发号 + 六类 marker + `EVENT_TYPES` 白名单（`parse_events` 逐行宽容读） |
| `io.py` | IO 原语：原子写 JSON · append-only JSONL · **行级容错**读（坏行跳过，不整份废掉） |
| `store.py` | `SessionStore`：世界/角色线路径 · `append_event`（**唯一发号口 + 全局锁**）· `append_raw_row`（无 seq 的账行）· 水位 |
| `staging.py` | **章暂存区**：章内一切先进暂存，见到 `vn_exit` 才整段 append 进真源；`StagingStore` 继承 `SessionStore`（同名同形 + 同一把锁） |
| `renderer.py` | 事件流 → 文本视图：喂 LLM 的 timeline（`indexed` 版带记录地址）· 回放过滤 · 状态推导 |
| `chapters.py` | 回忆册：事件流 → 可回放章节（纯派生, 0 LLM）；纪念图挂到板/章级回落 |
| `models.py` | `SessionMeta`（纯索引）· `VNState`（marker payload 的形状） |
| `maintenance.py` | 事件流维护 —— **只剩读侧**（`exclude_abandoned`：废弃段在派生时被排除） |

## 纪律

1. **append-only，永不改写**：要作废一段，用 marker **遮断**，不删行、不重写文件
   （一旦 rewrite，历史就不可信了）。
2. **发号只有一个口**：`append_event` 持进程级锁 + `max(seq)+1`。绕过它自己写 `seq`
   就会撞号（`test_store_concurrency.py` 钉着"并发写者共用一把锁"）。
   `append_raw_row` 是**唯一例外**：它写的行**没有 `seq`**，所以解析器永远看不见（见 `core/creep/`）。
3. **状态靠推导，不靠存档**：在不在 VN、在不在纪念、能不能恢复，都由 `session_status` 从
   marker 推出来 —— 别加"状态文件"，那会变成第二个真源。
4. **章内先进暂存**：VN 中途崩溃不该留下半章；`staging` 让"见到 `vn_exit`"成为唯一的提交点。
5. **恢复 = 回放**：`resume` 不是"读聊天记录"，而是按同一份渲染口径把事件流重灌成上下文
   （`test_vn_replay_compat.py` 钉住"回放与现场同形"）。
6. **读侧宽容、写侧严格**：坏行读进来丢掉并记账；写入要么成功要么抛（不吞）。
