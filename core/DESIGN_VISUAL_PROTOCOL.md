## 1. 背景与动机

三个问题迫使对 ② 导演组件做演进：

- **粒度**：现状一个 scene 只出一个表情；玩家期盼**每一句/每个 `()` 动作拍 → 一个表情**。
- **表情库角色差异**：遥香没有「生气」表情，阿露有；「笑」至少分闭眼微笑 / 睁眼期待地笑 / 微微闭眼痴女笑——文本上都是「笑」，正则和导演看文本永远分不出。
- **世界观**：主 LLM 未读世界观，会输出世界外的地点（"纽约"/"日本"）和现实设定。

共同结论：**知识不要塞进任何模型的大脑，搬进结构与配置**。
- 情绪/地点的**意图**只存在于主 LLM（它写那句时心里知道是痴女笑还是被夸开心）；
- 表情库差异、世界地点表是**领域静态知识**，放映射配置；
- 本地 LLM 只做**缩小后的决策空间**里的仲裁。

## 2. 统一架构形状

背景、表情、世界观校验是同一个形状的三个实例：

```
主 LLM ── 意图语义（emotion / place, 封闭词表）──▶
                                                   ▼
                              静态映射表（领域知识, 天然正确）
                                                   ▼
                        本地 LLM 仅在候选 1:N 时拍板（冷路径）
                                                   ▼
                              VisualState 平滑 / 边界归一
```

- 主 LLM **不背任何库**（不背角色表情 id、不背世界地点 id），只出语义意图；
- 映射层 = 这个世界/这个角色自己的数据文件；
- 导演 LLM 的决策空间 ≤3，可靠性质变（从几十个里猜 → 从 2-3 个里挑）。

## 3. 契约升级

`story_scene` payload 演进（`story_end` 同理，无 choices）：

```jsonc
{
  "beats": [
    {"text": "（她脸红了，低下头）", "emotion": "脸红"},
    {"text": "对不起…我刚才太激动了。", "emotion": "慌张"}
  ],
  "place": "campus",        // 可选; 场景切换才标, 不切省略 → 引擎保持
  "choices": ["陪她坐一会儿", "问她怎么了"]
}
```

- **emotion：per beat**（每一拍一个，词表内选）——落「每个断对应一个表情」。
- **place：per scene**（背景是 scene 级），可选。
- **两者均可选**：缺失的拍/场走现有降级（正则/保持/默认），**向后兼容，纯文本模式照跑**。
- 主 LLM 标出词表外的词 → 引擎**静默兜底**（00 表情 / 延续上一轮，见 §11），**不进主 LLM retry、不报错重试**（低风险建议性字段，宁缺勿错）；同时**记录**错误表述，供未来滤网层归一化。

## 4. emotion 词表（per 角色）

- 词表 = 该角色 `assets/illustration/{char}/emotions.yml` 的 **key 集**（键 = 情绪名 id，值 = `diff/` 相对路径，行尾注释 = 示范），VN 单角色注入主 LLM。
- **VN 是单角色**：一场羁绊剧情只有一个角色，主 LLM 每场只背当前这一人的词表（十几个词，一场注入一次），不背所有角色。
- **从表情库派生 → 结构性防错**：遥香没有生气表情 → 她的词表里没有「生气」→ 主 LLM 想标都标不出来（与 place 封闭词表同一逻辑）。
- **细微表情拆独立词**：三种笑 = 词表里三个词（`闭眼笑` / `期待笑` / `痴女笑`）→ 主 LLM 写那句时本来就分得清，标得细，映射就细，导演不用猜。

示例（示意，非真实数据）：

```yaml
emotions:
  giggle: diff/aru_spr_01.png     # 阿露招牌笑（得意）
  hmph:   diff/aru_spr_02.png     # 傲娇嘴硬
  angry:  diff/aru_spr_03.png     # 生气
  panic:  diff/aru_spr_04.png
  blush:  diff/aru_spr_05.png     # 害羞
  calm:   diff/aru_spr_06.png     # 默认
```

## 5. place 词表（per 世界）

- 封闭词表 20~30 个**通用地点语义**（campus / classroom / ramen_shop / roof / city_street …），主 LLM 从里选，**没有现实国名的入口**。
- **世界观校验三层**（前两层大幅压低违规率，第三层兜住漏网）：
  1. **小提示**：prompt 一句「架空世界观，无现实国家/地名」（成本最低，管大部分）；
  2. **结构约束**：place 封闭词表（没有"纽约"这个入口，物理上输不出来）；
  3. **边界归一**：映射表校验，非法 → 保持上一场景 / 归一直觉默认，**静默降级，不回传**。

**明确不做信息回传**：导演发现非法 → 回传主 LLM → 主 LLM 改文本，这条路代价最大（可能为修一个地点标签重写整场戏 + 污染叙事 context）。拦截在引擎边界、主 LLM 完全不知道，反而稳。

**边界划分**：背景管线只保证「视觉不跳去世界外」，不保证「文本里不出现『纽约』」——文本级世界观属于主 LLM 世界观注入质量的范畴（overview.yml common 档已注入，另案强化），不是本管线能解决的。

## 6. 映射层（领域知识全在这）

- **per 角色**：emotion → 该角色 sprite（= `emotions.yml`，单一真源）。
- **per 世界**：place → 合法 scene_id（静态表 / 目录分层数据源 `background_dirs()`）。
- **1:1 → 纯查表**，导演 LLM 不参与（零延迟零成本）；
- **1:N → 导演拍板**：一个 emotion 对应该角色多个近似 sprite（变体数组）时，导演在候选里选。

## 7. 导演 LLM 冷路径

- 决策空间 ≤3（2-3 个候选），从「自由选」改为「拍板」——7B 可靠性质变，persona 把握问题软着陆（不是把 7B 调好，是让它多数时候不上场）。
- 降级链不变：连续 2 次 `DirectorLLMError` → 禁用 → 查表 + 正则 + 默认，VN 照跑。
- **主 LLM 与导演的交流：单向、结构化、轻量**——意图语义（mood/emotion/place 流）下传；导演选出的 sprite **不回传主 LLM 历史**（防「揣摩导演」自我强化，视觉细节对叙事无增益，纯烧 token）。

## 8. 角色表情维护形式（角色卡作者指南）

**角色表情的标注是作者（创建者）的事，与最终玩家无关。** 玩家只会看到表情展示；作者负责给每个表情打上情绪标签。

- **真源 = `assets/illustration/{char}/emotions.yml`（逐行解析，键 = 情绪名 id，值 = `diff/` 相对路径，行尾注释 = 示范），不改文件名。** 文件名保持稳定 id，作者动作 = 拖图 + emotions.yml 加一行。骨架可由 `scan_diff.ps1` 生成（键留空待填）。
- **主 LLM 词表自动派生**：加了 key = 主 LLM 立即可标该情绪；删了 key = 标不了。**作者改词表，等于改主 LLM 的表达范围**。
- **加一个表情（含 AI 生成）三步**：① 图放进 `diff/`；② yaml 加一行 `情绪名: 路径`；③ 完成，下一场主 LLM 就能标。AI 生成的图可在注释里标来源。
- **变体**：一个情绪多张图 → 值写成数组（导演 1:N 拍板）。
- **对话音**：表情 key 名本身即可作语气词（`库呼呼` 既是情绪又是语音 tag）。

```yaml
# 例：AI 生成拥抱表情后的 emotions.yml
emotions:
  hug: diff/aru_hug.png           # AI 生成, 2026-08
  giggle: diff/aru_spr_01.png
  ...
```

## 9. 文件清单 / 影响面

- 契约：`core/story_actions.py`（story_scene/story_end schema 加 beats/emotion/place，可选）+ `core/bond_story.py`（BondScene 携带 beats）。
- 映射：`core/media/emotion_lexicon.py`（新建，逐行解析 emotions.yml → 词表 + 示范 + 注入文本）；世界地点表（place→scene_id，可放 `assets/_world_places.json` 一类，类比 `_director_whitelist.json`）。
- 导演：`core/director/`（`Director.visual_for` 改为消费 emotion/place 意图而非从文本猜；导演 LLM 只在 1:N 拍板；背景目录分层保留作 place 的候选数据源）。
- 注入：主 LLM VN prompt 注入当前角色 emotion 词表 + 世界 place 词表 + 一句架空世界观提示。
- 文档：本文档演进 `DESIGN_VISUAL.md` §②（其「导演从文本猜」描述届时标注 superseded）。

## 10. 验证 / 风险

1. 单元：词表派生、映射 1:1/1:N、词表外静默降级、place 非法归一、导演冷路径触发条件、契约向后兼容（旧存档/纯文本照跑）。
2. 冒烟：engine_smoke 加 beats 用例。
3. **实机（风险点）**：
   - DeepSeek 对 per-角色词表（十几个词）的**遵守率**——会不会标出词表外词，emotion 与文本一致性；
   - place 词表遵守率 + 世界外地点是否被边界归一并静默；
   - 1:N 拍板时 7B 是否只在候选中选（不越权）。
   - 验证通过 → 按 §3 契约落地；不良 → 回主分支冻结。

## 11. 词表注入节奏与词表外兜底（最终拍板 2026-08-23）

> 作者最终决定（取代「每 10 段喂一遍」的更早提议）。这条是运行时行为契约。

**注入节奏——只有两种触发，不轮询：**
1. **每个 bond story 开场喂一遍**：`start_session` 组装 system_prompt 时注入当前角色 emotion 词表（键 + 行尾示范 + `# eg:` 例句）——VN 单角色，一场一次，十几词，成本可忽略。
2. **犯错时喂一遍（不重写）**：上一场主 LLM 输出词表外 emotion → 下一场 `send_vn_scene` 在 system 层（`system_note`）**重喂词表** + 提示「上次标了词表外情绪 X，请只从词表选」。**只加注记，不重写剧情、不进 retry 循环。**

**词表外兜底（犯错时不重写，落在视觉层）**：该拍 emotion 词表外 / 缺失 →
- 优先 **延续上一轮表情**（保持上一场/上一拍 sprite）；
- 冷启动（无上一轮）→ **00 表情**（角色展示/默认态，= 词表 `_00` 对应键）。
- 静默降级，**不回传主 LLM**（不污染叙事 context）。

**正则辅助器 / 滤网（设计预留，本轮不写）**：
- LLM 出错时把错误表述**记下来**（`engine.invalid_emotions` 收集错误情绪 + 计数，日志记录）；
- 未来写一层滤网：词表外表述 → 归一化映射到最近合法键，在引擎边界拦截，仍不回传主 LLM。
