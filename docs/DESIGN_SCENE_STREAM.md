## 0. 决策记录（2026-09-08 用户拍板）

1. **按 text（自然段）标注 = 正解**：段闭合事件即启动, 不与主 LLM 同段并发
   （文本存在才能判情绪）, 而是与主 LLM **后续段落写作重叠**、与前端打字读速并行。
2. **角色简卡暂不压缩**：沿用现网 character_hint（身份 + personality 行为要点）；
   未来把"标注用角色简卡"下沉到 `emotions.yml` 的自定义字段（作者维护, 标注器
   只读该卡）——登记为后续优化, 本设计预留读取位。
3. **carry 形态定稿**：只传"上一段末句已生效情绪", 不传上一段正文（§4.2）。
4. **段内逐句必填, 禁止省略**：延续也**必须显式重复写同键**——分类任务不许
   LLM 偷懒；且 prompt 鼓励表情丰富（情绪有起伏就切键, 避免整段一个键）。
5. **词表注释全带**：键 + 行尾示范注释 + eg 例句全量注入——示范价值高于
   personality, 不许省（输入裁剪的例外之一）。
6. 输入裁剪原则：不带世界观 / wiki / 行为规则 / 长历史——例外见 §0.5/§0.9。
7. **I/O 整体示范必给**（2026-09-08 补充）: 词表注释示范的是"键义", 还缺一道
   "输入→输出" 整体示范——固定文案的示例段落 + 标签数组, 明确示范三件事:
   延续显式重复同键、段中情绪切换、叙述/动作 → nomal。示例的**标签键由 engine
   从该角色实际词表动态挑选**（保证示例永远词表内合法）。
8. **句子总数显式化**（补充）: 切句后 engine 已知 N——提示词顶部与底部双写
   "共 N 句 → 输出**恰 N 项**", 行号 1..N; 重试消息带"期望 N, 实得 M"。
9. **情绪情境上下文（补充, 形态如下）**: 不给 = 断章取义（"她低头笑"是害羞/
   逞强/道别取决于刚发生什么）; 给全量历史 = 失控。定界原则 = **只给"她此刻
   恰好读到/知道"的信息**:
   - 段 >1: **上一段原文** + 其末情绪 carry（玩家刚读完的, 情境最贴）;
   - 段 1: 本章 seed/标题那一句作锚（无上一段）;
   - **禁后文**（不许偷看未来）;
   - 世界观/wiki/brain 仍不带; 跨场长语境由人设卡承担（跨场景情绪衔接问题
     单列, 见 §11）。

## 1. 目标

- 标注与主生成**重叠**, 视觉键就绪不再依赖"整场门";
- 失败半径 = 单段数句, **永不整批 None**（延续确定性兜底）;
- 单次标注请求小而快（段级 2~5 句）, 缓存友好/成本低;
- 骨架/正文**段级渐进发布**给前端, TTFT 后即开始阅读;
- 保留: append-only 落库裁决语义、双 registry/模式事件、视觉键不进 LLM 上下文。

## 2. SceneStream 总图

```
主LLM chat_full 流式(token 逐块)
   │  engine 结构状态机: 追踪 JSON 层级/引号/转义——某段 "text" 值闭合
   ▼
[段完成事件] ──► ① 切句(split_paragraph, 0 LLM)
              ──► ② 组 emo 段任务(段号+句子+carry+全注释词表+人设卡)
              ──► ③ 入 Dispatcher(保序, 版本 token) → emo lane
              ──► ④ place 段判定并入(廉价, keep 即完成)
              ──► ⑤ 段发布 → 前端打字(渐进); 骨架对象逐段写回
   ...主 LLM 继续写后续段(①②③④⑤并行于写作)...
   │
[finalize] choices/branches/end/memorial 定稿
   │  语义/执行校验通过 → 交互面发布; 校验失败整场重来:
   │  版本 token 换代 → 旧段标注整体作废(不污染新场景)
   ▼
落库(裁决时, append-only; 视觉键已由段级流水保证)
```

## 3. 为什么是"段"而不是"句/场"

| 维度 | 依据 |
|---|---|
| 语义单位 | 段 = 节拍（早期定稿: 段=画面/情绪单位）——标注视角与叙事视角一致 |
| 安全边界 | 段闭合 = **JSON 元素闭合**, 非标点猜测——引号/括号/省略号坑全绕开 |
| 失败半径 | 单段 2~5 句; 重试一次后逐句延续, 视觉永不整板空白 |
| 成本/延迟 | 单次输入 ~200-400 token（段级）; 与主写作重叠, 尾部仅剩最后一段 ~≤1s |

## 4. emo 单段任务卡（终稿模板, llm/prompts/ 下新增文件占位）

### 4.1 提示词形态（终稿, 含情境区/总数显式/I-O 示范）

```markdown
【情绪标注任务 · 第 {para_no} 段】(角色: {char_name})

{character_hint}
（人设卡——身份 + personality 行为要点; 现网 _character_hint 原样注入,
  未来改读 emotions.yml 的自定义角色简卡字段, 见 §0.2）

【情境】{context}
（她此刻刚读到/知道的信息——段 >1 = 上一段原文 + 其末情绪; 段 1 = 本章 seed
  那一句。只用于理解情境, 不要输出它; 后文她不知道, 也不许你偷看。）

【本段】共 {n} 句（行号即输出位置, 每行一句）:
{sentences}

角色表情词表（键 + 注释 = 用法示范——只从这些键里选）:
{lexicon_full_annotated}

【示范】
句子:
1: 她别过脸去, 声音越来越小。
2: 「……嗯, 其实我很开心。」
输出: ["embarrassed", "smile"]      ← 每句一项, 情绪切换就切键
句子:
1: 她安静地收拾着窗台上的陶罐。
2: 罐子里的杂草舒展着叶子。
输出: ["nomal", "nomal"]            ← 叙述/环境 → nomal
（示例中的键可能不是你的词表——以词表为准, 格式照此。）

【输出】严格 JSON 对象: {"labels": {句号: "情绪键", …}}
- 句号 = 上面【本段】的行号——共 {n} 行: **每行都标, 一行一项, 不许合并/省略**
- 情绪延续也显式重复同键（不许推断空位）; 情绪有起伏就切键: 尽量让整段
  表情丰富, 不要为了省事整段一个键
- 平淡叙述/动作/环境 → nomal; 内心/逞强/哽咽按证据标, 参考人设卡与情境
- 只有 JSON 对象本身, 无任何解释、无 markdown 围栏
```

> **2026-09-08 真 API 修正（P1 落地时）**: 输出契约 = "json_object + **编号映射**
> `{"labels": {"1":键,…}}` + thinking 显式 disabled"。空响应根因 = DeepSeek
> v4-flash 系**默认思考开启且 reasoning 计入 max_tokens 预算**——"off"此前实现为
> 不传参数（默认思考吃光 512 → 空 content + finish_reason=length,
> deepseek-ai/DeepSeek-V3#1610 同型）; 改传 `{"thinking":{"type":"disabled"}}`
> 后单段 0.5-2.4s、零空响应。编号映射让**引擎数项**（句号键集合校验, 模型
> 只逐行标）; 解析端形态无关兜底（dict 数组/dict 编号映射/list/裸键容忍——
> 测试桩兼容）。§4.3.1 重试预算 1 → 2 次（首发现象期实测, disabled 后预算
> 基本用不到; 失败半径仍是单段, 永不断句 None）。

注: 示范文案固定, 但其中的标签键由 engine 从该角色**实际词表**动态挑两个
（如词表含 nomal/embarrassed/smile 用上例, 否则用词表前两个合法键）——保证
示范永远合法; 词表注释随键全量带（§0.5）。

### 4.2 情境块与 carry（engine 记账的"已生效链"）

- 情境 = **上一段原文 + 末句已生效情绪**（段 1 退化为本章 seed 锚）——只给
  "她此刻恰好知道"的信息, 禁后文（§0.9）;
- carry 只传情绪不传正文的旧形态**已被情境块吸收**（正文即情境, 情绪即 carry）;
- 生效链以"前端实际显示链"为准（engine 按写回/延续实时更新）;
- 冲突规则: 文本证据与 carry 冲突 = 真转折 → 以文本为准正常切键
  （前端"当前段补切"基建兜住, 视觉不闪断）。

### 4.3 校验与兜底（engine, 非 LLM 责任）

1. 长度 != 句数 → 该段重试（预算 3 次 = 首发 + 2 次重试, 2026-09-08 真 API
   修正: 负载期空响应/项数错配占首发 ~40%——见 §4.1 注; 指令同模板, 补
   "上次输出长度不符"）;
2. 逐项 ∈ 词表; 非法项只丢该项;
3. 仍缺项 → **段内延续**: 前一句键 → 段首用 carry; 更新生效链;
   **绝不整批 None**;
4. 每次兜底/重试记账（§8 质量指标）。

## 5. place 段判定（同管道, 简述）

- 输入: 本段句子 + 当前 place + 词表; 判"空间实体变更句";
- keep 是合法结果; 失败静默 keep; 锚点写回句项 place 键;
- 与 emo 并行, 与主写作重叠; 语义见 DESIGN_BOND_CONTRACT_V2 §5。

## 6. engine 职责清单（事件表）

| 事件 | engine 动作 |
|---|---|
| 每 chunk | 结构状态机推进（JSON 层级/引号/转义）——不解析语义 |
| 段 text 值闭合 | split_paragraph 切句 → 组段任务（段号/句子/carry/词表全注释/人设卡）→ 版本 token 附签 → Dispatcher 入队 → 段发布(前端打字/CLI 显示) |
| 标注返回 | 校验(§4.3) → 保序合并 → 写回 scene 句项 + emo_version++ → 更新生效链 |
| 语义重试(整场重来) | 版本 token 换代 → 旧段结果按 token 作废（防跨版本污染, 结构化替代身份检查） |
| finalize | choices/branches/end/memorial 定稿; 最后一段尾部 ≤1s 短等(可选) |
| 落库前 | 段级就绪保证: 当前展示段视觉键完整(不再整场门) |

## 7. 版本/保序/作废

- 每场景一个版本 token; 每次 send_vn_scene（含语义重试）换代;
- Dispatcher 按 (版本, 段号) 保序合并; 写回时版本不符 → 丢弃;
- 并发: emo/place 两路; 段级在路并行上限 2(可配)——保序由引擎合并层保证;
- 重试浪费 = 已标段 × 小调用（task 卡后语义重试已低频, 接受并计指标）。

## 8. 质量与日志

- 每段: `scene_anno para= N retry= fallback_sents= carry=→out=`（单行 grep）;
- 会话汇总: 填充率(必填=100%目标) / 重试率 / 兜底句数——调词表与 prompt 用数据;
- 前端: 保留 emo_version 补切（渐进发布期段已就绪则无感）。

## 9. 输入裁剪原则（例外已列）

不带: 世界观、wiki/brain、行为规则全文、历史窗口、branches/**后文**。
带: 本段句子 + **情境块（上段原文+末情绪; 段 1 = seed 锚）** + I/O 示范 +
全注释词表(§0.5) + 人设卡(§0.2, 现网形态)。
place 同理只带本段。

## 10. 分阶段落地

- **P1 Dispatcher（仍在整场收齐后跑, 但逐段入队/保序/版本/兜底/日志）**:
  证明"小输入 + 情境 + 全注释词表 + I/O 示范 + 快失败半径 + 永不空白"的
  质量与耗时; 不改流式, 风险隔离。验收: 填充率 100%(含延续显式)/
  兜底句数≈0/示范键恒词表内/重试消息带"期望 N 实得 M"/单场标注 ≤ ~2s。
- **P2 渐进流式**: 段闭合事件驱动(§2 总图), 前端渐进打字,
  最后一段尾部处理; CLI 同源(SceneStream 在 core)。
- 验收口径: 上屏 ~TTFT; 读到段时表情已就绪率 ≥ 95%; 语义重试无污染;
  llm+core+webgui 全绿。
