# agent for RP：她不是在写小说，她在用工具活着

*这个我懒得写了，所以这个全篇除了这句话都是AI在写*

## 0. 先把"RP 差"拆成三种病

大多数人优化 RP 的方式是改提示词。改完之后你会发现，能改的都改了，剩下的问题**不在词上**：

| 病 | 表现 | 真因 |
|---|---|---|
| 格式漂移 | 她该说一句话，输出了半截 JSON；该发图，字段写成 `video` | 你在**用自然语言要求一个格式**，而格式没有执行者 |
| 世界不动 | 她"拿起伞"、"看了眼时间"、"想起上周的事"——世界毫无反应 | 她只有**嘴**，没有**手**。所有动作都是叙述，不是行为 |
| 失忆 | 聊到第 40 轮，她开始编造上周的事；或者干脆不提 | 你让她"回忆"，但没给她**能查的东西** |

第三种最常见的应对是"把更多上下文塞进去"。塞到最后你会发现：**上下文越长，她越不知道该看哪一句。**

三种病要三种工具，而且都不是提示词：

```
格式漂移  →  正则化（协议 + 校验 + 自愈）
世界不动  →  动作域（她能做的事，引擎执行）
失忆      →  grep（她能发起的确定性检索）
```

下面三节，一节一个工具。

## 1. 正则化：格式必须有一个执行者

### 别让一句话承载两件事

最开始的坑是这样的：让她输出

```json
{"reply": "唔……我找找看", "actions": [{"name": "look", "args": {...}}]}
```

结果她经常把"话"和"动作"黏在一起、把 `actions` 写成字符串、把嵌套 JSON 的引号写漏。**一个字段承载两种语义，她就一定会混。**

现在是**行协议**：一行一条 JSON，判别键**恰好其一**。

```jsonl
{"text": "唔……我找找看"}
{"action": "mmt_look", "payload": {"clue": "苔藓 && 屋顶"}}
{"text": "找到了，是那次下雨。"}
```

三个好处，都不是"格式更整齐"这种审美收益：

- **一行一个气泡**，交错起来就是微信的节奏（话 → 图 → 话）；
- **能流式交付**：内容行到达即上屏，独占行攒到块尾；
- **坏一行只丢一行**，不必整轮重发。

### 三处各管一摊，而且不许互相看

| 层 | 只管 | 出错的后果 |
|---|---|---|
| `mmt_lines` | **形状**：是 JSON 对象吗？判别键合法且唯一吗？ | 坏行丢行 + 记账 |
| `registry.parse` | **字段**：这个动作的 payload 类型对不对 | 硬拒绝 |
| `mmt_check` | **组合**：这一轮的行放一起违不违规 | 硬/软分级 |

为什么要切这么细？因为**两处都判 = 两处会漂**。最典型的：提示词里写着"标题必填 3-16 字"，而字段校验只校验"是字符串"——空标题就这么放行了。发现这个洞之后，规则被搬进**组合层**（它管"字段之外的约束"），而不是"提示词里再强调一遍"。

### 自愈必须发生在校验之前

这是顺序问题，不是风格问题。

`mmt_send_media` 的 `media_type` / `image` 都是 registry 的**硬拒绝**。如果先校验，写歪的字段就没机会被修——直接回灌，白花一次调用。所以：

```
原始行 → 自愈（能修的修掉，每次都留一句说明）→ 校验 → 执行
```

修的原则三条：拿不准就不猜（归一化有歧义就交给回灌）、每次修复都要说得出为什么、**绝不新增语义**（它没写标题，就不能替它编一个）。

### 该归一化的地方，不叫"容错"，叫"听懂"

| 场景 | 处理 |
|---|---|
| 聊天里出现舞台指示 | `（低头）（小声）` 循环剥掉——MomoTalk 是手机，没有括号动作 |
| `igusa-haruka` / `IGUSA_HARUKA` / `伊草 遥香` | 折叠形比对（小写 + 抹装饰字符） |
| 整段元信息 `《名》｜5 天前｜9/26` 被抄进线索 | `normalize_title` 取 `｜` 第一段 |
| 中文输入法吐的全角 `＆` | 归一成 `&` |
| 全角 `｜` | **故意不归一**：它是元信息的分隔符，归一成 OR 会给出**错的**结果（比空更坏） |
| 全角 `（）` | **故意不归一**：真档正文里出现过插入语，当归组会把"照抄正文"的线索解析错 |

最后一行是关键：**并不是"归一化越多越友好"**。归错了比不归更坏——不归是"没听懂"，归错是"听懂了另一个意思"。

## 2. 动作域：说一句话不是动作

### 只有三个动作

```
mmt_look                 翻自己的记忆（静默轮；查到的东西回灌，她接着说）
mmt_send_media           发图（先查资源库，库里没有才生成）
mmt_trigger_bond_story   进羁绊剧情（模式切换，独占行）
```

注意**"说话"不在这里**。说话是内容行，不是动作。动作的判据只有一条：**这件事需要引擎介入**。

这条线画得很硬，效果也很直接：动作越少，每个动作能做得越深。`send_media` 不是"贴一个 URL"，而是"查库 → 没有就生成 → 回填"；她说"发张照片"，引擎真的会把图造出来。

### 查询族：查完接着说，而不是把这一轮作废

`look` 是**静默轮**：

```
她输出 look（可能是这一轮的最后一行动作）
  → 引擎执行，把结果**回灌**成一条消息
  → 同一轮继续，她带着资料把话说完
```

单轮最多 6 步（含这次回灌后的续写）。这个设计解决了一个很具体的问题：如果"查"必须单独占一轮，她就得先说一句"等我一下"，然后世界确实卡了一轮——**而人不会这样**，人会边说边想。

### 硬问题修不了，处理方式不一致才对

同样是"修不了的操作行"，处理方式按**后果**分：

| 动作 | 修不了怎么办 | 判据 |
|---|---|---|
| `send_media` | **丢行**（软），下一轮注记提醒 | 丢掉之后她只是没发成图，**前提没变** |
| `look` / `trigger` | **必须回灌**（硬） | 丢行她会以为自己翻过了 / 进剧情了，**带着错前提继续写作** |

这个判据可以复用到任何 agent：**丢掉这条之后，模型还会不会以为自己做过它。**

### 独占行：合法性取决于"同一轮还有没有别的行"

`trigger` 是模式切换，`look` 是查询——两者都是独占行：只能有一条操作行，且 `look` 后面不许再有行（块尾执行，写在它后面的话是在没看到结果时写的）。

而"独占"这件事**单看一行永远合法**，只有把整轮收齐了才判得出来。（`look` 后面再写话这一条只在提示词里教，引擎不判错——判了会逼她中断。）所以流式交付下这两类行要**攒到块尾**：内容行到达即上屏，独占行等整轮写完再判。否则"独占被破坏"会被流式绕过，而 `trigger` 一旦跑出去就收不回来。

## 3. grep：她得有一个能自己用的检索面

### 问题类型决定检索方式

| | 相似召回 | 定向寻找 |
|---|---|---|
| 问什么 | 哪几条**最像** | 符合这几条的**有哪几条** |
| 不变量 | 排序就是答案 | **漏一条就是错** |
| 输出 | top-k | **全部** |

只要判据里混进"相似"，"全部"就失去意义。所以定向寻找那一层里**全是确定的判据**，没有阈值、没有 top-k、不要向量后端。

五种锚，每种 1:1 复用已有的原语（零新匹配逻辑）：标题 / 某人的车道 / 某个类 / 时间闭区间 / **正文上的字面布尔式**。锚之间是 AND。

### 她的查询语言：字面 + `&&` / `||` + 括号

```json
{"action": "mmt_look", "payload": {"clue": "(苔藓 && 屋顶) || 雨后"}}
```

**不给她正则**。四条理由，一条比一条硬：

1. `\d` / `\w` / `\.` 在 JSON 字符串里是**非法转义**——那不是"精度差一点"，是整行解析失败，把行协议打掉；
2. `{}` 和引号写错同样把这一行弄坏；
3. Python 的 `re` 没有超时，`(a+)+b` 能把同步链卡死；
4. **不需要**：中文里"短子串"已经覆盖了 `苔.` 想干的事（`苔` 一个字就收了苔藓/苔痕/青苔）；而 agent 用 grep 时 `.*` 想表达的"同一条里同时含"，正是 `&&`——**"同一条"由记忆的粒度天然给了**。

所以她的线索语言 = 字面 + `&&`/`&` + `||`/`|` + 半角括号，词形 `and`/`or` 也认。正则味的字符**逐个明确拒**，可归因，不会变成"她以为在写模式、引擎当字面、静默 0 命中"。

求值实现里**连 `import re` 都没有**，字面就是 `in`。

### 三档空手：失败要分得开

| 情况 | 她看到 |
|---|---|
| 名字对不上是谁 | "这个叫法我对不上"（**可行动**：换个说法） |
| 时间认不出 | "这个时间我没弄明白"（不静默当"没给时间"去查全库） |
| 看了没有 | 第 1 次照旧 · 第 2 次给"回忆方法" · ≥3 次劝她停下 |

最后那档是**防死循环**：一个查不到的线索，她可能连查五轮。计数 + 递进措辞比"再试一次"有用。

还有一条节制：展示层只摆 5 条，但**如实报"还有 N 条"**。截断必须可见——否则她会以为"就这 5 条"，转述出去就是错的。

## 4. 谁摆、谁查、谁判

这三件事经常被混成一个"记忆系统"，而它们的分工正是不打架的原因：

| 谁 | 什么时候 | 判据 |
|---|---|---|
| **引擎摆** | 每轮 | 老师这句话提到了一个名字 / 出现了时间词 / 兜底打分最像的几条 |
| **她自己查** | 她决定 | 她写的锚 + 线索（确定性，可全量） |
| **消化时连** | 异步，40 轮一次 | 语义 + 字面 + 结构 + 时间 + 重要度五路打分 |

引擎摆的是**提示**（她不需要就能说话），她查的是**行为**（她必须知道才能说下一句），消化时连的是**长期结构**（长边，不占实时预算）。

把三者混起来的后果很具体：**每轮都做全库语义检索**——实测 916 ms（420 条库 11.2 秒），而且随时间线性恶化。这笔钱不该在 TTFT 里花。

## 5. 一组数字

| 项 | 值 | 为什么是这个数 |
|---|---|---|
| 单轮动作步数 | 6 | 含"查完接着说"那一步 |
| `look` 一次摆几条 | 5 | 展示层 cap；被挡掉的如实报数 |
| 行级续写 | 1 次 | 只补缺失的操作行 |
| 形状级重发 | 2 次 | 旧路径是 6 次整轮重发（最坏 6×4096 token 还什么都给不出） |
| 检索锚 | 5 | 每个 1:1 复用已有原语 |
| 检索截断 | 无 | 定向寻找层不截断（漏一条就是错） |

## 6. 带走三句话

1. **格式要的不是"更严的提示词"，是执行者。** 形状 / 字段 / 组合三层各管一摊，中间夹一层"自愈先于校验"——提示词只能提要求，不能保证。
2. **动作要少。** 说话不是动作；只有"需要引擎介入"的才进动作集。动作少的价值不是简洁，是每个动作都能做得深（发一张图 = 查库 + 生成 + 回填）。
3. **检索要么确定，要么别叫检索。** 混进相似度的"全部"是假话；而给她 `re` 的第一天就会打掉行协议。字面 + `&&`/`||` + "同一条"这个天然粒度，已经够了。
