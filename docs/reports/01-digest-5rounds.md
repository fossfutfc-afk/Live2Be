## 2. 事件{split-1}

现实生活中，记忆中的事件很复杂，但是假如忽略细节，我们可以粗略认定为它是`以普朗克时间为最小单位，在时间轴上的一个区间`

比如我上早八，那对应的区间可以粗略写作[8:00, 12:00]，至于为什么上课要四个小时，是因为我没起床



在我们的设计中，我们将玩家与角色的互动归档为一个`events.jsonl`，它原意仅仅是用于记录、回放、调试

但某种程度上，它可以被转化为一个`集合族`

我们为每一条输入/输出分配序号，那么在这里，事件本质上就是`以单一序号为最小单位，在对话流上的一个区间`

比如：

1 user: 奶龙你好呀               nailong: 嘻嘻，我就是奶龙，世界上最可爱的奶龙
2 user: 我们一起去吃饭吧          nailong: 好呀好呀
3 user: 这顿饭好不好吃呀          nailong: 好吃好吃！
4 user: 我先跑了，钱你自己付哈    nailong: (因为没钱被肘击了)

那么这四件事情就可以粗略的分为
```json
{
  "[1, 1]": "用户和奶龙寒暄",
  "[2, 4]": "用户巧施连环计，奶龙误吃霸王餐"
}
```

`事件`的被降解成了`区间`，记忆由此变的有来源、可追溯

至此，引子足够，我想有必要引出我们的digest模型:

```markdown
| 步 | key | 干什么 | 一句话 |
|---|---|---|---|
| ⓪ | `split` | 切分 + 顺手判账 | 这一段有**哪几件事**，每件覆盖哪一段事件 |
| ① | `record` | 填血肉 | 只写正文；**位置不归它** |
| ② | `akin` | 收货 | 把她当时"想起过什么"变成边（**0 次 LLM**） |
| ③ | `relate` | 接 | 只判关系，一个字正文都不写 |
| ④ | `cognize` | 想 | 造看法（新结论） |
| ⑤ | `settle` | 沉淀 | 认人 + 改名 + 写看法 + 写**她自己** |
```

显然，第0步split，就是按照这一原理应运而生的{split的第一作用}



## 3. 笔记{split-2}

假如我在角色生日当天约好明年的生日给她送礼，如何让她记得这件事情呢？

你可能觉得，设置一个重要程度，并把它调到最高就可以让它作为常驻记忆了

是的，这很优雅，很省字段，但会**破坏正常的事件召回流程**，事件的召回必然依仗重要程度，假如角色记忆里重要的事情都是几月几号要干什么，那这个角色显然没有灵魂



人在做笔记的时候绝对不是因为这个事情冲击大或者印象深，否则所有学生干脆都别带笔记本了(正解desuwa)

一个事情记在笔记本上**不是因为记住它有多好，而是因为忘了它有多坏**

笔记的评判标准应该区别于一般的事件，无论是设计成一个常驻节点/辅助体系，务必防止其与事件混淆即可，除非它已经尘埃落定



在这里，我们的第0步会顺手从事件中提取笔记，也就是那些忘了有代价的事情，让角色可以主动提取一些你想让她记住的事情{split的第二作用}

这个笔记原先想做成实时markdown动作，但是这样的话由于没有序号，无法追溯到具体事件，会打破原有设计，假如你的项目不需要这些，实时做笔记而非马后炮可能是一个不错的方案



## 4. 合同{akin+relate}

*老师...我还记得...您星期一送的红玫瑰，星期二送的郁金香，星期三送的蒲公英，星期四送的洋甘菊，星期五送的蝴蝶兰，星期六送的葱绒球，和星期日送的向日葵...*
*向日葵的花语...是沉默的爱吧...它每天只是默默注视着太阳，看着闪耀光辉、普照大地，无论那光芒是否落到自己身上，它也都就心满意足了吧...*
*但是老师...这一刻，我遇到了自己的太阳...花朵终究只是花朵，无法发出自己的声音...但是我...不再想只是默默在远处看着您...老师...我...喜欢您...*

芜！煽情结束，回到理论，假如你希望让你的角色能够说出这种话，你需要什么？

很简单，也就是对相同相近事件的整理

那么，如何找到相同时间的联系呢？

这里需要引入一个概念，纵轴相近与横轴相近

- 纵轴相近是指由于事件戳近邻或区间交叠，导致两个时间具有一定的连续性，从而产生相似连贯
- 横轴相近是指不同时刻发生的事件有着同样或类似的属性，从而产生似曾相识或层层递进之感

很明显，二者粗略上呈正交关系，当二者都趋近于正无穷时，也就是时间戳极相近且属性极相似，就意味着这件事情就是它本身

不过，我们这里需要的是横轴相近

具体做法很简单，lms起服务，embedding综合召回让LLM判断就可以了{relate轮次本质}

不过呢，我们为了好玩，创新增加了一个写时注意，也就是在说话的事后，角色可以使用notice动作，把当下的情形和某个以往的事件联系起来，加强其惯性{akin轮次本质}

这实质上对应了人在睡眠时的静默整理和清醒时的实时回忆，二者互相映衬，防止出现关系疏漏


## 5. episode-belief-ENTITY{record-recognize-settle}

这是图上的所有节点(当然你可能会看到一些历史遗留/实验性节点，不过这仨是正式的)

episode是区间事物，belief是抽象升华，它们之间有着各种各样的关系，这些都给LLM判断就好了{record写episode，recognize写belief，就这么简单}

但是ENTITY以及它对应的settle路径不太一样：

ENTITY是**重要且大概率会重复遇见的东西**，在我们的设计中，几乎只会是其他角色，它最重要的属性就是包含了一条实时更新的一句话印象

假如你的角色需要认识一个新人，它的记忆不应该四零八落，而用相似边链接它们也不现实，它们不是纵轴/横轴相似，它们只是发生在同一个实体上

仅仅只有episode和belief的图解决无法解决**发生在同一对象上**，这个语义，因而引入ENTITY

它应当小而精，它让角色能够认识她在角色卡里从未见过的角色，并且自主围绕她产生记忆，并且产生一句话的印象，让她有对这一ENTITY的认识

而且一旦发现ENTITY的引用被增加，就会出现settle轮，把一句话印象根据新事件全部重写，防止记忆过期{settle的本质}

这是迈向多人互通记忆里不可或缺的一部分
