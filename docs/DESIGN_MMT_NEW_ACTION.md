## 1. 动作面的形状：**性质不同，形状不许混**

### 1.1 现状（代码事实）

| 今天 | 形状 | 引擎内部怎么对它 |
|---|---|---|
| 消息行 | `{"text": "…"}` | **内容行** —— 一行前瞻交付 |
| `mmt_send_media` | `{"action": …, "payload": {…}}` | ⭐ **也是内容行**（和 `text` 同一条交付路径） |
| `mmt_inspect_character` | 同上 | **独占行**（攒到块尾判） |
| `mmt_trigger_bond_story` | 同上 | **独占行** |

⭐ **`mmt_check.py:59` 的 `WHOLE_TURN_ACTIONS = {trigger, inspect}`** ——
**引擎早就在按"独占行 / 内容行"二分，而 `send_media` 不在里面**（它走 `text` 那条交付路径）。
⇒ **契约层的 `action` 抽象，落后于执行器层的事实分类** —— 这就是"三个性质不同的东西被塞进同一形状"。

### 1.2 建议形状：**键名 = 这一行是什么性质**

| 性质 | 形状 | 谁 |
|---|---|---|
| 她**说**的话 | `{"text": "…"}` | 创作 |
| 她**发**的东西 | `{"media": {…}}` | 输出内容的另一种形式（**与 `text` 平级**） |
| 她**要**的东西 | `{"look": […]}`、`{"when": …}` | 查询（**独占静默轮 + 回灌**） |
| **模式切换** | `{"enter_story": "标题"}` | 独占（改流程状态） |
| ⭐ **顺手记账** | `{"noticed": "标题"}` | **零成本**（不上屏 · 不参与一行前瞻） |

⚠️ **`action` + `payload` 信封去掉** —— 那是"否定式分类"（"不是 text 的都是 action"）。
⚠️ **待裁**：键名照上表定死，还是保留信封（`PROCEED.md §3` #4）。

### 1.3 三条纪律（都是踩过的）

1. ⭐ **示例才是形状的来源**（陷阱 3/46）—— 改形状**必须同批改示例**
2. ⭐ **提示词里的"反例"会变成禁令**（陷阱 40）
3. ⭐ **看不见两端的 LLM 写不出那条边** —— 她判得出什么，取决于引擎把什么放到她眼前

## 2. `when` —— 时间查询语法（**冻结**）

### 2.1 定位：这是**过去检索语法**，不是"时间表达语法"

- 检索只可能命中过去（`events.jsonl` append-only，`ts` 恒为过去）⇒ **凡是落在将来的形式一律不进来**
- 将来时间有两个**别的家**：① 对话里的"下周三" = **创作内容**（进 history，引擎一个字不用懂）
  ② 约定到期日 = **`note.promise.due`**（一个**只存不渲染**的字段）
- ⚠️ **粒度只到 `day`** —— 一天之内的先后不可靠（`_node_ts` = 段内最后一条事件的 ts，
  而一段可横跨几天）⇒ **不许写时刻**

### 2.2 语法

```
when := YYYY/MM/DD                      2026/05/05              单点（整天）
      | YYYY/MM/DD-YYYY/MM/DD           2026/05/02-2026/05/06   闭区间
      | YYYY/MM | YYYY                  2026/01 · 2026          整月 / 整年
      | back A-B unit                   A 可省（= B）· A ≤ B

数字从 0 起, 越大越早    0 = 当前周期
unit := day | week | month | year  |  <锚表里 year 留空的周期名>
输出一律归到闭区间 [start, end], 粒度 day
```

| 写法 | 意思 |
|---|---|
| `back 0 week` | 本周（截到今天） |
| `back 1 week` | 上周 |
| `back 4 week` | 倒数第 4 个自然周 |
| `back 0-3 week` | 最近 4 个自然周（≈ 最近一个月） |
| `back 0-6 day` | 最近 7 天（⭐ 等价于滚动） |
| `back 2 christmas` | 倒数第 2 个圣诞 |

### 2.3 `back` 是**类型前缀**，不是可选修饰 —— 两条硬理由

1. **一次判定分流**：以 `back` 开头 ⇒ 相对解析；否则 ⇒ 绝对日期/区间。**零歧义、不用 backtrack。**
2. **失败可归因**：有前缀 ⇒ 引擎明确知道"她想说相对时间但写歪了"，能回具体的话；没前缀 ⇒ 连意图都不知道。

⚠️ 反例（**为什么不能省**）：`4 week` 的先验读法是**时长**（four weeks），不是"倒数第 4 个周"；
`2 christmas` 读起来像"两个圣诞"。省掉前缀 = 把已经消掉的歧义原样放回来。

### 2.4 校验规则（引擎逐条查，**每条都能确定地拒**）

| # | 规则 |
|---|---|
| 1 | `unit` ∈ {day,week,month,year} ∪ {锚表里 **`year` 留空**的 name} |
| 2 | `A ≤ B`；省略 `A` ⇒ `A = B` |
| 3 | `N ∈ [0, 99]`（上界防荒唐） |
| 4 | 单位恒用**单数**（`week` 非 `weeks`）；容错吃复数 |
| 5 | 大小写 / 多余空白不敏感；前导零可有可无（`5/5` = `05/05`） |
| 6 | 求值出的区间若**完全落在将来** ⇒ **返空**（不是错误）—— 例如 9 月问 `back 0 christmas` |
| 7 | 端点反了 / 跨度荒唐 / 非法日期 ⇒ **拒**（**不自动交换、不夹** —— 静默改她的意思比报错贵） |

⭐ 规则 1 正好用上 `festivals.json` 已有的 `year` 字段：
**`year=""`（每年一次）= 周期 ⇒ 能用 `back N`；`year=2027`（一辈子一次）⇒ 不能。**

### 2.5 锚表（开放，可增长）

| 类 | 例 | 谁写 |
|---|---|---|
| 固定节日 | `christmas` / `teachers_day` / `new_year` / `valentine` | ✅ `config/eggs/festivals.json`（作者手编） |
| 关系锚 | 关系起点 / 生日 | 引擎自有（`events.jsonl` 第一条 · `profile.yml` 的 `SIG~birthday`） |
| 表外的具名日（中秋） | —— | ⚠️ **一次补一行，之后永久是查表**（**不是查询时翻译**） |

⚠️ **表外命名日不进规范**：引擎回"认不出这个时间，你给个日期，或者问老师"，**不猜**。

### 2.6 容错层（引擎认，**不进规范**）

`上周` → `back 1 week` · `最近一周` → `back 0-6 day` · `这个月` → `back 0 month`
· `4 weeks ago` → `back 4 week` · `上个圣诞` → `back 1 christmas` · `圣诞节`（→ 表里 `name`）

⚠️ **容错不许改语义**：`4 weeks ago` → `back 4 week`（倒数第 4 周），**不能**归成"最近 4 周"。
**归错了就是静默错范围。**

### 2.7 明确不做

| 项 | 为什么 |
|---|---|
| ❌ `next` / 将来 | 检索没有将来（§2.1） |
| ❌ `this` | = `back 0`（纯冗余） |
| ❌ `past` | = `back 0-(N-1)`，而"最近一个月"用 `back 0-3 week` 近似即可（**不逼她做减法**） |
| ❌ 时刻（`21:30`） | 日内先后不可靠（§2.1） |
| ❌ `part`（"月底"） | 边界说不清 ⇒ 引擎只能猜 ⇒ **静默错范围**。按"定位归对话"，该问清楚后给显式日期 |

## 3. `look` —— 要东西进来

### 3.1 契约

```json
{"look": ["瓦片缝里的苔藓"]}
{"look": ["屋顶"], "when": "back 1 week"}
{"when": "back 0-3 week"}
```

- `look`：**数组**（文本线索）。⚠️ **数组 = AND（逐条收窄）**，不是 OR；要 OR 就**查两次**
- `when`：§2 的语法
- ⭐ **两个都可选，但至少要有一个** —— "只想查某个时间点的事"不需要 `look`

### 3.2 引擎三级解析（**她不需要选"用哪种查法"**）

```
① 当【标题】精确查      → 命中 ⇒ 取论据（一步到位）
② 失败 ⇒ 当【query】检索 → 给候选行（⭐ 每条带标题）
③ 都失败 ⇒ 【明说没找到】（不静默给空）
```

⭐ ②的候选行带标题不是装饰 —— 那是**下一轮她精确指向的输入**（"刚看到才抄得准"）。

### 3.3 权限按"目标落在哪"分派（保住 `inspect` 的原有语义）

| 解出来落在 | 走什么 |
|---|---|
| **她自己的记忆**（episode / belief / promise / 她记忆里的 entity） | ✅ **直接给** —— 查自己的记忆不需要许可 |
| **已建档角色的档案**（`char_loader` 里那类） | ✅ **走 `interperson` 权重 1/2/3**，无记录就拒 |

### 3.4 返回形状：**info-head + info**

```
[回忆 · "屋顶" · back 1 week · 命中 3 条]
- [9/20 · 杂草屋的环境调研] 老师接到联邦理事会的环境调研任务…
```

- head 只放**能被筛 / 能被判断**的（查了什么 · 时间范围 · 命中数）
- info = **正文原样**（不改写、不摘要 —— 摘要会二次失真）
- **不带 id**（一律渲染成标题，见 `PROCEED.md §2` #10/#11）
- 条数封顶 top-k；**空结果分两种说法**：
  - 完全无关 ⇒ `（你翻了翻，没找到相关的）`
  - ⭐ 有候选但被 `when` 筛掉了 ⇒ `（那段时间没有；再往前的有这几条）` + 候选 —— **如实报告筛选边界，不是猜**

### 3.5 ⭐ 空结果明说是"该去问老师了"的触发器

> **`（没找到）` 不是失败提示，是"轮到你问玩家了"的信号。**

配套产品规则（写进规则书）：

> **"你确定是哪件事、哪一天，就自己去翻；不确定就问老师 —— 问清楚比猜错好。"**

三条让它站得住：
1. **符合人设** —— "老师说的是哪一次……？"是自然台词，不是能力不足的暴露
2. **边界写死：先自己解决，解决不了再问**（否则变成"什么都问"，与"习惯性伸手"同病）
3. ⭐ **"问玩家"本身就是在往上下文里写数据** —— 玩家一回答，下一轮根本不用查

⭐ 这也是**模糊时间表达的最终归宿**：**定位（模糊→具体）归对话；表达（具体→区间）归 LLM；解析归引擎。**

### 3.6 延迟账（**要如实说，且要真机量**）

| 步 | 是什么 | 调用 |
|---|---|---|
| ① 她发起 | 主调用 #1（**独占轮，只输出一行**） | LLM ×1 —— **输出极短** |
| ② 翻译 | —— | ⭐ **0 次**（下方四条压掉） |
| ③ 查找 | 词面 + 图遍历 + 语义 | **零 LLM** |
| ④ 回灌 | 拼 messages | 零 |
| ⑤ 输出 | 主调用 #2 | LLM ×1 |

⇒ **固有成本 = 2 次主调用**（与 `inspect` 同族，省不掉 —— §1.1 的理由："没查到就先答"是错的）
⇒ **②被压到 0 的四条**：① 绝大多数表达**引擎零调用能解**（结构化 / 词表 / **事件锚走标题解析器** / 锚表）
② 容错层吃常见说法 ③ ⭐ **多数 `look` 根本不需要 `when`**（锚是事件/实体）④ **翻译与检索可并行**（时间只用于收窄）

⚠️ **MMT 单轮的端到端耗时没有可信数字** —— 埋点现成（`mmt_turn` / `mmt_stream_first` / `llm chat task=mmt out=/in=`），
**先量再决定要不要进一步优化**。

### 3.7 频率：它是**慢路**

| 场合 | 走哪条 | 调用 |
|---|---|---|
| "知道那是谁" | **预装**（名字 + 一句话） | 零 |
| "这轮想起什么" | **引擎每轮摆 1~2 条** | 零 |
| "骨架里已经有的事实" | **常驻骨架** | 零 |
| ⭐ **"我必须知道它才能说下一句"** | **`look`** | **2 次** |

⚠️ **规则书要写"回忆是动作，不是习惯"**（防每轮都查、防延迟）—— 与 `inspect` 那条"习惯性伸手"同源。

## 4. `noticed` —— 把东西送出去

### 4.1 形状（**已裁**）

```json
{"noticed": "瓦片缝里的苔藓"}
```

**一个字段、一个字符串** —— 砍掉 `quote` / `what`：
**定位 · 校验 · 归并维度全是引擎的**，她只做"**指一下是哪条**"。

⚠️ 不进 `action`（`MMT_DESIGN §8` 不做：那她就有两个靠"觉得需要"触发的口子 ⇒ 习惯性伸手）。

### 4.2 她给不了一对，**只给"过去那一端"**

⭐ **她只做「旧 ↔ 当下」**；**「旧 ↔ 旧」是 L2 的活**（要整组视野）。
一轮里想起多条 ⇒ **写多行**（记录行**零代价**）⇒ 它们都连到同一个"当下" ⇒ 当下固化后**自动同群**。

⇒ ⭐⭐ **群不是"她判定两条旧事同类"形成的，是"她在不同时刻分别想起它们"形成的。**

### 4.3 链路（**已裁 2026-09-29：只记账 + L1 落地**）

```
① 她输出   {"noticed": "瓦片缝里的苔藓"}
② 引擎解析标题 → 唯一 episode（命中 0 ⇒ 丢 · 歧义 ⇒ 不猜）
③ 引擎【只记一笔】：(她指的 episode_id, 本段, 本轮 seq)      ← 不落边
④ L1 建完 episode ⇒ 引擎【在那时落边】：
      akin{ 新 episode → 她指的那条, ts = 此刻 }
⑤ L2 分群 ⇒ **建群节点** + `member_of` 边（见 §4.5）
```

### 4.4 ⭐ 为什么是"只记账 + L1 落地"，而不是"seq 边 + 二分提升"

**原设计（`MMT_DESIGN §3.4/§3.5`）在代码上走不通**：

```python
store.add_edge(rel, src, dst)
    →  if src not in self._nodes or dst not in self._nodes:
           raise DanglingEdge("边端点不存在")
```

⭐ **`add_edge` 拒悬空，两端必须是节点 id** —— 而"当下"是 **seq 区间，不是节点**
⇒ 原设计的边**在边表里没有合法表示**。

**"只记账 + L1 落地"的四条好处**：

| # | 好处 |
|---|---|
| 1 | **不违反 `add_edge`** —— 落边时两端都是真节点 |
| 2 | ⭐ **不需要"二分提升"** —— L1 建 episode 时**本来就知道**自己覆盖哪些 seq |
| 3 | ⭐ **不产生孤儿边** —— 该段没产出 episode ⇒ 那笔记录自然失效（**下次 L1 重扫**，见 §6） |
| 4 | ⭐ **零新存储** —— **账本来就在事件流里**（记录行交付即落事件），L1 从本段事件里读那些 `noticed` 行即可 |

**代价（如实说）**：`noticed` 的效应**延后到 L1**。
⚠️ 但**它本来也要等 L1** —— 边要进群得等 L2，而 L2 在 L1 之后。⇒ **延后没有实际损失。**

⚠️ **由此作废的两条**（别再往回捡）：
- ❌ "边先落 `{seq区间 → episode}`" —— 边表没有这种端点
- ❌ "L1 后二分提升 seq → episode id" —— 不需要提升，因为**边根本还没落**

### 4.5 ⭐ 群是什么（**2026-09-29 定案；同时推翻 `PROCEED §2 #2`**）

#### 4.5.1 一句话

> **名字是群的属性（住节点）；成员是随时间建立的关系（住边）。**

```
soul/wiki.jsonl
  {"id":"g0001","kind":"group","title":"苔藓","ts":"…"}

soul/edges.jsonl
  {"rel":"akin","src":"m0014","dst":"m0015","ts":"…"}   ← 她当时觉得像（原始发现）
  {"rel":"member_of","src":"m0014","dst":"g0001","ts":"…"}   ← L2 判定属于这一类
  {"rel":"member_of","src":"m0025","dst":"g0001","ts":"…"}   ← 新 episode 加入 = 就加这一行
```

#### 4.5.2 为什么**两条边都要**（不能合并）

| 边 | 是什么 | 谁写 |
|---|---|---|
| `akin(ep ↔ ep)` | ⭐ **"她觉得这两条像"** —— 原始发现，可能错、可能只是两两 | **她**（每轮，纯边无属性） |
| `member_of(ep → group)` | ⭐ **"L2 判定它属于这一类"** —— 归纳结果，可合并/拆分/多归属 | **L2** |

**前者是输入，后者是输出。** ⚠️ 混成一条会让"她觉得像"和"判定同类"不可区分 ——
而真机证据（dense 相似度组内最低 < 组外最高，最差 **0.425**）说明**她的"像"是有噪音的**，必须由 L2 复判。

#### 4.5.3 为什么成员**必须**是边（不能存 `members` 列表）

| 加一条成员（⭐ 高频：每次 L2 跑） | |
|---|---|
| **存列表** | 读列表 → append → 写回。⚠️ **丢掉"什么时候加入的"** —— 整批成员共享群节点的 `ts` |
| **存边** | ⭐ `add_edge("member_of", ep, g)` —— **自带 `ts`** · **幂等** · **只 append** |

⭐ **"什么时候加入的"是信息，列表存不下。** 而且项目**明确在意边的时刻** —— `add_edge` 的 docstring 原文：

> *"2026-09-22: 原先默认空串, 结果写路径产的边全没有 ts —— 真机一轮后 `edges.jsonl` 里一半有、一半没有。"*

⚠️ **我在这一格上判错过一次，记档**：曾用"**群离开成员就不存在（那是个空集）**"论证"成员不是边、是群的内容"。
**错在把"当前成员列表"当成了"群的定义"** —— 而真相是：**成员是随时间一次次建立的** ⇒ 那是**关系**，不是构成。

#### 4.5.4 遍历：管"发现"，**不管"存在"**

```
BFS from episode, 只走 episode↔episode 边（akin）
  ⇒ belief / entity / promise / **group** 全部自动是墙
```

| | 靠什么 | 后果 |
|---|---|---|
| ⭐ **群的存在**（谁属于哪个群） | **显式的 `member_of` 边** | ✅ **完全不依赖遍历** ⇒ belief 挡不住它 |
| **群的发现**（L2 该看哪一块） | **遍历**（遇 belief 停） | ✅ 正好只给"**还没被任何 belief 收编的那部分**" —— 这是**想要的**，不是缺陷 |

⭐⭐ **这是"BFS 不过 belief ⇒ 用 belief 总结之后群被割裂"那个问题的解**：
**根因是把"发现"当成了"存在"** —— 一旦群靠 BFS 定义，belief 就成了墙；一旦群靠边定义，**墙只影响"看什么"，不影响"是什么"**。

⭐ **群节点本身也是一堵墙** ⇒ 已经归好类的不会再进候选 ⇒ **天然不重复归纳**。

#### 4.5.5 群上**不放**"关键信息"

| 信息 | 家 |
|---|---|
| **这是哪一类**（"苔藓"） | 群节点 `title` |
| ⭐ **这一类说明了什么**（命题 / 态度 / 成长） | **belief 节点** —— 它一直就是干这个的 |

⚠️ 群上再存一份"共同点"= **双真源**，L2 改了 belief 群上那份不会跟着改（必漂）。
`DESIGN_NOTE §5.3` 早把分界写死了：*"belief = 她的态度/命题 · 索引 = '这里有一类事'，**不含判断**"*。
⇒ 一个群可以有多条 belief（不同角度），一条 episode 也可属于多个群 —— 两边**都由边表达**。

#### 4.5.6 悬空：照抄 `note.refs` 那套

`members`/`member_of` 指向的 episode 若不存在 ⇒ **读侧跳过** + `audit()` 报一句，**不自动清理**
（`notes.check()` 的原话：*"不删条目、不改写 —— 那条线索失效不是她的错"*；清理是判定，归 L2）。

#### 4.5.7 合并两个群 ⇒ **零成员边改动**

给被并的群留档，加一条 **`evolved_from(g0001 → g0002)`**（该 rel 已存在，语义就是"新的取代旧的"）⇒
读侧顺 `evolved_from` 追到保留的那个群。**合并历史留痕**（谁并进谁、什么时候）。

## 5. 同步 / 异步的判据（一条，管四种情况）

> **不看贵不贵，看"它在不在她要等的那条路上"。**

| 位置 | 例 | 性质 |
|---|---|---|
| **生成之前**（前置） | `look` 的时间解析 / 检索 | **同步**（在独占静默轮里，玩家本来就在等） |
| **生成之中**（顺手） | `noticed` 多写一行 | ⭐ **不调用**（零成本） |
| **生成之后**（后处理） | emotion / place / 选图标注 | **异步**（玩家不等） |
| **离线批量** | digest L1 / L2 / L3 | **异步**（不在任何一轮的路上） |

⚠️ **`noticed` 不走异步**：① 异步会把它的成本从 0 变成 1（**毁掉它的存在理由**）
② ⭐ **异步看不到"当下"** —— 而"当下"就是 link 的全部价值（§4.2）
③ 它是比 `action` **更糟的第三种口子**：action 好歹是她自己的判断，异步是**引擎替她判**（违反"引擎决定看什么，LLM 决定是什么"）
