# 切片即账目 —— R0 单表契约（DESIGN_DIGEST_LEDGER）

> **2026-10-05 设计稿 · 尚未动代码。**
> 定位：**取代** `docs/EXEC_DIGEST_SPLIT.md` §13 那张"骨架 + 另开一块账"的形状。
>
> 一句话：**骨架与账目合成一张表** —— 一行 = 一件切片 + 它的账目状态。
> 约定从**出生切片**上长出来、在**了结切片**上关掉；没有那一刻的（生日那天没人来）**自成一行**
> （`span: null`）。**收口轮（`close`）整轮消失**，它的两件活分别搬进 R0 的表与引擎。
>
> ⚠️ 标记约定：**【裁】** = 用户本轮逐条裁决 · **【推】** = 由裁决直接推出、落在这里待确认 ·
> **【待】** = 仍未决。

---

## 0. 为什么要合

今天这条链上，同一批事实被**生产了两次**：

| | 谁产 | 长什么样 |
|---|---|---|
| **骨架** | R0（切分） | `{span, keep, abstract}` —— 位置真源，R1 照它填 |
| **账目** | R1 的 `keep=always`（3b-3）+ 收口轮 | `note/add` · `note/close` 操作 |

两边说的**本来就是同一件事**：一条 `keep=always` 的切片 = 一条要进备忘录的约定；
一条"了结了某约定"的切片 = 一次翻篇。分开产的直接代价是**两边要对上**
（`orders` 映射、`at` 指针、两条经历共享 span 时谁说了算）—— 而这对上的一步没有任何信息增益。

合起来之后，**位置、正文、账目共用一行**，引擎不再需要"把账接到叙事上"。

## 1. 表（形状）

```jsonc
[
  // 一件普通的事（与账无关）
  {"span": [28, 28], "abstract": "教师在周日突然邀请我去了咖啡厅"},

  // 说定了一件要带着的事 —— 进账
  {"span": [31, 31], "abstract": "下次一起去模型店", "state": "open", "due": "2026-05-10"},

  // 了结 n5 —— 那一刻就在这件切片里
  {"span": [31, 31], "abstract": "我把团子带来了", "state": "close", "id": "n5"},

  // 没有那一刻 —— 生日那天没有人来
  {"span": null, "abstract": "生日那天，老师没有来", "state": "close", "id": "n3",
   "title": "生日那天", "significance": 0.9}
]
```

### 1.1 真值表（**契约层当场校验，能红**）

| `state` | `span` | `id` | 另外必填 | 含义 |
|---|---|---|---|---|
| 省略 | **必填** | 必空 | —— | 一件普通的事（≈ 旧 `temporary`） |
| `open` | **必填** | **可空** | `abstract`（新建时＝将来的 note 正文） | 到**本段结束时仍开着**的约定（≈ 旧 `always` + 进 note）。**`id` 空 = 新建**；**`id` 有 = 更正那条**（§1.1b）。`due` 可选 |
| `close` | 可有可无 | **必填** | 无 `span` 时：`title` + `significance` | 了结某条约定；**无 `span` ⇒ `abstract` 就是那条经历的正文** |

三条**派生规则**（都由上表 + 闭集推出，不是额外机制）：

1. **`close.id` / `open.id` 必须是本轮料里出现过的编号**（**同一张闭集**：还开着的约定）⇒ **同段闭环天然不产生任何 note**：
   本段新开的约定还没有 id，模型不可能引用一个不存在的东西。用户那条
   *"出现 → 消失都在本章内 ⇒ 不特殊写入 note"* 因此是**结构性成立**的。
2. **`open` 只标"到本段结束时还开着的"**。否则同段闭环会被标成 `open`，而它没有 id 可以关
   ⇒ 永远开着 —— 正是这一整轮设计要消灭的那种病。
3. **`span: null` 只在引擎已判定该条超期时合法**（资格位，见 §3.3）。

### 1.1b ⭐ `open` + `id` = **更正**（2026-10-05 裁）

`open` 带 `id` 时**不是新建**，而是**更正那条还开着的约定**。它**替代**了"另加一条
`note/due` op"的方案 —— 在**行契约**里多一个组合，比在 op 表里多一个动作更省。

**它唯一必须干的事**：把"后来才知道的日期"补进去 —— *"不知道 → 她问 → 知道了"* 这条主路径
（不然那条 note 永远拿不到 `due` ⇒ 永远不过期 ⇒ 烂在本子上）。

| # | 规则 |
|---|---|
| 1 | **闭集**：`open.id` 与 `close.id` **同一张闭集** —— 本轮料里"还开着的约定" |
| 2 | **至少要改一样**（`due` 或 `text`），否则**拒** —— 与 revise 的"`update` 必须带非空 patch"同源（白跑一行不许） |
| 3 | **可改的只有两样**：`due`（补/更正日期）· `text`（重写那句）。⛔ 不许改 `refs`（出生地址）· `since` · 槽 |
| 4 | **留账**：引擎写一条 **`note/update`** op，带 `before` / `after`（与 revise 的 `changed` 同形）；`before == after` ⇒ **不写**（崩溃窗口重跑＝白跑，**不能假装变了**） |
| 5 | **名字**：⚠️ 与 revise 的 `update` 是**两个域**；与退役的 `rewrite` 的区别要写清 —— `rewrite` = **整槽替换**（`on_mind`），`update` = **按 id 改一条还开着的条目** |
| 6 | **那一行照样是一条记忆**：它有 `span` ⇒ R1 写正文 ⇒ 一条 episode（*"我知道了老师生日是 5/10"*）—— 位置、正文、召回全部自然成立（产出位置见 §2.1） |

⚠️ **为什么允许改 `text`**：不改的话，本子上会永远留着 *"我还不知道是哪天"*，而 `due` 已经补上
—— **自己跟自己矛盾**。note 是**当前抽屉**不是历史层（历史在事件流里，`update` 的 op 带
before/after），所以维护那句话是**维护当前状态**，不是篡改记忆。

### 1.2 两个 owner（**谁写哪个字段**）

| 字段 | 谁给 | 备什么 |
|---|---|---|
| `span` · `abstract` · `state` · `id` · `due` | **R0** | 位置 + 账目。R0 的料见 §3.6 |
| `title` · `text` · `verbatim` · `significance` · `tags` … | **R1** | 每条**有区间**的行 = 一条记忆（今天就是这样） |
| `title` · `significance`（**无区间**的行） | **R0** | 那条记忆没有别人写。没标题 = 她在视图里引不到它 |

⚠️ **`abstract` 的额度要分档**：有区间的行它是**骨架提示**（≤60，正文归 R1 重写）；
无区间的行**它就是她的记忆正文**（按 episode 文本上限，今天 `MAX_TEXT=300`）。
不分档 ⇒ "生日那天，老师没有来"只有 60 字的额度。

### 1.3 行 = 记忆

- **有区间的行**：R1 写一条正文。**同一个 span 允许两行**（既出又进："我把团子带来了，顺便又约了下周"）
  ⇒ 那就是**两条记忆**。【裁】
- **无区间的行**：**不经过 R1**（没有事件可写），正文已由 R0 的 `abstract` 给出。
  ⇒ **R1 的料只含有区间的行**（对齐照旧按下标；D1 的"漏填/多写"判据要跟着重写 ——
  "同一时刻的第二条记忆"从此是合法常态，不再告警）。
- **`open` / `close` 的行不许 drop**；普通行照旧可 drop（收下裁决 + 记账）。
- ⚠️ **`close` 行若被 drop**：**照样划掉 + 记一笔**（账平是事实，与有没有留下正文无关）。
  先例 = 3b-3 的 `lost_kept`：收下她的裁决、但让它可见。【推】

## 2. 账目语义（note 面）

### 2.1 出生

`state: open` ⇒ 引擎建一条 note：

- `text` = 该行的 `abstract`（**原样** —— 与 3b-3 同口径）
- **出生地址** = 该行长出来的 episode（`refs`）
- `due` 原样带过（没有就不带）

⚠️ **产出位置**：仍在 **record 那一轮的引擎段**（它手里有"行 → episode"的映射；
今天 `_pinned_ops` 就是这么做的）。判据从 `keep` 换成 `state`，并新增 `close` 那一类。
顺序是**正确性**：note 必须排在 R1 建完节点之后（`refs` 要真 id）。

### 2.2 了结：一律划掉

三种结局 —— **兑现 / 失约 / 被新约盖过** —— **一律**：进图 + 从本子除去。【裁】

> 用户裁据：*"就算是 broken 也都划掉，只要是作废了就划掉进图从 note 中除去，
> 是否召回是 sig 那边那个矩阵的事情。"*

⇒ note 面**只留"还开着的"**：本子是**当前抽屉**，不是账簿（账簿 = 事件流 + 图）。

连带删除（不清就是死代码）：

| 删 | 位置 |
|---|---|
| `close` 与 `retire` 的**两段式** | `core/brain/notes.py` 模块 docstring · `_apply_close` / `_apply_retire` |
| note 的 **`state`**（kept/broken/superseded） | `NoteItem.state` · `PINNED_OUTCOMES` · `_clean_close` |
| **结清组渲染** | `render_note_block` 里 `closed_at` 那一段 · `CLOSED_WORDS` · `_closed_suffix` |
| **`retire` 动作** | `notes.retire_op` · `_apply_retire` · `fold` 那一段 · `validate_ops` 的 `retire` 分支 |
| **`close` 操作的 `afterwards` / `state`** | `validate_ops` 的 `close` 分支（今天它**强制** `id` + `afterwards` + `state` 三样）⇒ 只剩 `id` |

⚠️ **代价（认下来）**：**确定的可见 → 概率的可见**。条目划掉之后，"她曾答应过什么"
靠**图里的经历**（召回）+ 它的 `significance`。note 是常驻（每轮都在她眼前），
经历是召回（相关度，不是保证）。这正是本设计要买的东西。

### 2.3 没有那一刻（`span: null`）

引擎建一条**无区间**经历：

| 字段 | 值 |
|---|---|
| `text` | 该行的 `abstract` |
| `title` | 该行的 `title`（R0 给） |
| `significance` | 该行的 `significance`（R0 给 —— "值很大"必须有人给，且不该由引擎替她拍） |
| `ts` | **那一天**（期限日）—— 记忆属于那天 |
| `event_seq` | **`[interact_max]`** —— 账记在本段（也是幂等键，见 §4.3） |
| `verbatim` | 空（没有事件，**绝不编** —— 已有先例） |

## 3. 时间（两个陷阱的落地）

### 3.1 口径

- 最小单位 = **现实天**；**剧情天 = 现实天**（`docs/ESSAY_TIME_MODEL.md`：
  *"日历 = 现实日期 + 日内时刻单调不回绕"*）。一天里发生 100 件事也是那一天的事。【裁】
- **过期当天算数**，无宽限（*"5/10 没来那就是没来"*）。【裁】
- **没有期限 ⇒ 永不过期**（"我会一直陪着你"这类本来就不该被判失约）。【推】

### 3.2 跨年同日（陷阱 1）【裁】

1. **`due` 只存全日期**（含年），**绝不存"5/10"这种**。
2. **比较只用全日期**，永远不许只看月日。
3. ⚠️ **给她显示可以省年份**（她视图里 `5/10` 更好读），**判过期不许** ——
   这是全项目**唯一一处"印剥有意不同源"**，注释里必须写明，否则下一个人一定会"顺手统一"掉。
4. ⭐ **只有"这一次、有明确时刻"的约定才写 `due`**；**年复一年的承诺不写**
   （「每年生日一起过」若写了今年那个日期，明年生日一过它就被判一次失约 ——
   跨年最容易咬人的就是这里）。契约里要把"一次性期限"和"往后一直算数"分开说，
   后者正是旧 `KEEP_SEMANTICS` 里「每年都来」那一档。
5. **料里两种措辞分开**：`本段期间到期` vs `已过 N 天`（陈年旧账）——
   否则模型会把这两件事混成一件。

### 3.3 资格位（陷阱 2 的一半）【推】

引擎算、**只摆事实不判死**：

```
due < 今天            （天粒度，全日期比较）
本段没有任何一处提到它  （引擎粗筛：词的相交，宁可多发）
过了几天               （age_days）
```

**判不判在 R0** —— 引擎替她判 = 把她没说的话写进记忆。
**过期未决**记一笔体检账（可 grep），**不自动作废**。

### 3.4 日期运算的真源【推 → ⚠️ **2026-10-05 订正**】

- ⛔ **`due` 一律 `date` 比 `date`**（`date.fromisoformat(due) < 今天`）—— **绝不喂
  `age_days`**: 那个函数吃的是节点 `ts` 那种 **aware** 时间戳, 裸日期会 `aware − naive`
  当场 TypeError（`tests/core/test_wiki_recall.py:146` 踩过一次）。
  "什么算全日期"的真源 = **`contract.digest_registry.is_full_date`** —— 料那一侧
  （`material._due_cell` / 资格位）与校验侧**共用同一个实现**。
- `age_days` 只管**带时刻**的那些（节点 `ts` / note `since`）—— 它仍是那条链的真源
  （`core/brain/read/recall.py` 的注释: *"别在这里手写 `fromisoformat`"*）。
- ⭐ **「今天」= 本段的最后一天**（段内最后一条内容事件的日期, 与 `ctx.now_ts` 同源）,
  **不是机器的挂钟** —— 补跑旧段时才不会把整段都判成超期（L3 采此解）。

### 3.5 "生日那天 / 特殊日子"怎么折算【裁 2026-10-05】

⭐ **陷阱**：这一类誓约**判不了** —— 原文只说"生日那天"，而今天的 R0 既看不见她的档案、
也看不见节日表。**两个办法都要**，它们覆盖的是两个不同子情形：

| 子情形 | 办法 |
|---|---|
| 原文**自带日期**（"5/10 那天"） | **让 LLM 写明确日期**就够（前提 = §3.6 的【本段的时间】） |
| 原文只说"生日 / 圣诞节 / 纪念日" | **必须注入** —— 把它们摆进 R0 的料，由它折算成绝对日期 |

⭐ **三档处理**（"不知道就问"是把第三档转成第一档的**手段**，不是新机制）：

| 情况 | 处置 |
|---|---|
| 原文**自带日期**（玩家说过"我生日 5/10"） | 写 `due`，正常判过期 |
| 档案里有（`SIG~birthday`）+ 引擎注入【日子】 | R0 折算成绝对日期 |
| ⭐ **她知道有这回事、但不知道日期**（"他说生日请我吃饭"，而谁也没说过哪天） | **不写 `due`** ⇒ 永不过期 ⇒ **挂在本子上等她将来知道**。⛔ **绝不猜** —— 猜错 = 误判失约，是这里最坏的错 |

**第三档怎么写才算诚实**（用户 2026-10-05）：那条备忘录**如实写"事实 + 空缺"** ——
*"老师生日那天约了我，我还不知道是哪天"*。

- ⛔ **不许编日期**（契约 + 提示词都要写死这条）。
- ⚠️ 而 *"我没好意思问他生日"* 这类**自我观察归 belief**（R2 的活），**不进备忘录** ——
  备忘录是约定的账，一放心境就会重新长出 `on_mind` 那种东西（那正是它被退役的理由）。

✅ **已裁（2026-10-05）：用 `open` + `id` 表达"补日期"，不另加 op** ——
`due` 只能在建 note 那一刻给的限制**没了**：后来知道了日期，就再来一行
`{"span": [..], "abstract": "……", "state": "open", "id": "n3", "due": "2027-05-13"}`
⇒ 引擎写一条 `note/update`（带 before/after）⇒ 过期判定恢复。规则全文见 **§1.1b**。

原本的两条备选（各记一句，别再回头）：

| 备选 | 为什么没选 |
|---|---|
| 补一条 `note/due` op（只补日期、不建不关） | 行契约里多一个组合就能表达，**不必动 op 表** |
| 不做，接受"老条目永不自动过期" | 账不平 —— 正是本设计要消灭的东西；而"不知道 → 问 → 知道了"是主路径，不是边角 |

⭐ 而第三档**自带触发器，不需要任何新机制**：那条挂着的约定**每轮都常驻在她眼前**
（备忘录注入 MMT 的 system 尾）⇒ *"你生日是哪天呀"* 是她看到它之后**自然会问的一句**。
她问到的那一刻，日期就进了原文 ⇒ 下一次 digest 走**第一条**路。

⚠️ 但"问"是**写作层**的行为（MMT / bond 的规则书），**不是记忆层的机制** ⇒
本次设计不为它加任何东西；若要教她"遇到自己不知道的重要日子就当场问"，
那是**另开一笔写作规则**（记在 `TODO_DIGEST_LEDGER §5`）。

**注入的最小集**（都是既有真源，零新存储）：

```
【日子】她 5/13 生日 · 老师 — · 本段附近：圣诞节 12/25
```

四条已查到的实情（**每一条都会咬人**）：

1. ⚠️ **生日格式不统一**：真机档案里 `5/13`（haruka · aru · mutsuki）与 `5月13日`
   （hina · ako · kokoro · iori）**两种并存** ⇒ 注入前要有**唯一解析器**（一形一义那条纪律）。
2. ⚠️ **生日有两个真源**：`profile.yml` 的 `SIG~birthday`（**给 AI 的**）与
   `config/settings/mmt_registry.toml` 的 `birthday`（**给显示用的**）—— 后者注释里
   已经划了这条线。R0 该读**前者**；**两者不一致时谁说了算，要写进文档**。
3. **节日表自己声明"生日不在这张表里"**（`config/eggs/festivals.json`）⇒
   生日与节日是两条源，注入要分别取。
4. ⛔ **老师的生日没有真源**：`config/player/profile.yml` 只有 `most_called_name` / `club`
   ⇒ **"老师生日那天"这一类目前折算不了**。要么给玩家档案补一个 `SIG~birthday`
   （字段集本来就与角色档案同一套），要么这一类只靠原文自带日期。

⭐ **这条路不依赖 `OccasionSource`**：`realtime.py` 自述"生日源尚未接"，那是给
**纪念日注记**那条链路用的；R0 的折算只要**直接读档案里那一行** ⇒ 它是独立的小活，不是前置。

**守门**（⭐ 2026-10-05 用户裁决，比我原来提的松）：

- **`due` 落在过去 ⇒ 收下、不告警** —— 用户原话：*"不太会出现这种情况，要是真出现了，
  LLM 有自己的理由吧，而且下一轮 digest 的 LLM 估计就反应过来了"*。
  ⭐ **这条之所以安全**：写了过去的日期 ⇒ 引擎下一段算出来的资格位就是"超期" ⇒
  那条约定会被摆到 R0 眼前 ⇒ 她有机会自己纠正（或那本来就是她想说的）。
  **自愈，不靠拒。**
- **`due` 不是全日期 ⇒ 当没有期限**（不落这个键、不告警）—— 引擎判不了就退化成
  "永不过期"（宁缺勿错）。⛔ 绝不替她滚到明年、也绝不替她猜。

### 3.6 料里加的那一格（**R0 专属，R1 不加**）【裁】

```
【本段的时间】2026-05-08 ~ 2026-05-10            ← 段可能跨天，给范围；单日就印一个
【日子】她 5/13 生日 · 老师 — · 本段附近：圣诞节 12/25   ← §3.5
【还开着的约定】
n3 生日那天一起去吃蛋糕   期限 2026-05-10（本段期间到期）
n1 带老师看瓦片缝的苔藓   期限 —（没有期限）
```

- 段的时间 = 段内事件的 `ts` 范围（引擎算）。
- ⚠️ **R0 今天的料里一个日期都没有**：`ctx.timeline = render_timeline(new_events, indexed=True)`，
  行首是 `[seq]` 索引。它今天**没有任何能力**说"这条过期了"。
- ⚠️ **R1 不给**：它写正文，正文里出现绝对日期会与既有的"剧情里不走绝对日期"口径打架。【裁】

✅ **落地（L3, 2026-10-05）** —— 实际印出来的三格（`material.py`，守门 `test_round_split.py`）::

    【本段的时间】2026-05-08 ~ 2026-05-10          ← 跨天给范围, 单日只印一个
    【日子】她 5/13 生日｜节日：元旦 1/1 · 情人节 2/14 · 教师节 9/10 · 圣诞节 12/25
    【还开着的约定】                                ← 名单非空才出现
    - n3 生日那天一起去吃蛋糕  ← 记于 3 天前    期限 2026-05-10（已过 3 天）
    - n7 周六去模型店          ← 记于 1 天前    期限 2026-05-09（本段期间到期）
    - n1 带老师看瓦片缝的苔藓  ← 记于 12 天前   期限 —（没有期限）

三条与本文早先写法的**差异**（都是当场裁的, 记下来免得回头改）:

1. **不另开【该有个说法】那一段** —— 它就是名单里的**措辞差**（`已过 N 天` / `本段期间到期`
   / `没有期限`）。另开一段 = 同一条印两遍; 真正的"格"是**引擎侧的资格位**（模型看不见）。
2. **节日表整张印**, **不设"附近"窗口** —— 六月里说定"圣诞节一起过"照样要折算, 窗口会把
   它挡在外面; 表是作者手编的（今天 4 行）, 长得很慢。
3. ⛔ **老师的生日那一格不印** —— `config/player/profile.yml` 没有生日字段（2026-10-05 查）;
   印 `老师 —` 等于告诉她"有个你不知道的东西"。生日真源取**档案**（`SIG~birthday`），
   与 `mmt_registry.toml`（显示用）不一致时**以档案为准**。
   ⇒ §3 待裁的"谁说了算"与"玩家生日缺源"两条**采此解结案**。

**资格位怎么算**（`_ledger_ids`, 引擎侧, 模型看不见）: `note_ids` = 名单里每一条的 `id`
（= `parse_split` 的闭集）; `overdue_ids` = 其中 `due < 今天` **且本段没提到它**的。
"提到"的粗筛两条（任一命中即算提到）: ① 它的出生经历 `refs` 的 `event_seq` 与本段 seq
有交集 ② 那些经历的 `tags` 出现在本段时间线里 —— 两条都不中 ⇒ 算"没提到"（**宁可多发**,
判不判在她）。

## 4. 固化（下游）

### 4.1 有区间的行

`_expand_spans` → `seqs` → R1 写正文 → episode（**如今天，零改动**）。

### 4.2 覆盖台账

按**集合**算。⚠️ 同一 span 两行**不影响**"未认领 = 0" ——
`_expand_spans` 早就返回"被 ≥2 条切片共享的 seq 数"，其 docstring 原话：
*"重叠如实报告、不裁：同一段事件本来就可以同时是两件事"*。
⇒ 唯一要守的两处纪律：覆盖**按集合去重** · `_find_duplicate`（kind + `event_seq` 相交 +
**正文全等**）不许因为两条正文写得一样而误合（钉一条测试）。

### 4.3 无区间的行（**幂等 —— 这里有个已验的洞**）

⚠️ `core/brain/revise.py:850`：`_find_duplicate` 第一行是 `if not node.event_seq: return None`
—— 而它存在的**唯一理由**是"崩溃窗口重跑防双写"。无区间的节点若 `event_seq` 为空，
**每重跑一次图上就多一条"生日那天，老师没有来"**。
⇒ **`event_seq = [interact_max]`**（R2/R3 的段级指针是既有先例；记忆属那天、账记本段）。

### 4.4 章收口

`_collapse_bond_episodes` 合并时 **`state` / `id` 不许丢** —— ✅ **落地（L4, 2026-10-05）
采的是"账目行不参与收口"**, 不是"把标记并进保留那条":

- ⚠️ 本文原来那句"它今天只保 `keep` 与 `abstract`"**不准确**: 保留那条一直带着自己的
  `state`/`id`（代码只动 `seqs`）; 真正会丢的是**被丢那几条**的账目。
- ⛔ 而"并过去"**表达不出来**: 一行只装得下**一个** `state`/`id`（两条 `close` 并进一行?）。
- ⇒ 规则: 收口只吃**无账目的行**; 带 `state` 的（`close` / 第二条 `open`）**整条留下**。
  丢一条 `close` = 那条约定永远开着 = **账不平**（用户: *"账不平比补判更糟"*）;
  丢第二条 `open` = 另一条约定从来没进过本子。
  代价: 这一章可能多于一条记忆（位置照样由引擎兜满整章）。
- 守门: `test_collapse_never_drops_a_ledger_row` · `test_collapse_keeps_two_open_rows_as_two_promises`
  （**变异验过能红**）。

✅ **§4.2 的覆盖纪律也已钉住（L4）**: 同一个 `span` 两行 ⇒ 未认领仍 = 0;
`_find_duplicate`（kind + `event_seq` **相交** + **正文全等**）不许把正文不同的两行合掉
（`test_the_same_span_twice_is_two_memories`）。

✅ **§4.3 的无区间行在 segment 侧已隔离（L4）**: 它**一个 seq 都不认领**（连 `seqs` 都不给）、
不被章收口吞掉、也不算覆盖
（`test_null_span_row_claims_no_position_and_is_never_collapsed`）。

⚠️ **留给 L7 的一个坑（本次查出来的）**: 无区间 episode 的 `event_seq = [interact_max]`
是**账的指针, 不是覆盖声明** —— 而 `pipeline._next_watermark` 读的正是 `node.event_seq`
⇒ 它会以为"整段都被覆盖了", 把**欠着的尾巴**一起推过水位（那些尾巴从此不再重喂）。
建那种节点时**必须把它排除在水位计算之外**。

### 4.5 关系与标记

- **出生 episode ↔ 了结 episode 不建边**：边表只有 6 条、刚砍过一轮；
  "这条经历了结了那条约定"留在 note 的事件流里。而"我把团子带来了"本来就会写在
  R1 给那条切片的正文里 ⇒ 读路径不缺这句话。
- **`#pinned` 打给出生那条 episode**（语义 = "这是她随身带着过的一件事"），了结那条不打。
  ⚠️ 判断在 R0 ⇒ 那条 episode 是同一批新建的 ⇒ **建节点时就能写 tag，不需要走 revise 通道**。

### 4.6 接口
