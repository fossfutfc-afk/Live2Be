# DESIGN_MEETUP — 见面式对话扩展（预期设计, 未立项）

> **状态（2026-09-10）**：用户口述预期定稿, **仅入档, 代码零改动**。
> 位置：与 MMT（手机聊天）、BS/VN（羁绊剧情板）并列的**第三种形态**候选——
> "见面式对话"（邀约/扯皮窗）。立项前以本文为准，冲突以本文为先。
> 实现难度预估：**中等偏低**（复用为主, 详见 §5）; 相关讨论链：Storyloom

## 1. 一句话

玩家在 MMT 里**显式发起邀约** → 进入一个"见面场景"：现场氛围（背景/差分/打字机
视觉壳）下的**纯粹对话**——玩家一句、角色 2~4 句, 爱聊多久聊多久, 不承载剧情
推进。本质 = "见面式 MMT", 多一层差分与背景, 少一层故事。

## 2. 用户拍板要点（2026-09-10 口述, 定稿）

1. **入口 = 玩家的独立显式动作**：玩家点击发起（不做自由文本意图识别——彻底
   回避误报问题; 手机呈现形态参考："发送自己的定位" 这类消息卡片式动作）。
   玩家可以借此主动制造话题（"我今天到你们学校门口了" 式的扯皮由玩家发起,
   非系统判定）。
2. **形态 = 纯粹的对话**：见面式 MMT（玩家一句 → 角色 2~4 句, 现场口吻,
   可用（）短神态）; 视觉壳只加背景/差分/打字节奏。
3. **不触发 memorial**：这个窗口**不生成纪念/生成立绘的资格**, 低赌注社交。
4. **是否结束由玩家自己决定**：玩家说再见/主动点离开 = 收尾; 不是 LLM 剧情
   裁决（story_end 语义不适用）。
5. **意外中断 ≠ BS**：此处**不同于羁绊剧情的中场退出**（BS: vn_enter 在押、
   重进回放续写）——见面对话意外中断/离开 = **直接打终止符号**收束, 不保留
   续写链（纯对话无"剧情中途"概念, 续聊没有结构意义）。
6. 邀约到确认之间（答应/拒绝/讨价还价/被拒绝后再说）属于**扯皮窗口**的一部
   分——学生有权拒绝（例：`{action: "decline", reply: "嘻嘻，老师求我，不然
   我可不来"}`）, 但拒绝话术须**留活口**（有条件/下次/继续求都行）, 拒绝是
   调情不是终局。

## 3. 关键区别速查

| | BS（羁绊剧情） | Meetup（见面对话） |
|---|---|---|
| 入口 | LLM 触发（mmt_trigger_bond_story） | **玩家显式动作**（发定位式卡片） |
| 生成单位 | 板（自然段+可选 choices） | 回合（玩家一句 → 角色 2~4 句） |
| 内容承载 | 完整小剧情（起承转合/黑屏收尾） | 纯对话/扯皮, 无剧情弧线 |
| memorial | 可触发 | **不触发** |
| 结束权 | LLM 创作裁决（story_end） | **玩家**（说再见/点离开） |
| 意外中断 | vn_enter 在押, 重进回放续写 | **直接打终止符号**, 不续 |
| 记忆消化 | 闭环 digest（bond 语义） | 未定（见 §6 未决②） |

## 4. 延迟前提（已实测, 2026-09-10）

探针 `.testtmp/probe_meetup_latency.py`（v4-flash 直连, 流式, max_tokens 512,
短 system + 一句用户输入）：

| 档位 | TTFT | 总时长 | 说明 |
|---|---|---|---|
| off（思考关） | 172ms | 0.66s | 输出较短, 味道略平但未崩 |
| low | 109ms | 2.5s | 结巴/自贬细节已齐 |
| high（现网主档） | 157ms | 2.2s | 最稳, 也在 3s 内 |

结论：**"自由输入为代价, 等 3s 可以" 的前提成立, 且不需要降档**——短回合下
thinking 开销被稀释, high 档总时长 ≈ 2.2s; TTFT < 200ms 意味着打字机可即时开打。
（探针为短上下文单发; 完整链路 +1s 量级仍落在 3~4s 预算内。）

## 5. 实现难度预估与分期（备忘, 立项后再细化）

架构位置建议：**不建独立域**, 做成 mmt 引擎的"现场场景态"——确认后切换场景
态（背景/地点/差分/现场 tone）, 消息事件/窗口/digest 走 mmt 既有管线;
marker/`session_status` 照 vn_enter/memorial 痕迹加第三种态。

- P0 事件语义：enter/exit/终止 marker + status 扩展 + CLI 最小现场循环
  （输入 → 2~4 句 → 落事件）——**先验证"直接打终止"语义**;
- P1 入口与现场：玩家显式邀约（卡片式）→ accept/decline（留活口规则）→
  地点选择（玩家自由输入 → place 白名单匹配/fallback 背景）;
- P2 视觉壳：背景 + 差分 lane（照 bond 晚到补切机制）+ 底部自由输入框;
- P3 收口：digest/好感挂点定案（§6 未决②）、prompts/夹具定稿、全量测试。

风险最集中的不是实现, 是语义决策——入口（已定：显式动作）、decline 规则、
离开判定, 均已在上文定稿或留未决。

## 6. 未决（立项时逐项拍板）

   需要玩家再说一句/点击移动卡片?）——预期允许但形态未定。
2. **对话如何进记忆**：纯对话的 digest 价值/节流（bond 密度高、见面密度低
   主题散——可能要见面专属 digest 策略或直接按 mmt N=25 规则）; 好感结算
   是否随每次见面累积。
3. **终止符号后的事件流呈现**：见面段如何归档/展示（终止段是否像
   exclude_abandoned 一样在窗口/digest 中被遮断）。
4. 超长见面会话的上下文窗口策略（120 单元之外, mmt 既有 digest 是否够）。
