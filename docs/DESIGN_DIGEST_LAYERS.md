## 0. 一句话

**把 digest 从「按轮分层」改成「按视野分层」** —— 一层只干它视野内干得了的事：

| 层 | 视野 | 频率 | 干什么 |
|---|---|---|---|
| ⭐ **L-M 对话轮（MMT / VN）** | **当下** | **每轮** | ⭐ **发现相同**（link）—— 见 §0.1(f) · 📄 **详细设计 = `docs/MMT_DESIGN.md`** |
| **L1 本段** | 这一次来访 | 必跑 | episode 抽象（区间切分）+ note 记账 |
| **L2 跨段** | N 条**同类单位** | 有新 episode 就跑；**有候选才做真活** | **collision**（分群 → 派生出 C）+ 全部关系连接 |
| **L3 实体** | 某 entity 的**全部** mention | **异步** | 动态人设基线（entity 摘要）—— 派生缓存 |

⚠️ **`L-M` 不是 digest 的一轮** —— 它是 **MMT/VN 那一侧的活**（每轮对话里的"想起"）。
它**在 L1 之前发生**，是 L2 的**上游**（组是它边走边连出来的）。

**账**：今天的 `R1 → R4 → R2 → R3` + 全景轮（`4 轮 + 1 旁路`）⇒ 本方案 `2 次同步 + 1 次异步`。

## 0.1 ⭐⭐ 根因与最终分工（2026-09-27 用户收口）

> 用户原话：*"link 和 collision 都要求全量视图，复杂度 O(wiki)，成本巨大；RAG 以及机械召回不可靠，
> 只能做辅助；就算预先像 entity 一样群分，类别极度容易膨胀；agentGal 所谓的关联并不能觉察出细节，
> 因为 belief 是越走越宽的，但生活中的细节才更加令人感动，我们的 link 的终极需求就是找到这些细小的相同；
> 不过话说回来，人有时也是想起某件事情才会发现联系，**难道说其实 Link 是 mmt 的活？**"*
> → 下面逐条核实，**最后一条成立，而且它一石五鸟**。

### （a）根因：**我们是流式的，而 link 与 collision 都要求「批量回看」**

| 痛点 | 证据链（全部真机实测） |
|---|---|
| **link** | `episode↔episode` 边 **0 条** → 写 `links` 的那个 LLM **视野里没有旧经历**（20 条 `supports` 全由 `decisions` 产生，`links` 只写过 **2 次**）→ `add` 契约只收 **1 条** episode |
| **collision** | 4 条 belief **全部诞生自 1 条** → 后来只是 `touch`（印证）⇒ **A→C→B** → 病：**模式判断在 n=1 时就下了**（`e0001` 出生即说"她有个习惯"）→ **框架锁死**（LCP 0.00~0.62）· **抽象被稀释**（抽象句占比 0% / 34% / 34% / 20%，7 条证据那条是 **0%**） |

⇒ ⭐ **共同要求 = 回看（batch review），不是流式（streaming）。**
⇒ **而"全景轮"的存在本身就是证据** —— 我们早就感觉到需要回看，只是给了它一个被 ≤20 字压死的出口。
⇒ **所以三层重排不是"加一层"，是「把纯流式改成流式 + 回看」，而 L2 就是那个回看。**

### （b）修正：**O(wiki) 里贵的不是"全量"，是"让 LLM 读全量"**

| 操作 | 复杂度 | 贵不贵 |
|---|---|---|
| 向量扫全量找最近邻 | O(N) | ⭐ **毫秒级 —— 引擎层完全没问题** |
| 让 LLM 判"这两条同类吗" | **O(N²) 次调用** | ❌ **不可能** |
| 让 LLM 看**整组** | O(组) | ✅ 可接受 |

⇒ ⭐⭐ **约束不是"不许全量"，是"别把 O(N) 的东西喂给 LLM"。**

### （c）RAG / 机械召回：**只能做辅助**（实测支持）

| | 实测 |
|---|---|
| 做**判定**（阈值划类） | ❌ **组内最低 < 组外最高**，最差 **0.425** ⇒ **阈值不存在** |
| 做**排序**（提候选） | ✅ **top1 4/4 语义正确**（Q11） |

⇒ **排序可用，判定不可用。** ⇒ 它是"提候选 + 给理由（`why`）"的角色，**不是判据**。

### （d）预先像 entity 一样群分：**会膨胀**（实测支持）

真机 18 条 episode 的 tag 分布：

```
n=6: 约定        n=4: 杂草屋 · 笔记      n=2: 大扫除 · 模型店 · MomoTalk
n=5: 夏莱        n=3: 纸兔子 · 苔藓            中秋节 · 月亮 · 杂草
```

⭐ **12 个 tag 值：4 个 n≥4 · 2 个 n=3 · 6 个 n=2（一半）**
⇒ **闸 ≥3** ⇒ 只剩 6 组，**且会漏掉"道歉"**（它 n=5，**可 tags 里根本没有这个词**）
⇒ **闸 ≥2** ⇒ 12 组里一半是名词噪声
⇒ ⭐ **闸设多少都不对** —— **"预先分组"这条路本身有问题。**

### （e）⭐ Link 的定义要改：**不是"找同类"，是"找到这些细小的相同"**

> 用户：*"belief 是越走越宽的，但生活中的细节才更加令人感动 —— 我们的 link 的终极需求
> 就是找到这些**细小的相同**。"*

**AgentGal 的规则恰好证明了这一点**（`UNDERSTANDING_PATCH` 原文）：
*"`add` 的认知应该与已有认知是**同一抽象程度**；如果是包含关系 ⇒ **修改已有认知的 subject** 以反映这个关系"*
+ *"`subject` … **不以具体情境命名维度**…太窄的应**归入更宽的维度**，把情境观察写进 content"*

⇒ ⭐ **它的 belief 朝抽象走（subject 越改越宽）** —— 而那句台词的力量**不在**"他每天送花"（抽象），
**在**"紫罗兰 / 洋甘菊 / 水仙 / 向日葵"（**4 个具体名字**）。

| 我原来设计的 | 用户要的 |
|---|---|
| 找**同类的实例**（先有"花"这一类） | ⭐ **找"同一件具体小事"在不同时刻的重复**（"他记得我随口说过的话"） |
| 维度 = **类别**（名词 / 行为） | ⭐ 维度 = **那个具体的行为本身** |

### （f）⭐⭐⭐ **Link 移交 MMT** —— 成立，且**一石五鸟**

**人的机制不是"后台扫全库"**：人是 **"某一刻突然想起来"**，而"想起来"是**被当前情境触发的**。
⇒ ⭐ **联系是在「用」的时候发现的，不是在「存」的时候算出来的。**
**而 MMT 就是"用的时候"** —— 她手上有：当前对话 + 历史窗口 + 记忆注入。
⭐ **digest 那次离线调用没有"当下" ⇒ 它没有"被什么触发"。**

| 原来的难题 | MMT 怎么解 |
|---|---|
| O(wiki) 的 LLM 成本 | ⭐ 不需要全量 —— **每轮只并置 1~2 条**（引擎召回），成本摊到每轮 |
| **类别膨胀** | ⭐ **不预建类别** —— 她在**具体两条**之间发现相同，不需要先有"类" |
| **触发问题** | ⭐ **当下就是触发** —— 不需要阈值，也不需要"每 10 段" |
| **细节 vs 抽象** | ⭐ 她手上是**具体那一条**（"您说过地砖里的苔花也是花"），不是类别 |
| **可校验性** | ⭐ 她必须**引用具体实例** ⇒ 引擎能查"这条引用真实存在吗"（**nacre 的强制锚点**） |

⭐⭐ **而且它打破了循环**：

```
原来：L2 要先分组才能派生  ⇄  分组又要先有 link        ← 循环
现在：⭐ link 由 MMT 在对话中自然产生 ⇒ L2 一上来就有组
```

### （g）最终分工

| | 谁 | 手上有什么 | 干什么 | 频率 |
|---|---|---|---|---|
| **link（发现相同）** | ⭐ **MMT / VN（当下）** | 当前对话 + **1~2 条召回** | ⭐ **发现"这两条是一样的"** | **每轮**（轻） |
| **collision（派生命题）** | **L2（离线）** | **整组全文** | 看分布 ⇒ **写出 C** | **过闸才跑**（重） |

⇒ ⭐ **MMT 负责「发现」（轻 · 频 · 有线索 · 可校验）· L2 负责「派生」（重 · 疏 · 要整组）。**
⇒ **而 L2 不再需要自己找组** —— 组是 MMT 边走边连出来的。

### （h）四个风险与对策

| # | 风险 | 对策 |
|---|---|---|
| **1** | **她可能不说** | ⚠️ 有前科：**提示词里的反例会把要的行为禁掉**（陷阱 40）⇒ **正面给例子**（"您上次也说过同样的话"是 RP 里最动人的瞬间之一） |
| **2** | ⭐ **MMT 的产出是"说出来的话"，不是"边"** | ⭐ **落库由引擎做**：从**她的引用**里提取"她在指哪两条" ⇒ 落 `same_kind` 边。**她只需要说，记账是引擎的**（内容与判定分离） |
| **3** | **她可能瞎联想**（Kindroid 的编造病） | ⭐ **锚点校验**：她引用的实例**必须真实存在** ⇒ 编造的引用直接丢 |
| **4** | **重复发现** | 边**幂等**（`add_edge` 天然幂等） |

⭐ **方向问题**：她总是"**从当下回想过去**" ⇒ **发现时是有向的**（当下 → 过去）；
而"同类"是**无向的** ⇒ **发现时有向、落库时规范化成无向**（`canonical_pair`）。

### （i）⚠️ 一个待定：她引用的"当下"，那时还没有 episode

- 她发现"这和上次一样"的那一刻，**当下这件事还没成为 episode**（episode 是 L1 的产物）
- ⇒ **两个候选解法**：
  - **(a)** 她引用**当下的原话** ⇒ 引擎按 `event_seq` 定位 ⇒ **L1 建完 episode 后补边**（**待挂记录**）
  - **(b)** 边的一端直接用 **seq 区间**（事件流即时存在）—— ⚠️ 但两端类型不一致
- ⇒ ⭐ **倾向 (a)**：MMT 侧只落一条**待挂记录**，**L1 建完 episode 后由引擎补边**（两端都是 episode，语义一致，幂等好做）
- 📌 **待用户裁**（见 §7）

## 1. 为什么要重排（膨胀的根源）

**今天按「轮」分层，每一轮都什么都干一点** ⇒ 每轮输入都要塞很多东西，而且**五处都在"隔着一层"干活**：

| 今天的轮 | 视野 | 它实际能做 / 不能做 |
|---|---|---|
| R1 | 本段 | 想切跨段的事件，但只有本段 ⇒ **切得烂**（号码袋，**40% 无人认领**） |
| R4 | 本段 + 约定名单 | 收口约定（本职，没问题） |
| R2 | 本段 + 候选（**只有 belief**） | 想归纳，但**候选池不含 episode** ⇒ **做不了归纳**；且**看不到边、看不到证据数** |
| R3 | 本段新节点 | 归属（本职，没问题） |
| 全景轮 | 跨段 | **唯一**看得到跨段 ⇒ 但产出被 `≤20 字` 规格压死 |

**真机证据全部在 `PROCEED.md`**（§2.4 零碰撞 · §4.5 框架锁死 · §4.6 MMT 处理形式 · §4.7 本节）。本文不重复。

## 2. L1 规格 —— 本段（**进事务**）

### 2.1 契约（`PHASE_RECORD` 的输出）

```json
{
  "episodes": [
    {"span": [213, 223],
     "text": "…",                       // 第一人称浓缩，不流水账
     "title": "…",                      // 8-16 字
     "verbatim_seq": [220, 221],        // 逐字锚点（索引 → parse 层回填原文）
     "tags": ["苔藓", "约定"],
     "items": ["果酱瓶"],
     "significance": 0.85,
     "emo_int": 0.7, "emo_span": 0.5,
     "about_hint": "老师"}              // 自然名字 → R3/L2 映射成 entity id
  ],
  "promise": [
    {"action": "add", "text": "带老师看瓦片缝的苔藓", "refs": ["m0014"], "due": ""},
    {"action": "close", "id": "n1", "state": "kept", "afterwards": "他真的来了"}
  ],
  "on_mind": "我给瓦片留了缝让它见光——也想给自己留一道"
}
```

### 2.2 ⭐ 三个关键形状

| # | 形状 | 为什么 |
|---|---|---|
| **①** | **`span: [from, to]` 替代"覆盖哪几个 seq 号"** | 今天的 `event_seq` 是**号码袋**（校验只有 `⊆`）⇒ 密度可低到 **0.17**、区间**跨骑**、**40% 无人认领**。区间只有"从哪到哪"，**连续性由构造保证** |
| **②** | **`unclaimed` 由引擎算，不由 LLM 写** | 引擎取 `seq_set − ∪span` ⇒ 归入闲聊，**不落节点** ⇒ **40% 丢失结构性消失** |
| **③** | **`promise` / `on_mind` 合并进 L1 的同一次调用** | 约定是"当场说定的"、心境是"此刻" ⇒ **本段视野就够**（今天这两样在 R4 + 全景轮，跨了两次调用） |

### 2.3 引擎侧处理（`digest.py`，插在 `_resolve_verbatim` 旁边）

```python
def _expand_spans(entries: list[dict], seq_set: set[int]) -> None:
    """span → event_seq（区间内**全部**内容 seq）。就地下场，下游零改动。"""

def _resolve_overlaps(entries: list[dict]) -> list[str]:
    """重叠区间 → **先到先得** + 返回告警（**不打回**：打回要重写整段，成本 > 收益）。"""

def _backfill_unclaimed(seq_set: set[int], entries: list[dict]) -> tuple[int, int] | None:
    """未被任何 span 覆盖的号 → 归闲聊。**不产节点**，只回一个区间供日志。"""
```

⭐ **下游零改动的理由**：节点的 `event_seq` 字段**不变**，只是来源从"LLM 挑的点"变成"引擎展开的区间"。
`_create_a_nodes` / `_node_ts(node.event_seq, by_seq, ts)` / `_collapse_bond_episodes` / R3 / 注入 / 召回 **全部不动**。
`_collapse_bond_episodes`（一章一条）**从主力降级成兜底** —— 区间化之后一章天然是一个连续区间。

### 2.4 ⚠️ L1 的两条禁令

1. **`decisions` 里不许出现 `add` / `update`** —— 那是 L2 的活 ⇒ **L1 不碰图**。
2. **`habits` 槽从 note 的读写路径上删掉** —— 它是"规律"的劣质替身 ⇒ 归 L2 的 belief。

### 2.5 L1 判据

- 区间展开 = 该区间内全部内容 seq
- 重叠区间 → 先到先得 + 告警，**不丢内容**
- ⭐ **覆盖率 100%**：`∪episodes.event_seq ∪ unclaimed == seq_set`
- 旧档（只有 `event_seq` 没有 `span`）**照旧读得进**（向后兼容）
- 真机探针重跑一次 digest：**密度 1.0 / 交错 0 / 覆盖 100%**

## 3. L2 规格 —— 跨段（**进事务**）

### 3.1 候选池：「窄而深」

> ⚠️ **"窄"是检索，"深"不是** —— RAG 解决"给谁"，"深"解决"给成什么样"。两句串联，不是同一件事。

**三维度，不许平铺成一维**（今天代码把三个维度的切法混叫"通道"）：

| 维度 | 取值 | 今天 |
|---|---|---|
| **语料**（从哪取） | `episode` · `turn`（玩家回合）· `entity:<名字>`（mention 集） | ⚠️ **只有 belief/experience —— 少了 episode 一整类** |
| **匹配**（怎么算分） | `semantic`（embedding）；无服务 ⇒ **降级** `anchor`（tag/子串） | 语义 **或** 字面（降级关系，不是并行） |
| **取数**（怎么合） | ⭐ **证据融合**：`why` 列表，**不打总分** | 直接按分数 top-k，**没有合** |

```python
@dataclass
class Evidence:
    node: BrainNode
    why: list[str]        # ⭐ 证据融合的载体："与 m0015 同 tag「苔藓」" · "语义 0.87" · "同 entity 老师"
    edges: list[Edge]     # 深：出边 + 入边（含方向）
    n_evidence: int       # 深：被引数（belief 的厚度）
    when: str             # 深：段/日标签（"09-26 晚"）—— 判跨段用
    quote: str            # 深：verbatim（逐字锚点）

def gather_evidence(store, *, corpora=("episode", "turn"), matcher="semantic",
                    budget_tokens: int = 2000, deep_k: int = 5) -> list[Evidence]:
    """混合（多语料）+ 证据融合（why）+ **按 token 预算装填**（不是条数截断）。
    前 deep_k 条渲染"深"，其余渲染"浅"（id + 标题 + why）。"""

def render_evidence(evs: list[Evidence], local_of: dict[str, str], *, deep_k: int = 5) -> str:
    """渲染成 LLM 能读的小块（`m0014 「瓦片缝里的苔藓」(09-26 晚 · sig 0.85)` + 正文/原话/边/被引/理由）。"""
```

**三条设计决定，各有真机理由**：

| 决定 | 理由 |
|---|---|
| ⭐ **不做分数融合（RRF 也不做）** | 真机：nomic 下"无关"最高 **0.865 > "相关"最低 0.848**（区间交叠）；Qwen3 下分开但窗口只有 **0.014 宽**。⇒ **我们的排名在同一主题内不可靠**，而判定者已经是 LLM —— 它要**理由**，不要总分 |
| ⭐ **证据融合用 `why` 列表** | `panorama.py` 的 `Candidate.why` **已经就是这个形状**（它的注释：*"候选如实标注来源——她看得见'这两条只是共享一个泛词'，才拒得掉"*）。**不是新发明，是把它抬成通用件** |
| ⭐ **按 token 预算，不按条数** | 今天 `cap=12` / `k=3` 是条数；"深"会让每条变贵 ⇒ 条数截断与深度互相打架。预算则显式、可观测 |

**不做/降级的两条**（今天有代码、但不需要）：

| 项 | 处置 |
|---|---|
| **graph spreading（一跳扩散）** | ❌ **砍**。图只有 18 节点 / 39 边，一跳无信息增益。**降级成一种语料**：`corpora=("entity:老师",)` 就是"提到老师的全部节点" |
| **temporal 通道** | ❌ **砍**。我们的 query 不是时间区间 —— **时间是判据（判跨段），不是检索通道** |

### 3.2 L2 契约

```json
{
  "groups": [
```

**四条硬规矩**：

| # | 规矩 | 理由 |
|---|---|---|
| **①** | ⭐ **`ignite` 与 `groups` 是两个键、两次调用** | `ignite` 要**重新找框架**，不能被"分群"的任务挤在同一段注意力里（"框架锁死"的教训） |
| **②** | ⭐ **`decisions` 里不再有 `add` / `update`**（见 §3.6 五动作） | 今天 `add` 是"**排除法兜底**"（真机铁证：4 个认知**全部诞生自 1 条 episode**）⇒ 新建本该是"归纳"的产物。**这条一写死，"框架锁死"在契约上不可能发生** |
| **③** | **`text` 第一句是命题**（带频率/条件词：总 · 常常 · 就算 · 只要 · 每次） | 真机实测抽象句占比 **0%（m0003）/ 34% / 34% / 20%** —— 有 7 条证据的那条反而 **0%**（每次只能在末尾加从句 ⇒ 实例稀释抽象） |
| **④** | **`growth` 的起点必须出现在 `text` 里** | 真机 `m0003` 的 growth 说「从『**我不配**』…」，而 `text` 里**没有"我不配"这个起点** —— 两个字段各写各的，互不约束 |

### 3.3 promotion 闸（四条，全部可测 —— **全是引擎的，不花 LLM**）

| 判据 | 阈值 | 真机对照 |
|---|---|---|
| **成员数** | **≥3**（且只数 `conf ≥ 0.8` 的边，见 §3.6） | 真机真组 4 / 5 / 6 / 6 / 7 ✅ |
| **跨段** | **≥2 个段** | 挡掉兔子组（`m0009/m0011/m0012/m0013` **全在段 4** —— 同段共现是"同一天"的构造事实，不是相似性） |
| **该群还没有 belief**，或 **belief 的证据落后于群成员数** | `supports 边数 < 群成员数` | —— |
| **反例** | 有 `contradicts` ⇒ 优先级**更高**（不是更低） | 真机 **0 次** —— 这条支路从未被触发过 |

⚠️ **闸只决定"要不要问 LLM"，不决定"要不要生成"** —— 生成与否由 §3.6 的 `covered` 判据（LLM）定。

### 3.6 ⭐⭐ 五个动作 + 谁决定什么（2026-09-27 用户裁决后成形）

> 用户两问：*"假如已有的 episode 群和另一个群撞了，是生成新 belief 还是 update？"*
> *"既然定义明确，你认为决定动作的应该是 engine 还是 LLM？"*

#### 判据（唯一一句）

> ## 引擎决定「**看什么**」，LLM 决定「**是什么**」。
> **所有动作的"落地"永远是引擎的**（节点 / 边 / aspect 归一 / 归档）—— LLM 只输出**判断**与**文本**。

**为什么这条是对的**（真机证据，不是原则口号）：**LLM 判不出来的，往往不是它笨，是引擎没把它放到眼前。**
R2 的视野里**没有旧经历** ⇒ `supports` / `contradicts` **结构性写不出来**——
真机 20 条 `supports` 全部由 `decisions` 产生（episode→belief），`links` 只写过 **2 次**。

#### 五个动作（`update` 不在其中）

| # | 动作 | **闸**（引擎：什么被看到） | **判**（LLM：它是什么） | **做**（引擎） | 花 LLM |
|---|---|---|---|---|---|
| **1** | **`join`** —— 新 episode 属某已有群 | 候选（锚点 / tag / 近邻）+ **如实标注 `why`** | "算不算同一类" | 落 `same_kind` 边 | 分群那次 |
| **2** | **`merge`** —— 群撞群 | ⭐ **成员重叠 ≥ 阈值 ⇒ 引擎直接并**（纯计算） | 名字同义 / 成员不重叠但同类 | aspect 归一 + 边重连 | 分群那次 |
| **3** | **`ignite`** —— 群跨过质变 | §3.3 四条闸 | "**覆盖得了吗 + 缺什么**" + 写正文 | 落节点 + N 条 `supports` + `about` | ⭐ **单独 1 次** |
| **4** | **`contradicts`** —— 对立 | ⭐ **冲突候选通道**（§3.8） | "对着来吗" | 落边 | 分群那次 |
| **5** | **`reignite`** —— **认知偏移矫正**（原 `update` 的正身） | ⭐ **保证它被看到**（§3.7） | "漂了吗" + 重写 | 新版本 + `evolved_from`（旧版**归档不删**） | 单独 1 次 |

⭐ **注意动作 1**：**加入一个已有群是零成本的**（分群时顺手判）—— 这正是"**link 廉价**"的含义。
绝大多数新 episode 都走这条路。

#### ⭐ `join` 的引擎快路（"能不让 LLM 做的不让 LLM 做"）

```
同 about_hint + tags 交集 ≥1 + 群已有 ≥3 成员   ⇒   引擎直接 join（不调 LLM）
```

⚠️ **防它的风险**：假阳性 join ⇒ 群变大 ⇒ **误触发 ignite**（花钱）。⇒ **对策**：

> **引擎 join 的边打低 `conf`（如 0.5）；`ignite` 的闸只数 `conf ≥ 0.8` 的边。**
> ⇒ **引擎可以便宜地加边，但"花钱的动作"只由高置信的边驱动。**

#### `ignite` 的触发判据：**"旧 belief 覆盖不了新的群"**

**不是"群变大了"就 ignite**（变大本身不值得花钱 —— 补边就够）。判据是让 LLM 回答：

```
"这条 belief 是否说了这一群的**全部**？如果有成员它没涵盖，是哪条、缺什么？"
  ├─ 全涵盖 ⇒ covered=true ⇒ 只补 supports 边（免费）
  └─ 有缺口 ⇒ covered=false ⇒ ⭐ ignite，而 gap 正好是**新 belief 该说的话**
```

⭐ **一石三鸟**：① 它是"**不够 abstract**"的可操作定义（真机 `m0003` 显然覆盖不了 7 条证据的差异）
② 它给出新 belief 的**内容方向** ③ 它**可测**（有缺口 / 无缺口）。

**辅助触发**（次要）：时间跨度跨阈值（"一晚"→"一整周"）· 出现张力（`contradicts`，**优先级最高**）。

#### `ignite` 的输入：**永远是「整群原文」**

```
输入 = 群内全部成员的 text + verbatim + 时间锚（**不是旧 belief 的文本！**）
```

⇒ ⭐ **"巨大 belief"从哪来**：不靠"改写旧的"，靠"**新生成一条**"。
旧的 belief **原样留着**（它没说错，只是窄）⇒ 两条并存 = BeliefMem 给 `self-reinforcing error` 开的药方。

#### `update` 的处置（原语义拆解）

| 原 `update` 的用途 | 新归属 |
|---|---|
| 并入新例子 | ⇒ **`join`**（只加边，正文不动） |
| 新角度 / 深化 | ⇒ **`ignite`**（重读整群，生成新的） |
| **事实性修正**（她写错了） | ⇒ **`reignite`**（§3.7） |
| ~~措辞微调~~ | ❌ **不做** —— 正文里的例子数量本来就该有上限 |

#### 调用账（回答"LLM 负担"）

| 时机 | 调用 | 频率 |
|---|---|---|
| 每次来访（有新 episode） | **L2-a 分群** —— `join` / `merge` / `contradicts`，只产边 | 必跑，**输出很小** |
| **只在过闸 + `covered=false` 时** | **L2-b `ignite`** —— 输入整群原文，产一条 belief | ⭐ **可能 0 次** |

### 3.7 ⭐ 认知偏移的两个来源（`reignite` 的边界）

> 用户原话：*"update 应该是发生**认知偏移**的时候进行矫正用的，虽然也不知道能不能召回的了"*

| 偏移来源 | 例子 | 处理 |
|---|---|---|
| **世界变了**（他不这样了） | 老师不再送花 | **`contradicts`**（事实对立）+ 可能 `reignite` |
| **她自己变了**（她不再那样想） | "我以前觉得不配，现在不这么想了" | ⭐ **绝不改写** —— 这**本身就是两条 belief**，`evolved_from` 连起来，**旧的原样留着** |

⇒ ⭐ **`reignite` 只用于"她当初写错了"，不用于"她变了"。**
（"她变了"是**成长**，是最该保留的叙事；改写它会毁掉"我以前……"这句话的资格。）

⚠️ **"不知道能不能召回得了"要正面回答**：这条**不能靠"LLM 判得准"解决**，只能靠
**引擎保证"可能冲突的那条"被放到眼前** ⇒ 见 §3.8。

### 3.8 ⭐⭐ 冲突候选通道（引擎的活，零额外 LLM）

**今天的做法是反的**：`recommend_candidates` 把「**最像的**」belief 给 LLM（帮它**找家**）——
而**冲突检测要的是「最不像的、但主题相同的」**。

```
冲突候选通道（纯引擎）：
  取本段新 episode 的 about_hint / tags / aspect
    → 在同一对象（同 entity）或同一 subject 下的 belief 里
    → 挑相似度【最低】的那些（= 主题相同但结论相反的嫌疑）
    → 连同「它的正文 + 它的边 + 被引数」一起摆到 L2 眼前
```

⭐ **为什么这能行**：**"世界变了"必然表现在新经历里**，而新经历与旧 belief 的相似度**会掉下来**。
⇒ **引擎不需要判断"冲突"，它只需要判断"谁该被看一眼"** —— 这是可计算的。

⚠️ **边界**：这条通道会**过召**（主题相同的都进来）。**可接受** ——
因为**过召的代价是几个 token**，而**漏召的代价是"她永远不会矫正"**。

### 3.4 让 `contradicts` 真的会被写出来（保留：两个根因）

**它今天是"机制齐全、零数据"**：`REL_CONTRADICTS` 在 `RELS` 里 · `store.add_contradiction` 有 API ·
`render_organize_view` 有渲染 · **三处测试** —— 真机 **0 条**。

**两个根因，都要修**：

1. **视野缺"旧经历"这一层**（`_round_b_material` 的候选只给**本地 id**，候选池只有 belief/experience）
   ⇒ `supports` / `contradicts` 的**两端都在旧经历里**
2. **没有"去找矛盾"这个动作** —— R2 的任务定义是"挂到已有认知上"，**增量输入里永远不会自己冒出冲突**

⇒ L2 的 `evidence` 块要**显式给**：候选旧经历的**正文** + 它的**边** + **被引数**；
并在 prompt 里给一个**主动动作**（"这一段里有没有哪条旧经历，与某条看法**对着来**？"）。

### 3.5 L2 判据

- `groups_of()` 能读出群；**不同 aspect 不许误合并**
- 成员 <3 或全在同段 ⇒ **只落边不落节点**
- 已有 belief 的正文**逐字节不变**
- `decisions` 里出现 `add` ⇒ **契约拒**
- 每条新 belief 的 `about` 边 **≥1 且含 `x0000`/`x0001`**

## 4. L3 规格 —— 实体（**异步，不进事务**）

```
真源   = `about` 边（谁 mention 了谁）
缓存   = soul/entity_summary.json      ← 派生，删掉可重建，失败零损失
内容   = {x0001: {"name": "老师", "summary": "…", "state": [...], "up_to_seq": 314}}
```

| 面 | 规定 |
|---|---|
| **刷新时机** | 异步（同 `notes.json` 的模式）；失败**静默降级**、不影响水位 |
| **身份** | **动态人设基线** —— 静态人设 = `config/characters/*/personality.yml`，动态 = 这份 |
| **外部对应** | Hindsight 的 `S`（**preference-neutral entity summary**）—— **中立的观察，不带她的态度** |
| **判据** | ⭐ **删掉缓存重跑，结果一致**（真源永远是 `about` 边） |
| **注入** | `render_character_view` 加一段"**关于他们**"（待裁：替代一部分 episode 全量注入，还是并列） |

⚠️ **为什么要它**：真机 `m0003` 的正文 = "关于老师的**观察**"（必须具体）+ "她的**态度**"（必须抽象）**混在一条里**，
而这两半要求**相反** ⇒ **今天妥协的是态度**（只剩 `growth` 那 30 字）。这是"不够 abstract"的机制原因。

### 4.1 ⭐ L3 的注入位置 —— **既不是并列、也不是替代，是"换一种读法"**

> 用户 2026-09-27：*"按 refs 展开，给她一个特定的动作吧（动作到时候再设计即可），
> 也就是 refs 中展开（可选 link 连环）；index 后者；2 OK；**1 具体讲一讲**"*

**今天注入的账**（真机 haruka，`render_character_view` 实测 **4293 字 / 27 行**）：

| 块 | 字数 | 占比 |
|---|---|---|
| episode 全文（18 条，一条河） | **2644** | **86%** |
| belief（4 条） | 418 | 13.7% |
| note（6 条） | 96 | 3% |

**L3 的成本**：4 个 entity × ~70 字摘要 + 抬头 ≈ **~350 字** ⇒ 若"并列"，注入变 **~4650 字**（涨 8%）。

**但真正的杠杆不在 L3，在 episode 的"全文常驻"** —— 而这一条**恰好被用户刚裁的"refs 展开 + 动作"解锁了**：

| 读法 | 内容 | 今天 | 之后 |
|---|---|---|---|
| 静态人设 | 盒B（profile + personality） | ✅ | ✅ **不变** |

| 记账 | note | ✅ 96 字 | ✅ ~130 字（+ `index` 一行） |
| **合计** | | **4293 字** | ⭐ **~1400 ~ 1600 字（净减约 2/3）** |

**三个前提（缺一不可）**：

1. ⭐ **`refs` 有走法**（引擎按 refs 展开）—— ✅ **用户已裁**
2. ⭐ **`index` 的 topic 路由** —— 引擎据此知道"这轮该取什么"（§5.2 的连带发现）。**没有它就只能全量灌**

| 风险 | 说明 |

| 步 | 做什么 | 注入总量 | 验收 |
|---|---|---|---|
| **步 1** | ⭐ **只加 L3 + 加骨架，不砍正文** | 4293 → ~4650 字（涨 8%，可接受） | ① L3 的摘要是否真的有用（人眼看 + writer 引用率）② 骨架是否影响"一条河"的连贯感 |

## 5. 边与图（承载"规律"）

### 5.1 `Edge` 加两个可选属性

```python
@dataclass
class Edge:
    rel: str; src: str; dst: str; ts: str = ""
    aspect: str = ""      # ⭐ 新增：同类维度（只 same_kind 用）
    conf: float = 0.0     # ⭐ 新增：判断置信度
```

`to_dict` / `from_dict` / `add_edge` / `store.groups_of()` 同批改。
⚠️ `from_dict` 今天**静默丢弃**盘上的多余键 ⇒ 加属性必须**同批改读写两侧**。

### 5.2 `same_kind` 与"群"

| 面 | 规定 |
|---|---|
| **rel** | 新增 `same_kind`（episode ↔ episode），进 `RELS`（7 → 8 条） |
| **走法（§2.2 判据）** | "从一条经历出发，沿**同一 aspect** 走出来所有同类经历" ⇒ **走法成立**，不是装饰 |
| ⭐ **群的身份 = `aspect` 的值，不是连通性** | ⇒ `groups_of()` 就是 `group_by(aspect)`，**零算法**。不需要聚类、不需要连通分量、不需要 FCA |
| **边数** | **链式 N−1 条**（7 个成员 6 条边，不是 21 条）—— 组的定义是"共享同一个 aspect"，不是"两两相连" |
| **多归属** | **允许**（`m0017` 同时在「苔藓」与「带去夏莱」两群里）⇒ 不需要互斥分区 |
| **aspect 归一化** | 对照已有 aspect 小字典；**新增必须论证**（否则"苔藓 / 瓦片缝的苔藓 / 那盆苔藓"会把一组拆成三组）—— 与 R2 已有的 `subject` 纪律同型 |
| ⚠️ **语义** | 同一 aspect 下若有不连通的两簇（"他送礼"发生在两个时期）⇒ **合成一组是想要的**，不是 bug |

### 5.3 ⭐ `about` 两条边（"他"与"我"）

**最小落点：复用 `about_hint`** —— 它今天已经存在（R1 的 episode 产"自然名字" → R3 映射成 entity id），
只是**只有 R1 用它**。给 L2 的 `belief` 也加 `about_hint`（**可为两个**）即可，**零新概念**。

```python
belief --about--> x0000 伊草遥香      # ← 至少一条
belief --about--> x0001 老师          # ← 或两条都有
```

**为什么是两条**：那句台词有**两个主语** —— "您星期一送的紫罗兰…"（**他**的行为，重复）
+ "我这样的杂草…第一次找到了自己的太阳"（**我**的转变）⇒ **belief 挂 self + sensei 不是形式整齐，是那句台词的语法要求**。

**现状**（真机）：`m0018` **已连对 3 条**（x0000 + x0001 + x0002 杂草屋）；
`m0003` / `e0001` / `m0008` **0 条** —— 它们是 09-20/09-22 建的，而 **R3 是 09-25 才接线** ⇒ **历史遗留**，不是机制缺失。
⇒ 两件要做：**① 旧档回填 ② 加约束（≥1 且含 self 或 sensei）+ R3 从"批量挂"改"逐条判"**。

⚠️ **`about`（关于谁）与 `subject`（哪一面）是正交的，两个都要**：
"关于**老师的接纳**"与"关于**老师的期待**"是**同一个对象、不同维度** —— **边只能表达"关于谁"**。
