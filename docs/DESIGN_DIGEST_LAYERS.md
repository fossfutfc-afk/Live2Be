## 0. 一句话

**把 digest 从「按轮分层」改成「按视野分层」** —— 一层只干它视野内干得了的事：

| 层 | 视野 | 频率 | 干什么 |
|---|---|---|---|
| **L1 本段** | 这一次来访 | 必跑 | episode 抽象（区间切分）+ note 记账 |
| **L2 跨段** | N 条**同类单位** | 有新 episode 就跑；**有候选才做真活** | belief 抽象（分群 → 新 belief）+ 全部关系连接 |
| **L3 实体** | 某 entity 的**全部** mention | **异步** | 动态人设基线（entity 摘要）—— 派生缓存 |

**账**：今天的 `R1 → R4 → R2 → R3` + 全景轮（`4 轮 + 1 旁路`）⇒ 本方案 `2 次同步 + 1 次异步`。

---

## 1. 为什么要重排（膨胀的根源）

**今天按「轮」分层，每一轮都什么都干一点** ⇒ 每轮输入都要塞很多东西，而且**五处都在"隔着一层"干活**：

| 今天的轮 | 视野 | 它实际能做 / 不能做 |
|---|---|---|
| R1 | 本段 | 想切跨段的事件，但只有本段 ⇒ **切得烂**（号码袋，**40% 无人认领**） |
| R4 | 本段 + 约定名单 | 收口约定（本职，没问题） |
| R2 | 本段 + 候选（**只有 belief**） | 想归纳，但**候选池不含 episode** ⇒ **做不了归纳**；且**看不到边、看不到证据数** |
| R3 | 本段新节点 | 归属（本职，没问题） |
| 全景轮 | 跨段 | **唯一**看得到跨段 ⇒ 但产出被 `≤20 字` 规格压死 |

**真机证据全部在 `PROCEED.md`**（§2.4 零碰撞 · §4.5 框架锁死 · §4.6 MMT 处理形式 · §4.7 本节）。本文不重复。

## 2. L1 规格 —— 本段（**进事务**）

### 2.1 契约（`PHASE_RECORD` 的输出）

```json
{
  "episodes": [
    {"span": [213, 223],
     "text": "…",                       // 第一人称浓缩，不流水账
     "title": "…",                      // 8-16 字
     "verbatim_seq": [220, 221],        // 逐字锚点（索引 → parse 层回填原文）
     "tags": ["苔藓", "约定"],
     "items": ["果酱瓶"],
     "significance": 0.85,
     "emo_int": 0.7, "emo_span": 0.5,
     "about_hint": "老师"}              // 自然名字 → R3/L2 映射成 entity id
  ],
  "promise": [
    {"action": "add", "text": "带老师看瓦片缝的苔藓", "refs": ["m0014"], "due": ""},
    {"action": "close", "id": "n1", "state": "kept", "afterwards": "他真的来了"}
  ],
  "on_mind": "我给瓦片留了缝让它见光——也想给自己留一道"
}
```

### 2.2 ⭐ 三个关键形状

| # | 形状 | 为什么 |
|---|---|---|
| **①** | **`span: [from, to]` 替代"覆盖哪几个 seq 号"** | 今天的 `event_seq` 是**号码袋**（校验只有 `⊆`）⇒ 密度可低到 **0.17**、区间**跨骑**、**40% 无人认领**。区间只有"从哪到哪"，**连续性由构造保证** |
| **②** | **`unclaimed` 由引擎算，不由 LLM 写** | 引擎取 `seq_set − ∪span` ⇒ 归入闲聊，**不落节点** ⇒ **40% 丢失结构性消失** |
| **③** | **`promise` / `on_mind` 合并进 L1 的同一次调用** | 约定是"当场说定的"、心境是"此刻" ⇒ **本段视野就够**（今天这两样在 R4 + 全景轮，跨了两次调用） |

### 2.3 引擎侧处理（`digest.py`，插在 `_resolve_verbatim` 旁边）

```python
def _expand_spans(entries: list[dict], seq_set: set[int]) -> None:
    """span → event_seq（区间内**全部**内容 seq）。就地下场，下游零改动。"""

def _resolve_overlaps(entries: list[dict]) -> list[str]:
    """重叠区间 → **先到先得** + 返回告警（**不打回**：打回要重写整段，成本 > 收益）。"""

def _backfill_unclaimed(seq_set: set[int], entries: list[dict]) -> tuple[int, int] | None:
    """未被任何 span 覆盖的号 → 归闲聊。**不产节点**，只回一个区间供日志。"""
```

⭐ **下游零改动的理由**：节点的 `event_seq` 字段**不变**，只是来源从"LLM 挑的点"变成"引擎展开的区间"。
`_create_a_nodes` / `_node_ts(node.event_seq, by_seq, ts)` / `_collapse_bond_episodes` / R3 / 注入 / 召回 **全部不动**。
`_collapse_bond_episodes`（一章一条）**从主力降级成兜底** —— 区间化之后一章天然是一个连续区间。

### 2.4 ⚠️ L1 的两条禁令

1. **`decisions` 里不许出现 `add` / `update`** —— 那是 L2 的活 ⇒ **L1 不碰图**。
2. **`habits` 槽从 note 的读写路径上删掉** —— 它是"规律"的劣质替身 ⇒ 归 L2 的 belief。

### 2.5 L1 判据

- 区间展开 = 该区间内全部内容 seq
- 重叠区间 → 先到先得 + 告警，**不丢内容**
- ⭐ **覆盖率 100%**：`∪episodes.event_seq ∪ unclaimed == seq_set`
- 旧档（只有 `event_seq` 没有 `span`）**照旧读得进**（向后兼容）
- 真机探针重跑一次 digest：**密度 1.0 / 交错 0 / 覆盖 100%**

## 3. L2 规格 —— 跨段（**进事务**）

### 3.1 候选池：「窄而深」

> ⚠️ **"窄"是检索，"深"不是** —— RAG 解决"给谁"，"深"解决"给成什么样"。两句串联，不是同一件事。

**三维度，不许平铺成一维**（今天代码把三个维度的切法混叫"通道"）：

| 维度 | 取值 | 今天 |
|---|---|---|
| **语料**（从哪取） | `episode` · `turn`（玩家回合）· `entity:<名字>`（mention 集） | ⚠️ **只有 belief/experience —— 少了 episode 一整类** |
| **匹配**（怎么算分） | `semantic`（embedding）；无服务 ⇒ **降级** `anchor`（tag/子串） | 语义 **或** 字面（降级关系，不是并行） |
| **取数**（怎么合） | ⭐ **证据融合**：`why` 列表，**不打总分** | 直接按分数 top-k，**没有合** |

```python
@dataclass
class Evidence:
    node: BrainNode
    why: list[str]        # ⭐ 证据融合的载体："与 m0015 同 tag「苔藓」" · "语义 0.87" · "同 entity 老师"
    edges: list[Edge]     # 深：出边 + 入边（含方向）
    n_evidence: int       # 深：被引数（belief 的厚度）
    when: str             # 深：段/日标签（"09-26 晚"）—— 判跨段用
    quote: str            # 深：verbatim（逐字锚点）

def gather_evidence(store, *, corpora=("episode", "turn"), matcher="semantic",
                    budget_tokens: int = 2000, deep_k: int = 5) -> list[Evidence]:
    """混合（多语料）+ 证据融合（why）+ **按 token 预算装填**（不是条数截断）。
    前 deep_k 条渲染"深"，其余渲染"浅"（id + 标题 + why）。"""

def render_evidence(evs: list[Evidence], local_of: dict[str, str], *, deep_k: int = 5) -> str:
    """渲染成 LLM 能读的小块（`m0014 「瓦片缝里的苔藓」(09-26 晚 · sig 0.85)` + 正文/原话/边/被引/理由）。"""
```

**三条设计决定，各有真机理由**：

| 决定 | 理由 |
|---|---|
| ⭐ **不做分数融合（RRF 也不做）** | 真机：nomic 下"无关"最高 **0.865 > "相关"最低 0.848**（区间交叠）；Qwen3 下分开但窗口只有 **0.014 宽**。⇒ **我们的排名在同一主题内不可靠**，而判定者已经是 LLM —— 它要**理由**，不要总分 |
| ⭐ **证据融合用 `why` 列表** | `panorama.py` 的 `Candidate.why` **已经就是这个形状**（它的注释：*"候选如实标注来源——她看得见'这两条只是共享一个泛词'，才拒得掉"*）。**不是新发明，是把它抬成通用件** |
| ⭐ **按 token 预算，不按条数** | 今天 `cap=12` / `k=3` 是条数；"深"会让每条变贵 ⇒ 条数截断与深度互相打架。预算则显式、可观测 |

**不做/降级的两条**（今天有代码、但不需要）：

| 项 | 处置 |
|---|---|
| **graph spreading（一跳扩散）** | ❌ **砍**。图只有 18 节点 / 39 边，一跳无信息增益。**降级成一种语料**：`corpora=("entity:老师",)` 就是"提到老师的全部节点" |
| **temporal 通道** | ❌ **砍**。我们的 query 不是时间区间 —— **时间是判据（判跨段），不是检索通道** |

### 3.2 L2 契约

```json
{
  "groups": [
    {"aspect": "苔藓",
     "members": ["m0014", "m0015", "m0016", "m0017", "m0020"],
     "conf": 0.9,
     "belief": {
       "subject": "被看见",
       "text": "…",                          // ⭐ 第一句必须是**命题**（带频率/条件），例证在后
       "growth": "从「没人看」到「有人会来看我」",   // ⚠️ 起点必须能在 text 里找到
       "about_hint": ["老师", "伊草遥香"],     // ⭐ 两条边：他 + 我
       "conf": 0.85}}
  ],
  "rejected": [{"members": ["m0009", "m0012"], "why": "只是同一个地点，不是同一件事"}],
  "decisions": [{"episode": "m0021", "decision": "touch", "target": "u0002"}],
  "links": [{"from": "u0009", "rel": "contradicts", "to": "u0005"}]
}
```

**四条硬规矩**：

| # | 规矩 | 理由 |
|---|---|---|
| **①** | ⭐ **`belief` 字段可缺** —— promotion 判据不过就**只落边、不落节点** | 这是"**link 廉价、belief 昂贵**"的解耦点。否则"每个 link 一条 belief" ⇒ 100 天约 75 条 ≈ 7500 字，占注入 **1/3** |
| **②** | ⭐ **唯一的 `add` 在 `groups[].belief`**，`decisions` 只许 `touch` / `update` | 今天 `add` 是"**排除法兜底**"（真机铁证：4 个认知**全部诞生自 1 条 episode**）⇒ 新建本该是"归纳"的产物。**这条一写死，"框架锁死"在契约上不可能发生** |
| **③** | **`text` 第一句是命题**（带频率/条件词：总 · 常常 · 就算 · 只要 · 每次） | 真机实测抽象句占比 **0%（m0003）/ 34% / 34% / 20%** —— 有 7 条证据的那条反而 **0%**（每次只能在末尾加从句 ⇒ 实例稀释抽象） |
| **④** | **`growth` 的起点必须出现在 `text` 里** | 真机 `m0003` 的 growth 说「从『**我不配**』…」，而 `text` 里**没有"我不配"这个起点** —— 两个字段各写各的，互不约束 |

### 3.3 promotion 判据（四条，全部可测）

| 判据 | 阈值 | 真机对照 |
|---|---|---|
| **成员数** | **≥3** | 真机真组 4 / 5 / 6 / 6 / 7 ✅ |
| **跨段** | **≥2 个段** | 挡掉兔子组（`m0009/m0011/m0012/m0013` **全在段 4** —— 同段共现是"同一天"的构造事实，不是相似性） |
| **不重复** | 与已有 belief 语义近邻 ⇒ **能并入就不新建** | 唯一需要 LLM 判的一条 |
| **反例** | 有 `contradicts` ⇒ 优先级**更高**（不是更低） | 真机 **0 次** —— 这条支路从未被触发过 |

### 3.4 ⭐ 让 `contradicts` 真的会被写出来

**它今天是"机制齐全、零数据"**：`REL_CONTRADICTS` 在 `RELS` 里 · `store.add_contradiction` 有 API ·
`render_organize_view` 有渲染 · **三处测试** —— 真机 **0 条**。

**两个根因，都要修**：

1. **视野缺"旧经历"这一层**（`_round_b_material` 的候选只给**本地 id**，候选池只有 belief/experience）
   ⇒ `supports` / `contradicts` 的**两端都在旧经历里**
2. **没有"去找矛盾"这个动作** —— R2 的任务定义是"挂到已有认知上"，**增量输入里永远不会自己冒出冲突**

⇒ L2 的 `evidence` 块要**显式给**：候选旧经历的**正文** + 它的**边** + **被引数**；
并在 prompt 里给一个**主动动作**（"这一段里有没有哪条旧经历，与某条看法**对着来**？"）。

### 3.5 L2 判据

- `groups_of()` 能读出群；**不同 aspect 不许误合并**
- 成员 <3 或全在同段 ⇒ **只落边不落节点**
- 已有 belief 的正文**逐字节不变**
- `decisions` 里出现 `add` ⇒ **契约拒**
- 每条新 belief 的 `about` 边 **≥1 且含 `x0000`/`x0001`**

## 4. L3 规格 —— 实体（**异步，不进事务**）

```
真源   = `about` 边（谁 mention 了谁）
缓存   = soul/entity_summary.json      ← 派生，删掉可重建，失败零损失
内容   = {x0001: {"name": "老师", "summary": "…", "state": [...], "up_to_seq": 314}}
```

| 面 | 规定 |
|---|---|
| **刷新时机** | 异步（同 `notes.json` 的模式）；失败**静默降级**、不影响水位 |
| **身份** | **动态人设基线** —— 静态人设 = `config/characters/*/personality.yml`，动态 = 这份 |
| **外部对应** | Hindsight 的 `S`（**preference-neutral entity summary**）—— **中立的观察，不带她的态度** |
| **判据** | ⭐ **删掉缓存重跑，结果一致**（真源永远是 `about` 边） |
| **注入** | `render_character_view` 加一段"**关于他们**"（待裁：替代一部分 episode 全量注入，还是并列） |

⚠️ **为什么要它**：真机 `m0003` 的正文 = "关于老师的**观察**"（必须具体）+ "她的**态度**"（必须抽象）**混在一条里**，
而这两半要求**相反** ⇒ **今天妥协的是态度**（只剩 `growth` 那 30 字）。这是"不够 abstract"的机制原因。

### 4.1 ⭐ L3 的注入位置 —— **既不是并列、也不是替代，是"换一种读法"**

> 用户 2026-09-27：*"按 refs 展开，给她一个特定的动作吧（动作到时候再设计即可），
> 也就是 refs 中展开（可选 link 连环）；index 后者；2 OK；**1 具体讲一讲**"*

**今天注入的账**（真机 haruka，`render_character_view` 实测 **4293 字 / 27 行**）：

| 块 | 字数 | 占比 |
|---|---|---|
| episode 全文（18 条，一条河） | **2644** | **86%** |
| belief（4 条） | 418 | 13.7% |
| note（6 条） | 96 | 3% |

**L3 的成本**：4 个 entity × ~70 字摘要 + 抬头 ≈ **~350 字** ⇒ 若"并列"，注入变 **~4650 字**（涨 8%）。

**但真正的杠杆不在 L3，在 episode 的"全文常驻"** —— 而这一条**恰好被用户刚裁的"refs 展开 + 动作"解锁了**：

| 读法 | 内容 | 今天 | 之后 |
|---|---|---|---|
| 静态人设 | 盒B（profile + personality） | ✅ | ✅ **不变** |
| ⭐ **当前人设基线** | **L3** entity 摘要（他/我/地点现在是什么样） | ❌ | ⭐ **新增 ~350 字** |
| ⭐ **历史骨架** | episode **标题 + 时间**（一条河仍在，只是不再全文） | ❌ 今天直接全文 | ⭐ **~360 字**（18 × ~20） |
| ⭐ **按需正文** | **`index` 的 topic 路由 → refs 展开**（+ 可选 link 连环） | ❌ | ⭐ **300~600 字** |
| 态度 | belief | ✅ 418 字 | ✅ **瘦身 ~200 字**（"关于他的观察"归 L3，只留态度） |
| 记账 | note | ✅ 96 字 | ✅ ~130 字（+ `index` 一行） |
| **合计** | | **4293 字** | ⭐ **~1400 ~ 1600 字（净减约 2/3）** |

**三个前提（缺一不可）**：

1. ⭐ **`refs` 有走法**（引擎按 refs 展开）—— ✅ **用户已裁**
2. ⭐ **`index` 的 topic 路由** —— 引擎据此知道"这轮该取什么"（§5.2 的连带发现）。**没有它就只能全量灌**
3. **检索质量** —— ✅ Qwen3 已换（陷阱 38）

⚠️ **必须说清的风险**：

| 风险 | 说明 |
|---|---|
| **预取时机不可移动** | writer **一次调用中途不能去查** ⇒ 预取**必须发生在注入时** ⇒ **取错 = 她这轮看不到该看的** |
| **冗余消失** | 今天"全量灌"的**冗余正是它安全的原因**（总有一条在里面）⇒ 改成预取后**没有冗余兜底** |
| ⇒ **必须有兜底** | 预取失败 / 无 topic 命中 ⇒ **退化成"最近 N 条正文"**，而不是空 |

**⭐ 建议（待点头）：分两步走，别一次砍到底**

| 步 | 做什么 | 注入总量 | 验收 |
|---|---|---|---|
| **步 1** | ⭐ **只加 L3 + 加骨架，不砍正文** | 4293 → ~4650 字（涨 8%，可接受） | ① L3 的摘要是否真的有用（人眼看 + writer 引用率）② 骨架是否影响"一条河"的连贯感 |
| **步 2** | 验证 **refs 展开的命中率**之后，**再砍正文** | → ~1400~1600 字 | 预取命中率 ≥ 阈值（**需真机标定**，见 §7 未定 4） |

⇒ **为什么分两步**：避免"一次砍掉 2300 字、然后发现取不回来"。**步 1 是净增，但它买的是步 2 的可行性。**

## 5. 边与图（承载"规律"）

### 5.1 `Edge` 加两个可选属性

```python
@dataclass
class Edge:
    rel: str; src: str; dst: str; ts: str = ""
    aspect: str = ""      # ⭐ 新增：同类维度（只 same_kind 用）
    conf: float = 0.0     # ⭐ 新增：判断置信度
```

`to_dict` / `from_dict` / `add_edge` / `store.groups_of()` 同批改。
⚠️ `from_dict` 今天**静默丢弃**盘上的多余键 ⇒ 加属性必须**同批改读写两侧**。

### 5.2 `same_kind` 与"群"

| 面 | 规定 |
|---|---|
| **rel** | 新增 `same_kind`（episode ↔ episode），进 `RELS`（7 → 8 条） |
| **走法（§2.2 判据）** | "从一条经历出发，沿**同一 aspect** 走出来所有同类经历" ⇒ **走法成立**，不是装饰 |
| ⭐ **群的身份 = `aspect` 的值，不是连通性** | ⇒ `groups_of()` 就是 `group_by(aspect)`，**零算法**。不需要聚类、不需要连通分量、不需要 FCA |
| **边数** | **链式 N−1 条**（7 个成员 6 条边，不是 21 条）—— 组的定义是"共享同一个 aspect"，不是"两两相连" |
| **多归属** | **允许**（`m0017` 同时在「苔藓」与「带去夏莱」两群里）⇒ 不需要互斥分区 |
| **aspect 归一化** | 对照已有 aspect 小字典；**新增必须论证**（否则"苔藓 / 瓦片缝的苔藓 / 那盆苔藓"会把一组拆成三组）—— 与 R2 已有的 `subject` 纪律同型 |
| ⚠️ **语义** | 同一 aspect 下若有不连通的两簇（"他送礼"发生在两个时期）⇒ **合成一组是想要的**，不是 bug |

### 5.3 ⭐ `about` 两条边（"他"与"我"）

**最小落点：复用 `about_hint`** —— 它今天已经存在（R1 的 episode 产"自然名字" → R3 映射成 entity id），
只是**只有 R1 用它**。给 L2 的 `belief` 也加 `about_hint`（**可为两个**）即可，**零新概念**。

```python
belief --about--> x0000 伊草遥香      # ← 至少一条
belief --about--> x0001 老师          # ← 或两条都有
```

**为什么是两条**：那句台词有**两个主语** —— "您星期一送的紫罗兰…"（**他**的行为，重复）
+ "我这样的杂草…第一次找到了自己的太阳"（**我**的转变）⇒ **belief 挂 self + sensei 不是形式整齐，是那句台词的语法要求**。

**现状**（真机）：`m0018` **已连对 3 条**（x0000 + x0001 + x0002 杂草屋）；
`m0003` / `e0001` / `m0008` **0 条** —— 它们是 09-20/09-22 建的，而 **R3 是 09-25 才接线** ⇒ **历史遗留**，不是机制缺失。
⇒ 两件要做：**① 旧档回填 ② 加约束（≥1 且含 self 或 sensei）+ R3 从"批量挂"改"逐条判"**。

⚠️ **`about`（关于谁）与 `subject`（哪一面）是正交的，两个都要**：
"关于**老师的接纳**"与"关于**老师的期待**"是**同一个对象、不同维度** —— **边只能表达"关于谁"**。
