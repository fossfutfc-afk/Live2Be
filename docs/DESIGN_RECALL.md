## 1. 契约形式（**已定**）

### 1.1 动作与行形状

```json
{"action": "mmt_recall", "payload": {"scope": "memory", "query": "炸弹", "when": "上周"}}
```

- **独占静默轮**：与 `mmt_inspect_character` 同款 —— **那一轮只有它一条行**（不夹消息行、
  不夹别的操作行），引擎执行后把结果**回灌**，她带着回忆说下一句。
  理由：回忆是台词**前提**（"call → 工具结果回灌 → 再 call"），先说话再查就等于"没查到就先答"。
  ⇒ 实现上进 `WHOLE_TURN_ACTIONS`，并进 `build_line_schema` 的硬规则（现第 5 条扩成两条独占动作）。
- **一轮内的预算**：`RECALL_MAX_PER_TURN = 2`（超出那一行**丢弃 + 记账**，别让她反复查不停）。
- 结果**只往尾部插**（`feedback`），不动 system / history 前缀 —— 前缀缓存纪律。

### 1.2 payload

| 键 | 必填 | 说明 |
|---|---|---|
| `scope` | ✅ | 四支 + 一支占位，见 §1.3 |
| `query` | ⭕ | 关键词（人名 / 地点 / 物 / 一句话）。**空 = 最近的那些** |
| `when` | ⭕ | 时间范围。**只有带时间戳的支认它**（实现顺序：`events` 先）。见 §3.3 |

写进 system 的那段文案（`mmt_actions.py` 的 `payload_schema`，措辞按设计稿判据③
"意图形状、不是 API 形状"）：

```
scope: 你想翻哪一本 ——
    memory     你自己的记忆: 经历 / 看法 / 关于某人的印象 / 承诺
               （想知道"那次到底怎么了"「我怎么看他」时用它）
    events     原始记录: 当时**逐字**说过的话、发生过的场景
               （想核对原话, 或按时间翻"那天""最近"时用它）
    note       你备忘录里**已经结清或退场**的旧条目
               （手上还开着的本来就在上面, 不必查）
    chapters   你和他已经走完的羁绊剧情（标题 / 板数 / 有没有纪念图）
    inventory  你现在带在身上的东西（暂无内容, 恒空）
query: 关键词（人名 / 地点 / 物 / 一句话）; 空 = 最近的那些
when:  时间范围, 可省 —— "今天 / 昨天 / 前天 / N 天前 / 最近 N 天 / 上周 / 上个月"
       或 "9/20" "9月20日" 这类日期
```

### 1.3 四支 + 占位（**用户 2026-09-27 裁决：四支 + 空占位**）

| `scope` | 读哪里（真源） | 能回答 | 现成读入口 |
|---|---|---|---|
| `memory` | `soul/wiki.jsonl`：`episode` / `belief` / `experience` / `entity` / `group` + **6 类边**（⏸ `promise` 与它的三条边 2026-09-29 退图） | "那天到底怎么了"「我怎么想他的」"关于阿露我知道什么" | `recall_subgraph`（词面+语义）· `compose`（四路合成）· `render_character_view` |
| `events` | `soul/events.jsonl` 原始事件（对话 / 剧情 / 裁决 / 标记 + `ts`/`seq`） | **"当时到底怎么说的"**「那天的原话」 | `renderer.render_events` · `filter_bond` · `window_messages`（用来判断哪些**已在上下文**） |
| `note` | `soul/notes.json`（约定 / 惯例 / 最近在想） | "我答应过他什么"「上次那个约定后来怎么了」 | `notes.fold` · `NotesState.items` · `render_item` |
| `chapters` | 事件流派生的**已结束章** | "我们经历过哪几章"「那章叫什么」 | `chapters.chapter_index`（**与回忆册同源**） |
| `inventory` | 台账（`DESIGN_GRAPH_V4` §3.3：独立成系统、暂不做） | — | 恒空，**接口在** |

### 1.4 返回形状（**用户 2026-09-27 裁决：一行摘要 + 正文原样 top-k**）

```
[回忆 · memory · "炸弹" · 命中 3 条]
- （3 周前）[经历] 第一次和她去拆炸弹的那天，她紧张得一直捏着衣角……
- （2 周前）[看法] 她其实很怕黑，但在我面前从不承认
```

- **一条节点一行**：时间短语 + 类型标签 + **正文原样**（不改写、不摘要 —— 摘要会二次失真）。
- **不带 id、不带邻接表**（角色视图至今零 id 的纪律；`memory` 支尤其）。
  ⚠️ 例外：`note` 支**沿用现有渲染**（`n3 周六模型店 (m0009) ← 已结清（送出去了）`）——
  她的备忘块本来就印编号，且她要用编号去 `close`。
- **条数封顶**：top-k（默认 `k=5`，与 `[recall].sim_k` 无关，后者是"命中名次"）。
- **空结果明说**：`（你翻了翻，没找到相关的）` —— 不静默给空。
  两条理由：① 静默空会诱使她**反复查**（预算挡次数不挡体验）；② 明说"没有"能压住"编一个"。
- 长文本上限见 §4.2（落库时截断；当轮回灌同样截断，保持一致）。

## 2. 使用情景（用例倒推：她什么时候**真的**会调它）

### 2.1 先看她手上已经有什么（决定边际价值）

| 层 | 内容 | 判据 |
|---|---|---|
| 常驻 | 盒A + brain 记忆视图（分桶）+ **随身笔记块**（开着的 + 已结清的）+ P16 羁绊进度 + task 卡 | 每轮都在 |
| 窗口 | 最近 **120 叙事单元**（≈40 轮）的对话与剧情 | `window_messages` |
| 可按需 | `mmt_inspect_character`（**别人**的人设档案） | 已有动作 |

⇒ **recall 的边际价值只有两块**：**窗口之外**，以及**常驻层没有的粒度**（原话 / 时间 / 依据）。

### 2.2 用例表

| # | 情景 | 她心里那句话 | 该查哪支 | `query` | 返回**必须**含 | `when` |
|---|---|---|---|---|---|---|
| U1 | 玩家细问某个事件 | "那次到底怎么发生的" | `memory`（正文原样）；细节已被消化掉 ⇒ `events` 原文 | 事件关键词 | 正文 + **时间短语**（她要说"那是三周前"） | ⭕ |
| U2 | 需要 promise 的**依据** | "我答应的是哪一条、为什么答应" | `note`（**开着的已在常驻块** ⇒ 只有已结清/退场才需要）+ `memory` | 约定关键词 | 条目 + **它指向的记忆** | ✗ |
| U3 | 玩家**重复说过的话** | "他之前是不是说过" | `events`（窗口之外的**原话**） | 玩家原话关键词 | **逐字原话** + 时间 | ✅（"上次"就是时间型） |
| U4 | 问某个**具体的人** | "关于阿露我知道什么" | `memory`（`entity` 载荷 + `about` 边 + 相关 belief） | 人名 | 载荷字段 + 关联记忆 | ✗ |
| U5 | "我们经历过什么" | "我们做过哪些事 / 去过哪" | `memory`（episode 按时间）+ `chapters` | 空或关键词 | 一行一条清单 | ✗ |
| U6 | 她**怀疑自己记错了** | "我记得的是不是这样" | `events` 对 `memory`（**原话 vs 我的结论**） | 关键词 | 两边都给 | ⭕ |
| U7 | **时间型** | "上周三那天" | `events`（`ts` 窗口） | 空 | 那段时间的事件 | ✅ 必需 |
| U8 | 惯例 / 约定现状 | "我们有什么惯例" | ❌ **常驻块已给，不该查** | — | — | — |

### 2.3 三个"大致情景"（她实际用起来的样子）

```
情景 A — 玩家细问（U1 + U7）
  玩家：那天在屋顶你到底说了什么来着，我记不清了
  她：  {"action": "mmt_recall", "payload": {"scope": "events", "query": "屋顶", "when": "上周"}}
  引擎：（你翻到了——9/20 傍晚，屋顶）老师：我们上去吧。 / 我：上面风大，我带了外套。
  她：  {"text": "我说了『上面风大，我带了外套』"}
        {"text": "结果你根本没穿……我记着呢"}

情景 B — 承诺的依据（U2）
  她（想说"我答应过你的"）：{"action": "mmt_recall",
                            "payload": {"scope": "note", "query": "模型店"}}
  引擎：n3 周六模型店 (m0009) ← 已结清（那天去成了）
  她：  {"text": "周六那家模型店……我们说好要去的，已经去过了哦"}

情景 C — 玩家重复说过的话（U3）
  玩家：我不是说过我不吃辣吗
  她：  {"action": "mmt_recall", "payload": {"scope": "events", "query": "辣"}}
  引擎：（你翻到了——9/12）老师：我不太能吃辣，下次点清淡的吧
  她：  {"text": "……对不起，我忘了"}
        {"text": "那下次点清淡的，我记住了"}
```

### 2.4 从用例倒推出来的结论

- **被用例逼出来的只有两支：`memory` 与 `events`(+`when`)** —— 后者尤其高频
  （玩家爱说"上次"和"那天"，这两类问句**没有 `when` 就只能靠她猜日历**）。
- `note` 留契约但**低频**（开着的已在常驻块 ⇒ 边际价值只在"已结清 / 退场之后"）。
- `chapters` 只服务 U5 的一个变体，但**入口现成、返回极短** ⇒ 留着划算。
- `inventory` **无用例** ⇒ 恒空占位（§3.3）。
- ⚠️ **反例（不该查）**：常驻块已有的（U8）、窗口之内的对话（`events` 支要**排除**已在
  上下文的那些，否则花一次往返换回已有的东西）、以及"为了显得记得而每轮都查"——
  最后这条是**规则书**的事（§6 未定）。

## 3. 检索后端与 `when`

### 3.1 两个后端，**不是两个动作**

| 后端 | 语义 | 成本 | 什么时候赢 |
|---|---|---|---|
| **字面 grep** | 子串 / tags / `ts` 过滤，**精确** | 零依赖、毫秒 | "我说过『天台』吗"「上周三那次」 |
| **语义召回** | embedding + 四路合成（`compose`），**模糊** | 需本机服务（`[embed]`，1235） | "那件让我心里一沉的事" |

同一个 `query` 走两个后端再**合并去重**（词面命中优先、语义补足）。
⚠️ 今天 `recall_subgraph` 只有"二选一"（`embed_fn is None` 就整条降级）——**合并是本节点要新写的那一小块**。
⚠️ 服务不在时的行为：**降级到字面，绝不失败**（`digest_embed fn=none` 那行日志同源；今天已确认服务在跑）。

### 3.2 各支的检索方式

| 支 | 主路 | 备注 |
|---|---|---|
| `memory` | 词面（tags ∩ query / 正文 2-gram / subject 命中）+ 语义（`compose`） | 现成：`recall_subgraph` / `recommend_candidates` 的既有实现 |
| `events` | **字面**（正文子串 + `payload.reply`/`player`）+ `ts` 过滤 | **排除窗口内**（避免重复）；渲染复用 `render_events` |
| `note` | 词面 + 状态过滤（已结清/退场） | 复用 `notes.fold` / `render_item` |
| `chapters` | 标题词面 + 序 | `chapters.chapter_index` |

### 3.3 `when`（**用户 2026-09-27 裁决：相对 + 字面**）

- **解释口径 = 现实日期 / 壁钟**（她问"上周三"用的是现实日历），与 `age.parse_ts` / `date_of`
  同一真源 —— **不是**剧情时间。
- 支持面：相对（`今天 / 昨天 / 前天 / N 天前 / 最近 N 天 / 上周 / 上个月`）+ 字面（`9/20`、`9月20日`）
  ⇒ 解析成 `[start, end)` 窗口去筛 `ts`。
- **落点：`core/worldtime/`**（如 `parse_when(text) -> (start, end) | None`），
  **别写在 recall 里** —— `events` 支、将来的回放查询、digest 都用得上。
  仓库现在只有**正向**（`render_relative`），逆向是新代码。
- **失败模式**：解析不出 ⇒ **不猜**（宁缺勿错）⇒ 退回"最近的那些" + 打一行可 grep 的记账。
- 返回里**同时带时间短语**（"9/20 傍晚"）⇒ 她不必自己算"那是几天前"。
- ⚠️ **一个已知坑**：真机 event 的 `ts` **新旧混排**（旧的是朴素本地时间，新的是 `+08:00`）
  ⇒ 比较必须走 `age.parse_ts`（2026-09-27 刚在 `_random_segment` 修过同类崩溃，别再重犯）。

## 4. 结果的生命周期（**用户 2026-09-27 裁决：按本节落**）

### 4.1 一个开关管六个面

| 面 | 靠什么 | 落库 ⇒ | 不落库 ⇒ |
|---|---|---|---|
| 当轮能用 | `feedback` 插 messages 尾部 | ✓ | ✓ |
| **下一轮 / 重进** | `render_events` → `window_messages` → `_history` | ✓（**live 与 resume 同形**） | ✗ 下一轮就忘 |
| **触发 VN 的开场前缀** | `bond_start` 里 `vn._history = window_messages(…)` | ✓ **自动带上** | ✗ |
| 回放能重建"她当时想起了什么" | 事件流 | ✓ | ✗ |
| digest 会不会当成剧情 | `NON_CONTENT_TYPES` | 收录 ⇒ **不消化** | — |
| 会不会变成手机气泡 | `render_chat_events` 只认 `type=="mmt"` | 新 type ⇒ **天然不进** ✓ | — |

### 4.2 落法（四处增量）

1. **新事件类型** `type="tool"`，`subtype` = `mmt_recall` / `mmt_inspect_result`；
   `payload.result` = **给模型看的那段文本**（与当轮回灌逐字一致）。
2. **收进 `NON_CONTENT_TYPES`** ⇒ digest 不当剧情消化（否则它会把档案文本当成"她说过的话"
   写进 episode）。⚠️ 归类只改这一处（`is_content_event` 的三个消费点自动生效）。
3. **`render_events` 加一条专用分支**：**不切块（`split_reply_chunks`）、不剥括号
   （`_strip_action_brackets`）** —— 资料不是她发的消息。放在 `is_content_event` 判断**之前**。
4. **落库文本上限 = 8 行 / 400 字**（常量，可调），超出截断并标 `（完整资料本轮已用过）`。
   为什么必须截断：`window_messages` 的**单元 = `content.split("\n")` 行数** ⇒
   一段 30 行的档案会吃掉 30/120 个单元 —— **她会记得档案、却忘了刚聊过的话**。
   （钱不是问题：history 是稳定前缀，吃缓存。）

### 4.3 为什么它比"留到触发 VN 再说"更好

- 触发 VN 的交接**已经**由 `vn._history = window_messages(…)` 完成（09-05 的"断桥修复"）
  ⇒ **落库就顺手解决了 VN 交接**，不需要另接一条线。
- 不落库 = 继续欠着"**live 与 resume 同形**"这条硬纪律（今天 `inspect` 就是欠着的：
  资料只活在当轮、事件流里一个字都没有 ⇒ 重进后她"忘了自己查过"）。
- 它是**纯增量、可反悔**：新 type + 一条 render 分支 + 一处归类 + 一个截断常量。
- **默认进 VN 前缀**（保持"她刚查过"这个事实的连续性）。若判断"当面演不该背档案"，
  加一条 subtype 过滤即可砍掉（一行）。
