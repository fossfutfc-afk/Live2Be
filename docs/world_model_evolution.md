# 世界 / 存档 / 多角色 —— 模型演进史与图论建模

> 本文档记录"角色世界线"这一核心模型从萌芽到定稿的完整思想史：
> 每一版模型、它被什么现象推翻、下一版如何修补、以及它对应的现实/理论模型。
> 写作目的：不是给结论，而是给"我们怎么一步步走到这里"——推翻本身比结论更有价值。
> 阶段 5 之后是本项目讨论最深入的部分，逐阶段展开（反例 + 现实模型映射）。

---

## 一、演进脉络（讨论 → 推翻 → 新模型）

### 阶段 0 — 一个人多个 session（最早直觉）

**模型**：一个角色可以开多个 session，每个 session 是独立对话存档。

**被推翻**：角色的"成长"如何跨 session 累积？多个 session 里角色的状态互相是什么
关系？——没有定义。

---

### 阶段 1 — 平行世界（per-角色独立世界线）

**模型**：每个 session = 一条独立世界线，纯平行，一条路走到黑。brain（记忆）
per-session，每个世界线的角色有自己私有的 wiki（"遥香自信 wiki" ≠ "遥香依赖 wiki"）。

**关键原则确立**：brain 是**算法**，不是跨 session 的共享实体——每个世界线各自
用自己的 events.jsonl 调同一套算法，产出各自私有的成长。

**被推翻**（阶段 6 才被推翻，但裂缝在阶段 3 就出现）：per-角色独立世界线，意味着
角色之间没有对齐规则——这为多角色同框埋下了致命隐患。

---

### 阶段 2 — rewind 方案（讨论中的替代，被否）

**模型**：去掉平行世界，改 rewind——单时间线 + 回退时 AI 反思"该删掉哪些 wiki
讯息"（选择性遗忘）。

**被否**：语义干净（单时间线好感天然可排序），但 AI 反思删除成本高（每次回档
一次 LLM 判断删什么）+ 语义难（易误删）。定位为"高级功能"，不是基础。

---

### 阶段 3 — 好感度排序之惑

**现象**：平行世界下好感排序"怪"——不同世界线的遥香和阿露混排，好感没有可比性。

**初步结论**：排序用"最近活跃"，好感只显示不参与排序。
**推翻**：查证 BA 桃信——好感排序是**存在的选项**（参考图顶部"好感等级"下拉 +
排序按钮）。
**修正**：好感排序做成选项，per-char 聚合（取"最高好感 session"作代表值）。

---

### 阶段 4 — current_character 字段（多角色萌芽）

**问题**：要不要让 LLM 在每个动作填 `current_character`（自我认知 + 为分饰多角准备）？

**结论：不要**。单角色下是冗余 + LLM 偷懒风险（memorial 教训：可选字段必偷懒）。
多角色的正确形态是"**输入侧指定说话人**"（引擎告诉 LLM 你是谁），不是"输出侧
自声明"。同时给 prompt 加**单人模式声明**（LLM 只扮演当前角色，提他人用转述）。

---

## 阶段 5 — A/B 双方案（一次调用 vs 轮番调用）【深入】

### 5.1 问题

多角色同框时，怎么生成"多个角色都在说话"的剧情？

### 5.2 两个方案

| | A：一次调用分饰多角 | B：轮番调用 |
|---|---|---|
| 机制 | 一个 LLM 调用输出带 speaker 的段落流 | 每角色独立 LLM 调用，speaker 由引擎写 |
| prompt | 多角色人设堆一起（膨胀） | 每次只注入当前角色人设（小） |
| speaker | LLM 声明（易错） | 引擎写（调谁就是谁，零错） |
| 接话 | LLM 内部把握节奏 | `pass_to` 字段声明 + 引擎校验 |
| 防霸屏 | 无法控制 | 软提醒 / 强转（规则性） |
| 中断 | 混合输出难恢复 | 每轮原子，天然简单 |

### 5.3 反例

- **群像戏**（茶会/委员会 5 人一场戏）：B 轮番要 5 次调用、延迟 ×5、节奏碎；A 一次搞定
- **防霸屏**：B 下 LLM 可能一个角色说不停——需要引擎检测"说太多"（字数阈值）→
  软提醒（feedback"该让别人说了"）或强转（引擎强制换人）
- **身份声明**：A 下 LLM 可能把 speaker 填错（填成玩家/别的角色）——需要引擎兜底

### 5.4 现实模型映射

- **戏剧调度**：B = 舞台监督逐个喊演员上场（"轮到你了"）；A = 即兴群戏（演员们
  自己抢戏）——导演（引擎）在 B 里掌控节奏，A 里放任自流
- **多智能体系统（MAS）**：B = 集中式调度（orchestrator 指派）；A = 分布式涌现
  （agents 自主交互）——Live2Be 选"集中式（B）为主"，因为叙事需要可控性

### 5.5 结论

两者并存，统一抽象为**段落流** `[{speaker, text}]`——下游（校验/落库/记忆/中断）
共享。选择策略：cast ≤ 2-3 → B（人格清晰）；cast ≥ 3 / NPC 群像 → A（低延迟）。

## 阶段 6 — 世界线对齐（**核心矛盾被发现**）【深入】

### 6.1 反例（用户，一针见血）

> 遥香今天要和阿露处理任务；但阿露1（世界线1）生病，应该是阿露2（世界线2）有空去。

### 6.2 问题本质

per-角色独立平行世界：玩家可以**独立重开遥香而不重开阿露** → 遥香的世界线和阿露
的世界线之间**没有任何对齐规则** → 遥香线里的"阿露"无法确定是阿露的哪条线。

```
igusa_haruka/sessions/{sid1, sid2, sid3}    遥香三条线, 互不关联
rikuhachima_aru/sessions/{sid1, sid2}       阿露两条线, 互不关联
遥香线 sid2 里"阿露登场" → 是阿露 sid1 还是 sid2? —— 无解
```

### 6.3 现实模型映射：量子多世界诠释（MWI）

> Everett 多世界诠释：宇宙在每次测量/选择点**整体分叉**——不是"每个粒子各自分叉"，
> 而是"整个宇宙"共享一次分叉。各分支平行存在，decoherence 使分支间**不可通信**。

对应关系：

| MWI | Live2Be |
|---|---|
| 宇宙整体分叉（不是粒子各自分叉） | 世界整体分叉（不是角色各自分叉） |
| 分支间不可通信（decoherence） | 世界间隔离（"阿露2 不在遥香的世界"） |
| 观测者在一条分支里 | 玩家在一个世界里 |

**结论**：阶段 1 的"per-角色独立平行"等价于"每个粒子各自有平行宇宙"——物理上
不成立（宇宙是共享的）；正确模型是"**世界整体分叉**，角色世界线挂靠世界"。

### 6.4 新模型（引出阶段 7）

必须引入「世界（周目）」作顶层——角色世界线挂靠世界，同框 = 同世界对齐。

## 阶段 7 — 世界模型（DESIGN_WORLD.md）【深入】

### 7.1 模型

```
世界（周目）= 顶层存档单元
  └─ 世界里每角色【一条连续线】（惰性创建）
      同框 = 同世界角色（状态一致）
      "阿露1生病/阿露2有空" = 世界1阿露/世界2阿露——世界隔离不交叉
```

### 7.2 反例验证

- "遥香在世界1 → 只能找世界1的阿露（生病那个）"——"跨世界选阿露"**不可能**（世界隔离）
- 同框状态一致：遥香线里阿露登场 = 同世界阿露的世界线（她记得该世界的事）

### 7.3 现实模型映射：平行时空 + 周目

- **"周目"**（playthrough / NG+）：每开一个世界 = 新周目（真·平行），旧周目保留
- **隐式默认世界**：玩家日常不感知"世界"（像手机聊天不感知"我现在在哪个平行宇宙"），
  只有"开新周目/切换"才显式接触——降低 UX 复杂度

### 7.4 结论

世界是对齐单元，不是角色。玩家日常一个"当前世界"，MMT 列表 = 当前世界的角色。

## 阶段 8 — 存档快照（用户方案，取代 rewind）【深入】

### 8.1 模型

```
遥香0 --故事1(吃拉面)--> 遥香1 --故事2(看杂草)--> 遥香2
```
- **存档 = 复制 events.jsonl（快照）**——故事节点快照，继续走原线
- **回退 = 加载快照**——从快照点重走（省掉 rewind 的"按 seq 重算"）
- BA 平行时空设定背书（存档 = 平行时空分叉）

### 8.2 为什么优于 rewind

| | rewind（按 seq 截断重算） | 存档快照 |
|---|---|---|
| 回退机制 | 按 seq 累计重算好感/状态 | 复制 events.jsonl → 加载副本 |
| 粒度 | 任意 seq（语义模糊） | 显式存档点（玩家可控） |
| 世界观背书 | 无 | BA 平行时空分叉 |
| 成本 | 每次回退重算 | 存档时一次复制（廉价） |

**关键**：affection 事件在事件流里（真源）→ 快照只复制 events.jsonl 就够
（wiki/好感可重算），不复制派生文件。

### 8.3 现实模型映射：存档机制

- **游戏 save point**：存档点 = 明确的回退锚点（不是任意帧都能回退）
- **系统还原点**（Windows restore point）/ **VM 快照**：全量时点快照 vs **重放日志**
  （redo log，对应 rewind 的重算）——快照是"现成的状态"，日志是"需重放的增量"
- **BA 平行时空**：存档 = 平行时空分叉——世界观叙事背书（游戏机制与世界观统一）

### 8.4 优化：全量世界快照

存档 = 快照**整个世界**（所有活跃角色线一起复制），不检测/不挑选——
"检测剧本涉及角色"容易漏（阿露被提到算不算登场？），全量零判断、绝对自洽。

## 阶段 9 — 重新生成 vs 世界树（粒度分层）【深入】

### 9.1 现象（用户观察其他 RP）

其他 Roleplay 是"剧情不满意 → 重新生成 → 不满意的不写记忆"。

### 9.2 反例区分（两种"不满意"）

| | 微观重试 | 宏观回退 |
|---|---|---|
| 场景 | "这句台词不对，重来" | "这一整段走向不满意，回到某点重走" |
| 粒度 | 单轮 / 单场景 | 剧情节点 |
| 频率 | 高频 | 低频 |

### 9.3 关键澄清：重新生成 = 已有机制

事件流 append-only → **不落库 = 不进 digest = 不进记忆**——LLM 输出不满意 →
feedback 重试（已有）；玩家不满意 → 重发。**只要"不满意"发生在落库前，它天然
不进记忆**。

### 9.4 现实模型映射：记忆的两级

- **工作记忆 vs 长期记忆**（认知心理学）：刚说的不满意 = 工作记忆里纠正（不进长期）；
  走了很远才后悔 = 需要"回到过去"（长期记忆层面）
- **即时纠正 vs 重生/后悔**（叙事）：人类"说错话重说"是即时的，"走错人生想重来"
  是宏观的——两个层次的需求，不能混为一个机制

### 9.5 结论

世界树降为低频长期项，不是当务之急；高频的"重新生成"已经在。

## 阶段 10 — 图论建模（世界树 = 快照树）【深入】

### 10.1 形式化定义

```
世界树 T = (V, E)
  V = S ∪ W
    S = 存档点节点（携带【完整状态快照】）
    W = 世界/世界线节点（活跃叶子）
  E = 分叉边 { (s, w) : w 是从 s 继续/回退 分叉出的世界 }
```

### 10.2 关键性质：快照树（非增量树）

| | 增量树（git commit） | 快照树（世界树） |
|---|---|---|
| 节点内容 | 相对父的差异 | 完整状态快照 |
| 节点自包含 | ❌ 依赖祖先 | ✅ 自包含 |
| 删中间节点 | 子树失去基础 → 必须 rebase | 子树数据仍完整 → 零 rebase |

### 10.3 交叉节点删除的接入逻辑

```
删除 v ∈ V:
  T' = T \ {v}
  对于 v 的每个子节点 c: c 成为新根（parent = null）
  → 结果是一个【森林】

不变量: 删除任意节点后, 剩余节点的快照内容【不变】
```

三种候选接入逻辑判定：

| 接入 | 行为 | 判定 |
|---|---|---|
| 孤儿化 | 子树变独立树根 | ✅ 快照树天然支持，零数据丢失 |
| 级联删除 | 子树连带删 | ❌ 快照树不需要（数据不依赖父） |
| 上移挂靠 | 子树挂祖父 | ❌ 语义破坏（子树数据含"父之后"，时间线矛盾） |

### 10.4 现实模型映射：备份策略

- **git（增量）**：删除中间 commit = rebase（重写历史，代价大）——对应"增量树"
- **VM 快照（全量）**：删除中间快照 = 子快照仍完整（自包含）——对应"快照树"
- **推论**：世界树天然支持"删掉中间存档但保留两端世界"——增量树做不到

## 阶段 11 — 回退的记忆语义（平行时空分叉）【深入】

### 11.1 反例

回退到存档点后，阿露该不该记得"吃拉面"（回退掉的剧情）？

### 11.2 答案：区分两条线

| 阿露 | 记得吗 | 说明 |
|---|---|---|
| 当前线（回退后继续玩） | ❌ 不该记得 | 吃拉面在存档点之后，被回退抹掉 |
| 原线（保留的时空） | ✅ 记得 | 她确实吃了，记忆自洽 |

### 11.3 现实模型映射：时间旅行的两种诠释

| 诠释 | 语义 | 对应 |
|---|---|---|
| **时间倒流**（改变过去） | 回到过去改变 → 抹掉原未来 | 覆盖回退（原线消失） |
| **平行时空分叉**（回到过去 = 进入分支） | 回到过去 → 进入新分支，原线保留 | 分叉回退（原线可回放） |

**关键**：Live2Be 选**平行时空分叉**（不是时间倒流）——回退 = 分叉，不是覆盖——
每条线的角色记忆各自自洽。这规避了"祖父悖论"式的矛盾（改过去导致自相矛盾）。

### 11.4 结论

世界快照统一回退 → 当前线所有角色回到存档点时点（吃拉面"没发生"）；原线保留
（吃拉面"发生"）——两条时空各自自洽。

## 阶段 12 — 依赖交织（广播落库 + 回退粒度）【深入，最后一块】

### 12.1 反例（用户，戳中要害）

> 玩家在"遥香+阿露+sensei 共进晚餐"节点后，先去和阿露玩了几轮，回来回退遥香——
> 阿露那几轮（基于晚餐的后续）怎么办？

### 12.2 问题本质：角色线是交织的

```
遥香线: S1 ──▶ 共进晚餐(阿露登场) ──▶ ...
阿露线: ... ──▶ 阿露几轮(可能提到"上次吃面") ──▶ ...
```

回退遥香 → 晚餐在遥香线消失 → 阿露线已基于晚餐推进 → **悬空引用**（阿露记得一件
"当前遥香线里不存在"的事）。

### 12.3 第一条地基：共享事件广播落库

多角色登场的事件，在每个登场角色的线里**各自落一份视角**：

```
共进晚餐（遥香+阿露+sensei）→ 落库两份:
  遥香线: "我和老师、阿露一起吃了面"   （遥香视角）
  阿露线: "我和老师、遥香一起吃了面"   （阿露视角）
```

这样"阿露记得不记得"由**她自己的线**决定，不依赖遥香线——回退遥香只删遥香线
那份，阿露线那份仍在。

### 12.4 第二条地基：回退粒度分层

| 回退粒度 | 行为 | 阿露状态 | 适用 |
|---|---|---|---|
| 世界回退 | 全截断到某时点 | 阿露丢几轮，不记得晚餐 | 对整个走向不满意 |
| 角色回退 | 单线截断 + 他人保留 | 阿露保留几轮 + 记得晚餐 | 只对和某角色的剧情不满意 |

### 12.5 现实模型映射：共同经历与失忆

- **共同经历的分布式记忆**：现实中"一起吃面"这件事，在遥香和阿露各自的脑里
  **独立存一份**（不共享存储）——广播落库正是这个模型
- **选择性失忆**（影视常见桥段）：一个人失忆、另一个人记得共同经历——
  "阿露记得晚餐、遥香不记得"不仅自洽，还是**剧情素材**（阿露困惑"你怎么不记得
  我们吃面了"——可成为新剧情引子）
- **目击者证词的独立性**：每个参与者对共同事件有独立记忆——证词可以不同
  （各自视角），但不会"一方的记忆因另一方失忆而消失"

### 12.6 结论（修正阶段 5 的旧结论）

阶段 5 曾说"客串角色不产生独立记忆"——**被本阶段推翻**：客串在共享事件中**必须
落自己的视角记忆**，否则回退/后续引用会悬空。这是多角色系统真正的地基。

## 二、图论建模（世界树的形式化）

### 2.1 定义

```
世界树 T = (V, E)
  V = S ∪ W
    S = 存档点节点（携带【完整状态快照】）
    W = 世界/世界线节点（活跃叶子）
  E = 分叉边 { (s, w) : w 是从 s 继续/回退 分叉出的世界 }
```

### 2.2 关键性质：快照树（非增量树）

| | 增量树（git commit） | 快照树（世界树） |
|---|---|---|
| 节点内容 | 相对父的差异 | 完整状态快照（events.jsonl 全量） |
| 节点自包含 | ❌ 依赖祖先 | ✅ 自包含 |
| 删中间节点 | 子树失去基础 → 必须 rebase | 子树数据仍完整 → 零 rebase |

### 2.3 交叉节点删除的接入逻辑

```
删除 v ∈ V:
  T' = T \ {v}
  对于 v 的每个子节点 c: c 成为新根（parent = null）
  → 结果是一个【森林】

不变量: 删除任意节点后, 剩余节点的快照内容【不变】
```

三种候选接入逻辑判定（见阶段 10.3）。

### 2.4 推论

世界树天然支持"删掉中间存档但保留两端世界"——增量树做不到。为未来"整理存档"
提供理论保证。

## 三、最终模型定稿（整合全部讨论）

```
世界（周目）= 顶层对齐单元（多角色同框的时空, MWI 的"世界整体分叉"）
  └─ 角色线 = 单线连续（遥香0→1→2→…, append-only events.jsonl）
       ├─ 存档点 = 快照（复制 events.jsonl, 分叉点, 平行时空分叉）
       ├─ 共享事件 = 广播落库（每个登场角色各自视角, 分布式记忆）
       └─ 好感/记忆 = 从事件流算（per 角色线）
  └─ 回退粒度:
       世界回退（全截断, 时间倒流语义）/ 角色回退（单线 + 他人保留, 失忆桥段）

世界树 = 快照树（节点自包含）
  └─ 交叉节点删除 = 子树孤儿化（森林）, 零 rebase

微观重试（重新生成不写记忆）= 已有（append-only + 重试）, 高频
宏观回退（世界树）= 低频长期项
```

### 关键设计原则（沉淀）

1. **世界是对齐单元，不是角色**——多角色同框的时空必须共享（MWI）
2. **事件流是唯一真源，wiki 是不可逆派生**——存档**连 wiki 一起快照**（wiki 有损压缩、
   不可逆，回退靠"回滚快照"而非"重算"）; 事件流删除 = 有损回滚，对应 wiki 有损压缩
3. **共享事件广播落库**——记忆归属由"谁在场"决定（分布式记忆），不依赖主角色
4. **回退 = 分叉，不是覆盖**——原线保留，每条线记忆自洽（平行时空，规避祖父悖论）;
   角色回退在他人视角 = **失忆**（"倒退一个人的时间" ≈ "这个人忘了，别人还记得"）
5. **快照树优于增量树**——节点自包含使删除/回退零代价
6. **森林 + 关联边（虚边），而非共享节点**——角色保持树，共同世界靠"对应节点对 +
   event_id"关联（虚边不改变树结构，删除是树内操作）

## 阶段 13 — 图论精确化：森林 + 关联边（A or B → A & B）

### 13.1 问题

"共同世界事件"在图论里到底该长什么样？两种候选：

| | A：共享节点 | B：关联节点对 |
|---|---|---|
| 形态 | 一个节点被多棵树引用 | 每棵树各自一个视角节点 + event_id 关联 |
| 图类型 | 图（树交叉） | 森林 + 跨树关联边 |
| 删除 | 要处理"谁删、影响谁" | 各自删各自的（树内操作） |
| 记忆 | 共享一份 | 各自独立 |

**结论：选 B——但 A 和 B 不是"二选一"，而是统一为"A & B"**：
保留 A 的"树"结构（角色线），用 B 的"关联"表达共同世界（事件对应）——
**森林（角色树）+ 关联边（世界事件）**。

### 13.2 为什么否决 A（共享节点）

```
  A: 共享节点 —— 一个节点, 两棵树都指着它

          T_遥香               T_阿露
            │                    │
            │                    │
            └────────┬───────────┘
                     │
                     ▼
              ┌─────────────┐
              │   [晚餐 D]   │   ← 唯一的物理节点
              └─────────────┘
                     │
            ┌────────┴────────┐
            ▼                 ▼
        遥香后续           阿露后续

  删除 D 的困境:
    · 谁删? 两棵树都引用它
    · 删了之后, 遥香后续接哪? 阿露后续接哪?
    · 角色回退(只删遥香视角)根本无从下手——节点是共享的
  → 共享节点让"角色回退"退化成了"世界回退", 丢了粒度
```

### 13.3 为什么选 B（关联节点对）

```
  B: 关联节点对 —— 各自视角节点, event_id 标成"同一次晚餐"

          T_遥香（树）                T_阿露（树）
             │                          │
             ▼                          ▼
      ┌─────────────┐          ┌─────────────┐
      │ 晚餐 D·遥香视角│          │ 晚餐 D·阿露视角│
      │ "我和老师、    │          │ "我和老师、    │
      │  阿露吃面"     │          │  遥香吃面"     │
      └──────┬──────┘          └──────┬──────┘
             │        event_id=D         │
             └──────────~关联~───────────┘
             │                          │
             ▼                          ▼
         遥香后续                    阿露后续

  删除:
    · 角色回退遥香 = 删 T_遥香 的 [晚餐D·遥香] —— 树内操作, T_阿露 不动
    · 世界回退     = 两棵树各自删各自的 [晚餐D·*] —— 各自树内操作
    · 关联边随视角节点删除(视角没了, 关联自然断)
  → 每个视角节点自包含, 删除是树内局部操作, 不牵连对方树
```

### 13.4 最终形态：森林 + 关联边（A & B 的统一）

```
  ╔══════════════════════════════════════════════════════════════╗
  ║          世界 W1（一个森林 F, 共享 world_id）                  ║
  ╚══════════════════════════════════════════════════════════════╝

    T_遥香（角色树）                T_阿露（角色树）
         │                            │
     遥香0·约会                    阿露0·社团
         │                            │
         ▼                            ▼
    ┌──────────┐                ┌──────────┐
    │晚餐D·遥香│ ═══event_id══►  │晚餐D·阿露│   ← 关联边(对应节点对)
    └────┬─────┘                └────┬─────┘
         │                           │
         ▼                           ▼
     遥香2·后续                   阿露2·几轮
         │                           │
         ▼                           ▼
        ...                         ...

  关联边集合 C = { (d_遥香, d_阿露) : event_id = "晚餐D", ... }
     —— 标注"这两棵树上的视角节点 = 同一个世界事件"
     —— 森林保持(树不相交), 关联边只是"对应"关系, 非物理共享
```

### 13.5 存档与回退（森林的时点切片）

```
  存档 = 森林的时点快照（所有树各自截断打包）

  ══════════════ 存档点 S（世界时点）══════════════
    T_遥香  截断于 seq_a        T_阿露  截断于 seq_b
    （含 晚餐D·遥香 + 它之前的全部）  （含 晚餐D·阿露 + 它之前的全部）
    + 各自 wiki 快照
  ═════════════════════════════════════════════════

  回退 = 加载快照

    世界回退（全森林回滚到 S）:
      T_遥香 → seq_a    T_阿露 → seq_b     ← 一次加载, 对齐

    角色回退（只回滚 T_遥香, T_阿露 保留）:
      T_遥香 → seq_a（晚餐D·遥香 被删）
      T_阿露 → 不动（晚餐D·阿露 还在, 关联边断开但阿露记忆独立）
      → 结果: 阿露记得晚餐, 遥香不记得（失忆桥段, 自洽）
```

### 13.6 形式化定义

```
森林  F = { T_1, T_2, ..., T_n }        每角色一棵树 T_char
关联  C = { (v_i, v_j) : event_id 相同 } 跨树对应边, v_i∈T_i, v_j∈T_j

世界  = (F, C)     —— 森林 + 关联, 而非"一棵大树"或"节点共享图"

操作:
  存档(world) = 对每棵树截断快照 → 打包（含 wiki）
  回退(世界)  = 加载打包快照 → 全森林回滚
  回退(角色)  = 加载快照的单树部分 → 单树回滚 + 关联边断开(他人树不动)
  删除(节点v) = T_char 内删除 v, 子节点接父（树内, 关联边随 v 消失）

不变量:
  删除任意角色的任意节点, 其他角色的树【不变】
  （关联边断开 ≠ 对方视角节点消失 —— 分布式记忆, 各自独立）
```

### 13.7 收束：三个顿悟（把"时间回退"翻译成"现实语义"）

**顿悟 1 — 虚边（virtual edge）**

关联边本质是**虚边**：不改变树结构，只标注"这两个视角节点 = 同一次世界事件"。
删除永远是**树内操作**（各自删各自的视角节点），虚边随节点消失——
"共同世界"是**逻辑关联**，不是**物理共享**。

**顿悟 2 — 角色回退 = 他人眼中的失忆**

> 我们一直被"时间回退"搞昏了头——没意识到：**个人时间回退，这个行为，
> 在别人眼里，不就是失忆吗！**

- "倒退遥香的时间" ≠ "世界倒流"（那会让阿露的时间也倒退，不合理）
- "倒退遥香的时间" = "遥香忘了晚餐之后的事"（阿露还记得）
- 这正是现实里的**选择性失忆**——一个人失忆，其他人记得共同经历
- 逻辑因此闭环：角色回退不再是"数据操作该不该"，而是"叙事语义 = 失忆"

**顿悟 3 — 有损回滚（lossy rollback）**

"删除中间发生的一件事、保留其他事件" = **有损回滚**——删掉的不是"某个时点之后
的一切"，而是"中间一段"，前后的上下文可能因此缺一块。

这与 wiki 的**有损压缩**（digest 综合提炼、不可逆）正好对称：

```
事件流删除 = 有损回滚（删中间, 前后可能断裂）
wiki digest = 有损压缩（综合提炼, 不可精确逆向）
→ 两者都"有损", 所以 wiki 不能靠"重算"回退, 只能靠"快照回滚"
→ 这就是"wiki 必须快照"的最终依据（不是资源考量, 是数学必然）
```

**顿悟 4 — 共通删除（common delete, 未来操作）**

有了"虚边关联"，可以自然延伸出第三种删除粒度：

| 删除粒度 | 语义 |
|---|---|
| 角色回退（单树） | 一个人失忆（他人保留, 虚边断开） |
| 世界回退（全森林） | 所有人回到某时点（时间倒流语义） |
| **共通删除（关联节点对）** | 删除"某次共享事件"本身——所有相关角色的视角节点一起删（虚边是删除的依据） |

共通删除 = "这件事在世界里从没发生过"（所有人都不记得），比世界回退更精细
（不是回退到某时点，而是抹掉"某一件事"）。

### 13.8 模型的现实闭环

```
时间倒退 → 失忆（他人视角）        ← 角色回退的叙事语义
删中间事 → 有损回滚                 ← 事件流删除的代价
wiki 提炼 → 有损压缩 → 不可逆        ← wiki 回退不能靠重算（见阶段 14 的双机制）
虚边关联 → 共同世界的逻辑表达        ← 森林不揉成一棵大树的图论依据
共通删除 → 抹掉一件事（全角色）       ← 虚边赋予的第三删除粒度

→ 这个模型"几乎完美符合现实意义"：回退不是神秘的时间魔法,
  而是"失忆/有损回滚/共同记忆"这些我们日常就能理解的现实机制
```

## 阶段 14 — wiki 回退的双机制（快照回滚 + LLM 重写，复用 IDE）

### 14.1 洞察：wiki 有损回滚 → 复用 IDE 重写，复活 rewind

之前（阶段 13）结论："wiki 不可逆 → 必须快照回滚"。但这是**唯一路径**吗？

新洞察：**wiki 不删，而是让 LLM 重写**——复用 IDE 的"安全编辑结构化文件"能力，
"告诉 LLM 哪段记忆没了 → LLM 重写对应记忆"。

这**复活了阶段 2 被否的 rewind**，但消除了它的致命缺陷：

| | 阶段 2 rewind（被否） | 阶段 14 LLM 重写 |
|---|---|---|
| 触发 | 回档时 AI "反思删哪些" | 回退已**确定**删了哪段事件 |
| 范围 | 模糊（AI 自己判断）→ 易误删 | **明确**（"这段事件没了，重写对应记忆"） |
| 成本 | 每次回档一次反思 | 每次有损回退一次**定向重写**（非反思） |

阶段 2 被否的原因是"AI 反思删什么"范围模糊——现在反过来了：**删除是明确的**
（回退删了哪些事件是确定的），LLM 只做"依据明确删除、重写对应记忆"——
**误删风险消失**。

### 14.2 双机制（互补，不是二选一）

```
① 快照回滚（存档点）    = 精确回到时点, 0 LLM 成本, 确定
② LLM 重写（有损回滚）   = 删中间事件 → 复用 IDE 重写 wiki, 灵活, 1 次 LLM 调用

适用:
  回退到【存档点】   → ① 快照回滚（主路径, 确定无成本）
  删【中间某段事件】 → ② LLM 重写（无存档点也能回退, "有损回滚"的 wiki 处理）
```

### 14.3 IDE 复用的本质：executor 模式通用化

IDE 的动作（create_character/update_character/search...）是角色卡专用，但它的
**机制**是通用的"安全编辑结构化文件"——wiki 是结构化 JSON，天然适用：

```
IDE 机制（可复用）              →  wiki 重写对应
  search  → 定位（多候选+alias）  →  "在 wiki 里找到受影响的记忆条目"
  plan    → 规划改动              →  "该删/该改哪些 facts/beliefs"
  diff    → 改动预览（审批）       →  "重写前看 diff, 避免误改"
  execute → 写回                  →  "原子写回 wiki.json"
```

复用 = 把 executor 目标从"角色卡目录"扩展为"wiki 文件"（通用化），或新增
`rewrite_wiki` 动作复用同一套 plan/diff/execute 管线。

### 14.4 完整回退体系（收敛）

```
存档点回退  → 快照回滚（事件流 + wiki 一起回滚, 确定）
中间删除    → 事件流删除（有损回滚）+ wiki 复用 IDE 重写（LLM 依据删除定向重写）
世界回退    → 全森林快照回滚
角色回退    → 单树快照回滚（= 他人眼中的失忆）
共通删除    → 关联节点对一起删 + 相关角色 wiki 定向重写
```

**"wiki 不可逆"的困境彻底解开**：不是只有"快照"一条路——**快照（确定、存档点）+
重写（灵活、任意点）两条路**，重写这条路靠复用 IDE 就拿到了。
