## 3. 已裁口径（施工时照抄，别再重新推）

- **一律划掉**：三种结局（兑现/失约/被盖过）都进图、都从本子除去；`state` 字段取消，结局写在正文里
- **时间**：天粒度 · **当天算数、无宽限** · 没有期限 ⇒ 永不过期 · 只有"这一次、有明确时刻"的才写 `due`
- **跨年同日**：全日期存储与比较；**给她显示可省年份**（全项目唯一一处"印剥有意不同源"，注释写明）；料里给全日期
- **生日 / 特殊日子**：原文自带日期 ⇒ 让 LLM 写明确日期；只说"生日"这类 ⇒ **注入【日子】**由它折算；⭐ **`due` 落在过去 ⇒ 收下、不告警**（超期资格位下一段就会把它摆到 R0 眼前 ⇒ 自愈）· **不是全日期 ⇒ 当没期限** · **折算不了 ⇒ 不写 `due`（挂着，绝不猜）** · 不知道日期时 `abstract` **如实写空缺**（⛔ 不许编日期）
- ⭐ **`open` + `id` = 更正**（不新建）：补/更正 `due` · 重写那句 `abstract`（**`open` 行的 `abstract` 恒 = 那条约定在她本子上的那句**），留 `before`/`after` —— **不另加 `note/due` op**
- **`open` 只标"到本段结束时还开着的"**；`close.id` / `open.id` 闭集 ⇒ **同段闭环天然不写 note**
- **出 + 进 = 两行 = 两条记忆**（同一个 span 允许两行）
- **`span: null` 只有一种**（没有那一刻）：`abstract` 即正文，`title`/`significance` 由 R0 给
- 无区间经历：`event_seq = [interact_max]`（幂等）· **不计入 `MAX_EPISODES`** · **进 `ctx.episode_ids`**
- **不建边**；`#pinned` 打给**出生那条** episode
- **`significance` 的口径归 R1 的提示词工程**（无区间那行的值由 R0 给，两边共用一套说法，别写两套）

## 4. 守门清单（**十三条，每条先验能红**）

1. 真值表 **5 合法 + 3 拒**（省略 / `open`（`id` 空·有）/ `close` × span 有·`null` × id 有·无）
2. `close.id` / `open.id` **闭集**：拿一个料里没有的编号 ⇒ 拒
3. **同段闭环不产 note**
4. **无区间经历幂等**：同一段重跑，图上仍只有一条
5. **覆盖集合去重**：同一 span 两行 ⇒ 未认领仍 = 0
6. **`due` 非全日期 ⇒ 当没期限**（不落这个键；不告警、不丢整条）
7. **一律划掉**：三种结局跑完，本子上都不剩
8. **旧档**：真机那两条 open 没有 `due` ⇒ 永不隐式过期（⚠️ 两条已于 2026-10-05 划掉 ⇒ 这条改成"**划掉后不再出现**"）
9. **章收口后 `state`/`id` 还在**
10. **R1 的料里没有日期**（防"顺手给它也加一行"）
11. **`due` 落在过去 ⇒ 收下、不告警**（用户 2026-10-05：*"LLM 有自己的理由…下一轮就反应过来了"*）· ⛔ 引擎不替她滚到明年
12. **`open.id` 白跑一行 ⇒ 拒**（`due` 与 `abstract` 都没变）
13. ⛔ **`open.id` 不许改 `refs` / `since` / 槽**（只许 `due` · `abstract`）
