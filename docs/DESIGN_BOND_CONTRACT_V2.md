## 2. 职责分层（三写手模型收敛版）

```
主 LLM（创作）:     段数组（纯文本）——规则: 空间/时间明显跳变 → 另起一段
                    其余创作裁决: 选项文本、memorial 时刻、end（§8 未决形态）
标注层 emotion（现网）: 逐句词表键（打字机/立绘差分）——不变
标注层 place（新）:     逐句判定"此处发生空间实体变更 → 词表 id"（背景切点）
导演/引擎:        消费 place 锚点 → 句边界换背景; 非法/缺失 → 静默保持
存储/回放:        锚点键只进 payload, 不进 LLM 上下文（仿 emotion 先例, §6）
```

单源原则：选定本方案后，主 LLM 契约**不保留任何 place 字段**（避免双源）；rules/schema
中现有的 place 指令删除，替换为"换场换段"写作约定（§4）。

## 3. 换场定性判据（共享定义——rules 与标注层 prompt 镜像同一套）

用户点名："从…走进…"这类语句**需要定性**，两处 prompt 必须同一定义，否则编剧
切段与标注层判定互相空转。

### 3.1 判定：空间实体变更 = 换场（场景/背景切换）

- 说话人所处的**可命名地点实体**发生改变：教室→天台、事务所→夏莱、街道→拉面店。
- **强线索句式（正例）**——含"离开 A + 到达 B"的移动语义：
  走出/走进/回到/来到/赶往/推开…（的门）/穿过…走廊/离开…前往…/
  **从…走进…**/从…回到…/…碰头后一起去了…
- **反例（不换场）**——同一地点内部的姿态/位移/动作：
  向窗边走了两步/转身/靠近/蹲下/坐下/背靠墙/掏出手机/整理书包——仍在同一场地，
  画面不需要切换。
- 多次移动允许：一段叙事可连续"教室→走廊→天台"（两句内两次变更），标注器按句
  依次给出；常见情况每场 0~1 次。

### 3.2 边界情况（v1 定义, 防过度承诺）

| 情形 | 写作侧（主 LLM） | 标注侧（place） |
|---|---|---|
| 明显时间流逝（第二天/放学后/夜深） | **另起一段**（节拍节奏） | **keep**（v1 背景库无时间变体, 不换图） |
| 回忆/闪回/心理跳转 | 可另起段（节奏）；不要求空间语义 | **keep**（回忆场景模式留待"氛围/镜头"第三路, 登记 §8） |
| 视角变化但地点未变 | 不强制换段 | keep |
| 地点在词表外/判不准 | — | **keep**（宁缺勿错, 与现网非法 place 静默保持同语义） |

> 定性补注（给两处 prompt 的共同例句）：
> - "她**从**教室里**走进**走廊，又**推开**天台的门" → 两次变更（走廊/天台）
> - "她**从窗边转过身**，向我走来" → 同地点内动作 → 不换场

## 5. place 标注器设计（标注层第二路）

### 5.1 输入
1. 本场**句子列表**（引擎已切句, 扁平——自然段分组未在引擎侧保留, §6）；
2. 当前 place（引擎持有的上一画面地点; 无 → None/起始默认）；
3. 地点词表（closed, `_director_whitelist.json` common_scenes）；
4. 角色名（可选, 语境参考——与 emotion 标注同款传参习惯）。

### 5.2 输出与语义
- 输出 JSON 数组（text 模式, 同 emotion 风格）:
  `[{"sentence": 3, "place": "rooftop"}]` —— 空数组 = 全场无换场；
- `place` 必须 ∈ 词表且 **≠ 当前 place**（相等/词表外/句号越界 → 该项丢弃=keep）；
- 句号按引擎传入序号（1-based, 与 emotion 标注一致便于复用校验）；
- 失败/超时/输出非法 → 空数组（keep, 静默降级, 不进主 LLM 重试）。

### 5.3 llm/prompts/place_annotate.md 全文草案（待审）

```markdown
【地点标注任务】（独立标注, 判定型——不要创作, 只按证据判定）

给你: 角色当前所在地（place）与本场每句文本。判断叙事中是否发生了
**空间实体变更**（从 A 地移动到 B 地, 如 走出/走进/回到/来到/推开…的门/
穿过…走廊/从…走进…）, 变更发生的那一句标出新地点。

判据（与编剧规则同一套）:
- 换场: 可命名地点实体改变。例: 她推开天台的门 → 该句起在 天台
- 不换场: 同地点内动作（转身/走近窗边/坐下/整理东西/纯对话）
- 时间流逝（第二天/夜深）→ 不标（背景不变）
- 回忆/闪回 → 不标
- 拿不准 → 不标（宁缺勿错, 画面保持上一地点）

地点词表（只能从中选, 词表外不标）:
{lexicon}

当前 place: {current_place}（未变化请保持; 若变更句的新地点与它相同 → 也不标）

句子列表:
{sentences}

输出: 变更句数组 JSON, 无变更输出 []:
[{"sentence": 3, "place": "rooftop"}]
```

### 5.4 预算与档位
- max_tokens 真源 = task_levels 新形态 "place"（建议 256）;
- thinking: off（同 emotion——低价值判定快速失败快速兜底）;
- 调用次数: 每场至多 1 次（+ 二分重试兜底可复用 smart 模式, 见 §7）。

## 7. 双路并发实现分解（标注层）

> **并发模型澄清（2026-09-07 用户确认）**：不是"一个消费者按某顺序吃两个队列"。
> 正确形态 = **两队列 + 两消费者（lane）**：emotion lane 只吃 emotion 队列、
> place lane 只吃 place 队列，**互不等待、各自并行**；跨 lane 无顺序要求。
> 时序约束只有两条：① lane 内 FIFO（场景不重排）；② 每场景两路都完成才开 gate。

### 7.1 每场景时序（发布 → 放行）

```
t0  骨架发布（busy=False）→ 前端立即打字显示（不等待标注——现状语义不变）
t0+ 同时入两队列: Q_emo(本场景逐句情绪) + Q_place(本场景变更判定)
     W_emo 开始调用（~1-3s, thinking off）; W_place 开始调用（~0.5-2s, thinking off）
t0+ place_done → 锚点句写回 payload（place 键, 稀有）; place_ver++
     前端在锚点句位置切换背景（见 7.2 晚到规则）
t0+ emo_done  → emotion 键回填; emo_version++（现状）
gate  当且仅当本场景 两路标志都置位 → 放行推进（gate_busy 条件 = 双路未齐）
```

- 两路都廉价（256-512 token、off-thinking），并行墙钟 ≈ max(两路) 而非之和；
- place 判定句子少、通常先到——**天然赢"锚点 vs 打字位置"竞态**，无需优先级调度
  机制；若实测仍常晚到，再考虑 place lane 先行（v2 不做）。

### 7.2 锚点晚到规则（到达时锚点句已打过头）

- 锚点到达即应用（背景即时切换, 允许晚半拍——与 emotion 补切立绘同款容忍）;
- 不做"跳过/排队到下一板"的复杂化; 罕见竞态以"迟切一拍"收场, 可接受;
- 导演 current place 状态**无论何时都立即更新**（后续场景判定/下一板默认背景正确）。

### 7.3 线程/进程形态（方案 A: 双 lane）

- 每场景会话两条 daemon lane（Q_emo/W_emo、Q_place/W_place），各自 FIFO;
- 两路写同 payload **不同键**（emotion / place）→ 逐键赋值无冲突; 若嫌脏,
  place 路写副本、完成时一次合并（实现时二选一, 测试覆盖）;
- 失败隔离: emotion 失败延续兜底 / place 失败空数组 keep——互不影响;
- **引擎同步路径（CLI/测试 annotate=True）不需要线程**: 同一线程内串行调用
  （顺序实现时按最小 diff 定）。⚠️ 既有 annotate=True 测试的 ScriptedLLM 脚本数
  需 +1（多一次 place 文本调用; place 输出非法 → 空数组 keep 不崩溃, 但脚本耗尽
  会误报——P3 需审计受影响用例）。

| 件 | 改动 | 验收 |
|---|---|---|
| place_annotate.md | 见 §5.3（新文件） | 文案审 |
| 标注函数 | core/bond 新增 `annotate_places`（text 模式单次）+ smart 二分兜底（复用 emotion 的 robust 模式）; 词表/当前 place 参数 | 单测: 正例/反例/越界/词表外/相等 → keep |
