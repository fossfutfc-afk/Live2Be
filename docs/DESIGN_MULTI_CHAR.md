# 多角色（Multi-Character）设计——A/B 双方案并存（2026-08-25 落档）

> 状态: **设计定稿, 暂不实现**。当前版本只支持**单人模式**（prompt 已声明——
> LLM 始终以当前角色身份回答, 其他角色只转述不扮演）。
> 本文档为未来"多角色/NPC 群像"的实现蓝图。

## 0. 背景

单角色剧情中可能出现其他角色（核心痛点）:
- **浅层**: 遥香回忆起阿露曾说的话（阿露第一人称展示——回忆帧）
- **深层**: 阿露实际登场, 二者相遇对话
- **未来**: 多 NPC 群像（茶会/委员会/论坛群聊）

两个生成方案最终都会提供, 作为可选项; 按场景选择。

## 1. 统一抽象: 段落流（Paragraph Stream）

**两种方案都产出"带 speaker 的段落流"**——这是统一中间表示:

```
[{speaker, text}, ...]
```

- **落库/校验/记忆/中断全部基于段落流**（与生成方式无关）
- speaker 校验: `speaker ∈ cast`（引擎规则, 非法 → 静默修正 + 记录, 不 retry）
- 逐段落落库（段落级原子, 每段独立 seq）→ 中断恢复 = 段落级（已落的保留）
- digest 按 speaker 分组提炼（一次调用输出多角色记忆块）

## 2. 方案 A: 一次调用分饰多角（群像/低延迟）

**适用**: cast ≥ 3 / NPC 群像 / 论坛群聊（轮番调用延迟 ×N, A 一次搞定）。

### 痛点解法

| 痛点 | 解法 |
|---|---|
| prompt 膨胀 | **cast 摘要表**（每角色 1-2 句, 按 interperson 权重裁剪）+ 主角色完整人设; 深度了解 → `inspect_character` 动作（契约已有）按需注入 |
| 记忆/反思多次 | **一次 digest, 按 speaker 分组提炼**（导演视角输出多角色记忆块）; 客串/NPC 记忆 = 主角色视角的"她当时说了什么"; NPC 一次性 → 不持久化 |
| 中断复杂 | **段落级原子落库**——一次调用输出段落流, 引擎逐段校验落库; 中断 = 段落截断（已落的保留, 恢复从事件流重建） |
| speaker 声明易错 | LLM 声明为主 + 引擎规则兜底（非法 → 按上下文推断/主角色, 静默修正不 retry——沿用词表外情绪兜底哲学） |

## 3. 方案 B: 轮番调用（2-3 人/人格清晰）

**适用**: cast ≤ 2-3 / 交互密集（每角色独立 LLM 调用, 人格绝对清晰）。

```
loop:
  1. 引擎选当前说话人（初始 = cast 顺序 / 剧情指定）
  2. 注入【当前角色人设】(仅一人, prompt 小) + 场景上下文(对方刚说的话)
  3. 调 LLM → 当前角色段落（text + 可选 pass_to: 把话头交给谁）
  4. 引擎落事件流（speaker = 引擎填——调谁就是谁, LLM 零身份声明）
  5. 防霸屏: 该角色累计输出超阈值 → 软提醒(feedback) / 强转(引擎强制切人)
  6. pass_to ∈ cast 校验 → 切换说话人 → 回到 2
```

**关键**: speaker 由**引擎写**（输入侧指定说话人原则的落地）——LLM 不需要任何
身份字段（current_character 类字段**不需要**——说话人是引擎每次调用的参数）。

记忆: 主 session 事件流 speaker 区分 → digest 一次（主角色视角）;
客串不产生独立记忆（平行世界, 各自世界线独立）。

## 4. 方案选择策略（可配置, 未来可自动）

```
cast ≤ 2-3          → B（轮番, 人格清晰）
cast ≥ 3+ / NPC 群像 / 论坛 → A（一次调用, 低延迟）
```

## 6. 单人模式约束（当前版本, 已生效）

prompt 已声明（momotalk_rules.md / bond_story_rules.md）:
- LLM 始终以当前角色身份回答; 不扮演其他角色说话
- 其他角色出现/回忆 → 转述而非扮演（"阿露说想去那家店" 而非 "阿露: 我们去…"）
