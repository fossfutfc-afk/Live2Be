## 1. ⭐ 验收样本（用户的例子需求 —— 这是本主题的**判据**，不是修饰）

### 1.1 正例：**规律 + 她自己的态度**（要能说出来）

> "……您星期一送的**紫罗兰**，星期二送的**洋甘菊**，星期三送的**水仙花**……还有……星期日送的
> **向日葵**……向日葵的花语是**沉默的爱**吧，可是……我这样的**杂草**，第一次簇拥在花束旁，
> 第一次找到了**自己的太阳**……我不想……仅仅只是在**远处凝望**"

拆开看，由**五件东西**构成，缺一不可：

| 组成 | 说明 |
|---|---|
| ① **一串具体细节** | 紫罗兰 / 洋甘菊 / 水仙 / 向日葵 —— **每天一个具体花名**，不是"每天送我花" |
| ② **她自己发现的重复** | "每天都有"这件事是**她注意到的**（引擎没替她指出） |
| ③ **她自己的诠释** | 花语 → 沉默的爱 → 接上**自我认知**（"我这样的杂草"） |
| ④ **一个没能说出口的愿望** | "不想仅仅只是在远处凝望" —— **未来导向**、克制 |
| ⑤ **情绪浓度** | 适合在**高潮那一刻**说出口 |

### 1.2 反例（明确**不要**的那一档）

> ✗ "老师今天又送我花了" ✗ "老师很关心我"

### 1.3 第二个需求：**对玩家的觉察**（关于"他"，不是关于"我"）

> *"角色对玩家的口癖/习惯有觉察，假如玩家对角色说了 20 句**不要自卑**，那么角色就应该认识到这个规律"*

两个已核实的事实：

- 现实里多半是**同一意思的不同说法** ⇒ **字面计数抓不到**。真机实例（全是同一晚同一个意思，
  字面几乎零重叠）：
  ```
  [ 91] 没关系呢，那份报告我已经写完啦，遥香说的话我都有认真在听的
  [214] 不要自卑呀，我觉得这些事情真的很有意义呢
  [218] 这是因为遥香对我而言很重要哦~
  [226] 嗯...不被知道名字、不引人注目也没关系吧，只要有人在旁边照顾的话，一定能成长的很好的
  [279] 没关系，那我就来陪遥香吧，说不定社团的大家是去给遥香准备惊喜了呢…
  ```
- ⇒ **计数只能当排序/提示**，**"算不算同一个意思"的判断交给 LLM**。

## 2. 为什么现在的是坏的（**实测证据，别凭感觉**）

### 2.1 note 的真机事实（2026-09-27 全量实测）

| 面 | 实测 |
|---|---|
| note 条目总数 | **6 条**（2 约定 + 3 惯例 + 1 在想）—— 量不大，"坏"不在量 |
| `note/close` | **0 次**（建档至今**从没收过口**，根因见陷阱 39） |
| 写者 | 只有 haruka 有 3 条 note 操作（2 `add` + 1 `rewrite`）；**全景轮一共只跑过 1 次** |
| 全景轮计数器 | `segments_since_card = 2`（`PANORAMA_EVERY = 10`）⇒ 新章内容**要等 8 段**才进卡 |
| 每轮注入的记忆视图 | **4293 字 / 27 行**，含 **18 条 episode 全文 + 4 条 belief 全文**（带时间短语） |
| 条目质量问题 | 6 条里 **3 条有问题**：`n1` 过期未收口 · `n2` 与 `n1` 同一件事 · `n4` 与 belief `m0008` 同一件事 |
| 字面重复 | 玩家原话里 ≥3 次的短语主要是**噪声**：`，遥香`(5) `的话，`(4) `嗯..`(4) |
| ⭐ **refs 完整度** | `n2`「瓦片缝那盆苔藓」refs = `(m0014, m0015, m0017)` —— **漏了 m0016 与 m0020**（抽样，非全集） |

### 2.2 规格层面：**提示词明文禁止了我们要的那种话**

`llm/prompts/panorama.md` 原文：

> `text` 一句短语（**≤20 字**）：写具体做法 + 此刻的意思，有人味，但 **别复述事件**
> （✗「周六我们一起去了模型店」 ✓「周六模型店，有点等不及」）

⭐ 那句台词**恰恰就是"复述事件 + 超过 20 字"**（枚举四天花名，100+ 字）⇒ **契约把要的东西写成了反例**（陷阱 40）。
`on_mind` 是另一把锁：「写你自己的口吻，**一句就够**」⇒ 装不下那五句的排比。
另有明文：**「频次绝不印」**（`notes.render_note_block`）⇒ 想表达"重复"却没有数字位置。

### 2.3 管线层面：**跨段重复在整个管线里没有观察点**

| 轮次 | 视野 | 能看到"重复"吗 |
|---|---|---|
| R1 记录员 | 本段时间线 | ✗ 单段 |
| R4 收口 | 开着的约定 + **本段**新经历 | ✗ 单段，且只关心约定 |
| R2 理解者 | 新经历 + 候选（**池 = belief/experience，不含 episode**）+ 本段时间线 | ✗ 候选池里没有 episode ⇒ 看不到"第 N 次" |
| 全景轮 | 本段新 episode + **锚点/语义近邻的旧 episode** + 上次的卡 | ✅ **唯一**能看到跨段的 —— 但它看 episode（**不含玩家原话**）、产出被 ≤20 字规格压平、每 10 段才跑 |

其他缺口：`occurrences`（计数）**没实现** · `belief.tags` 只被 recall/锚点消费，**没有情境触发注入的消费者**。

### 2.4 ⭐⭐ 本轮核心：**episode 之间从来没有碰撞过**

**证据 1 —— `evolution.jsonl` 里每个认知的出生记录，`episode` 字段永远是单数**：

```
{"action":"add","episode":"m0001","id":"m0003","kind":"belief"}      ← 杂草屋调研 → "老师对我的接纳"
{"action":"add","episode":"m0002","id":"e0001","kind":"experience"}  ← 复印件约定 → "我道歉的习惯"
{"action":"add","episode":"m0005","id":"m0008","kind":"belief"}      ← 夏莱大扫除 → "我对待重要东西的方式"
{"action":"add","episode":"m0014","id":"m0018","kind":"belief"}      ← 瓦片缝苔藓 → "我对自己（杂草）的看法"
```

**4 个认知全部诞生自 1 条 episode。真机 0 次"两条 episode 合成一条认知"。**

**证据 2 —— 多条同类 episode 确实同段在场，却各挂各的**：

```
seg1  seq   1.. 31  → 2 条 [m0001, m0002]   m0001→add m0003    m0002→add e0001
seg3  seq  83..131  → 3 条 [m0005,m0006,m0007]  m0005→add m0008  m0006→update m0003  m0007→touch m0003
seg5  seq 208..261  → 4 条 [m0014..m0017]  ⭐ 四条全是「苔藓」
      m0014→add m0018    m0015→touch m0008    m0016→update m0003    m0017→update m0008
```

**四条同类事件被拆散挂到三个不同认知上，谁也没说出"苔藓"这件事本身。**
（后来是**全景轮**说出了它：`n2`「瓦片缝那盆苔藓，总想带他去看」—— 而它 refs 还是抽样的。）

**证据 3 —— 契约三行（缺口的**确切位置**）**：

| 层 | 现状 | 后果 |
|---|---|---|
| 决策行形状 | `{"episode": "m0001", "decision": …}` **单数字符串** + "每个 episode 恰好一行 + 必须覆盖全部" | **契约字面就是 1 episode : 1 决策** |
| `links` 白名单 | `link_ids = set(local_of.values())` = belief/experience/promise | **episode id 不在合法域 ⇒ 看出来了也写不出来** |
| 任务定义 | prompt 第 3 行：*"把刚刚记下的经历, **挂到她已有的稳定认知上**"* | 任务是"挂到已有认知"，不是"看这几条新经历之间有什么关系" |
| `add` 语义 | *"无同主题: 新建"* + *"必须在 note 里写一句**为什么它不是上面任何一条**"* | ⭐ **排除法兜底，不是"我发现了一类重复"** |

**证据 4 —— 真人的两个机制我们只有一个**：

| 机制 | 真人 | 我们 | 真机计数 |
|---|---|---|---|
| **印证**（新经历 × 已有结论） | "又是这样" | ✅ `touch` / `update` | **14 次** |
| **归纳**（新经历 × 新经历 ⇒ 新结论） | "他每次都这样" | ❌ **一次都没有** | **0 次** |

⇒ 而且 `add` 把"归纳"挤掉了：它的触发理由是"跟已有认知都不像" ⇒ **新认知的起点永远是一条孤立经历**，
重复只能事后靠 `touch` 慢慢长出来。**真人是反过来的：先注意到重复，才形成结论。**

## 4. ⭐ 本轮推理链（2026-09-27 夜 —— 从"note 定位对不对"问到"三层重排"）

> 用户四个问题依次是：
> ① *"如何实现我所说的两个例子，link 字段 + BFS 能做到吗，还是说 Note 的定位就错了"*
> ② *"每轮对互相 link 的 episode-group 做 digest，这是你的意思吗"* → ③ *"说错了，是指 episode-episode 边"*
> ④ *"有没有一种可能，我们思路僵化了，其实边也可以携带信息？"*
> ⑤ *"什么样的模型能够从类似/矛盾事件中撞出火花……本质就是七个类似 events 撞出来的巨大 belief"*
> ⑥ *"这是否牵扯出了 MMT 的处理形式？它是大量且离散的，而且会导致低质 link"*
> ⑦ *"还有可能就是玩家不想 VN，只想聊天……到底如何处理这种离散数据"*
> ⑧ *"你真的有办法落成代码吗"*
> 下面是逐问的结论，**每个结论都带真机证据**。

### 4.1 两个例子要的是什么

**它们不是"一条记忆"的需求，是"多条记忆之间关系"的需求。** 四件必需品，两例共用：

| # | 需求 | 例 1 送花 | 例 2 觉察玩家 | 今天 |
|---|---|---|---|---|
| ① | **可数的单位** | 7 朵花 = 7 个单位 | 20 次安慰 = 20 个 | ❌ **见 §4.5 的粒度问题** |
| ② | **同类判据** | 槽位（送 + 花 + 不同天） | 语义（同义句） | ❌ `episode↔episode` 边 **0 条** |
| ③ | **有序时间锚** | 周一…周日 | 跨度 / 频率 | ⚠️ 有原料，**取错了字段**（陷阱 42） |
| ④ | **她的态度** | 花语→杂草 | "我让他操心了" | ⚠️ `belief` 有 4 条，但**无指向规律的边** |

⭐⭐ **关键：两例的层级不同** ——
**例 1 跨段**（episode 级可见，7 天 7 条 episode ⇒ 数得出来）；
**例 2 段内**（真机：一个段 19~38 轮只切出 1~5 条 episode ⇒ **"20"这个数字在 episode 化那一刻就没了**）。
⇒ **一套机制服务不了两个例子。**

### 4.2 link + BFS 能做什么、不能做什么

**✅ 能数 —— 而且今天就能用，不需要新字段。** `render._count_of` = `supports` **入边数**：

| 看法 | 证据数 |
|---|---|
| `m0003 sensei对我的接纳与珍视` | **7** |
| `e0001 我道歉的习惯` | **5** |
| `m0008 我对待重要东西的方式` | **5** |
| `m0018 我对自己（杂草）的看法` | **3** |

⇒ 设计稿 §2.2 那句 *"`degree` 不必预存 —— 沿 supports 数一数就知道"* 是对的。

**❌ 不能发现**，四条硬理由：

| # | 理由 | 证据 |
|---|---|---|
| ① | **BFS 没有起点** | 规律节点**不存在** ⇒ link+BFS 是规律的**消费者**，不是生产者 |
| ② | **没有同类边** | `episode→episode` = **0 条**；只能靠 belief/entity 中转。entity 的**命名其实是好的**（`name` 字段：`伊草 遥香` / `老师` / `杂草屋` / `夏莱`），但「老师」那组 7/18 = **39%**，世界一长会退化到 100% |
| ③ | **每条 episode 出度恒 1**（真机 18/18） | ⇒ 一条经历**不可能同时是两个规律的证据**（`m0014` 既是"自我看法"也是"总想带他去看"的证据，图里只有前者） |
| ④ | **走到 N 个叶子 ≠ "N 次"** | 仍缺一次聚合判断 |

**❌ 「对互相 link 的 episode-group 做 digest」也不行**（用户 ② 的提法，我否掉）：

- 键 A = **belief**（沿 `supports` 入边）：`m0003` 的 7 条成员是 杂草屋调研 / 高级料理 / 送笔记 / 到家拜托 /
  兔子挂件 / 晚安两句话 / 老师说我重要 —— **组内 tags 交集 = 空**。对这样一组做 digest，**只能重新得出那条 belief 本身** ⇒ **循环**（分组键就是你要发现的东西）。
- 键 B = **entity**（沿 `about`）：方向对，但会退化（见上）。
- ⭐ **最硬的证据 —— 想找的重复全都跨组**：

| 模式 | 出现在 | 分布在几个 link-group |
|---|---|---|
| 苔藓 | m0001 m0014 m0015 m0017 | **7 个组** |
| 夏莱 | m0004 m0005 m0006 m0012 m0017 m0021 | **6 个组** |
| 笔记 | m0001 m0002 m0004 m0005 m0006 m0007 | 3 个组 |
| 兔子 | m0009 m0011 m0012 m0013 | 3 个组 |

⇒ **任何一个 link-group 内部都看不到完整的重复。这个键恰好把要找的东西切碎了。**

### 4.3 episode 之间从来没有碰撞过

见 **§2.4**（本轮核心证据，四条）。结论一句话：

> **`add` 今天是"没有地方可挂"的兜底，不是"我发现了一类重复"的产物。**
> ⇒ **新认知的起点永远是一条孤立经历 ⇒ 框架永远长不出"巨大"。**

### 4.4 ⭐ 边可以携带信息 —— 形状因此改变

**今天的边只能装 4 个字段**：

```python
@dataclass
class Edge:
    rel: str; src: str; dst: str; ts: str = ""
```

`to_dict` 只写这 4 个，`from_dict` **只读这 4 个**（盘上多余的键**静默丢弃**）；
写入口 `add_edge(rel, src, dst, *, ts="")`。⇒ **边的表达能力是零。**

⇒ 所以任何"关于关系本身"的话，我们只能**把关系升格成节点**（`belief` / `pattern` / `promise` 就是这么来的）
—— **这不是设计选择，是存储能力逼出来的。**

**边携带信息解锁的五件事**（每条带真机证据）：

| # | 解锁 | 证据 |
|---|---|---|
| 1 | ⭐ **"哪方面同类"变成一等公民** | `{rel:"same_kind", src:m0014, dst:m0015, aspect:"苔藓"}`；同一对 episode 可在**不同方面**各自成立。节点模型必须二选一 —— 真机 `subject` 被反复改写：`"我表达善意时的习惯"` → `"关于 我道歉的习惯"`；`"我对待重要东西的方式（在老师面前不再埋起来）"` → `"…（从埋起来到放到老师手上）"` |
| 2 | ⭐ **多对多天然成立** | 打破"每条 episode 出度 1"，**不需要破例** |
| 3 | **证据可自带原话与角色** | nacre 的强制锚点 / Zep 的 citation-quotation 落在边上 |
| 4 | **时效与演化不用删边** | `t_valid/t_invalid`（Zep）· `reinterpretation`/`correction_history`（HIMF） |
| 5 | ⭐ **"升华"退化成一次纯遍历** | 沿 aspect 分组 → 组内按 `event_seq → events.ts` 排序 → 取每条边的 quote/verbatim = **有序列举**（§4.2 的"有序列举"现成做法） |

⭐⭐ **最重要的一条推论：它改变了 nacre 判据的作用域。**

> nacre 说"重复出现的规律**不存在于任何单条记录中** ⇒ 检索不到 ⇒ 必须常驻或专门生成"。
> **但一旦规律写在边上，它就在边集里了** —— "所有 `aspect=苔藓` 的 `same_kind` 边"是**一次可检索的查询**。
> ⇒ **nacre 判据的作用域是"生成之前"。规律一旦被写下来（节点或边），它立刻变成可检索之物 ⇒ 不必常驻。**
> ⇒ **需要常驻的从来不是规律，而是"模型不会主动去查"的那一类**（仍生效的约定、要回避的话题）。

**两条防退化纪律**：
① **边上只放"关于这段关系本身"的信息** —— 判据：*把它挪到任一端点上会失真吗？* 会 ⇒ 必须在边上；
② **aspect 要归一化**（否则"苔藓 / 瓦片缝的苔藓 / 那盆苔藓"会把一组拆成三组）—— 与 R2 已有的 `subject` 纪律同型。

### 4.4b ⭐⭐ belief 会不会膨胀？（2026-09-27 夜实测，用户直接问的）

> 用户原话：*"一旦出现 Link 就写 belief 会导致 belief 极具膨胀，事实上，我现在不知道现在的 belief
> 数量是否合适，因为假如很多 belief 表达的仅仅是同一个意思，那就单纯在消耗上下文。"*

**实测（embedding = 本机 LM Studio，余弦）**：

| 对 | 余弦 | | 对 | 余弦 |
|---|---|---|---|---|
| `m0008` ~ `m0018` | **0.877** | | `m0003` ~ `m0008` | 0.829 |
| `e0001` ~ `m0018` | 0.869 | | `m0003` ~ `e0001` | **0.818** |
| `m0003` ~ `m0018` | 0.851 | | **无关对基线**（belief × "今天天气不错"/"考试考砸了"） | **≤0.753** |

⇒ 4 条 belief 两两相似度（0.818~0.877）**全部高于任何一条与无关句的相似度（≤0.753）** ——
它们共享一个语义核心。⚠️ **但绝对值不能当判据**（nomic 的分数带在同一主题内天然压缩，T17 删阈值就是这个原因）
⇒ 只有**相对差**（+0.07~0.12）可用，而且**同义判定最终要 LLM 在"候选摆出来"之后判**（§4.5 零件②）。

> ⚠️ **上表是 nomic 量的（2026-09-27 当天已换 Qwen3，见陷阱 38）**。换模型后同一批数据变成：
> belief × belief **[0.418, 0.628]**（带宽 0.06 → **0.21**），而且 **`e0001` 被正确分开**
> （0.418~0.462 vs 别人 0.596~0.628）—— **"它是独立轴"这个判断，nomic 下只能靠人眼看正文，
> Qwen3 下用分数就分得出来。** ⇒ **本节的结论（"同义判定要 LLM 判"）仍成立，但"分数带压缩"这条是 nomic 制造的。**

**肉眼看内容 —— 真机这 4 条其实是"1 个转变 × 3 个侧面 + 1 条独立轴"**：

| belief | subject | 判定 |
|---|---|---|

⇒ **今天的主要矛盾是 episode 全量注入，不是 belief**。**但用户的担心是前瞻性的、正确的**：
若"每个 link 就产一条 belief"，按真机 5 个相似组 / 18 条 episode 的比例，100 天 ≈ 270 条 episode ⇒ **≈75 个组**
⇒ 75 条 × ~100 字 ≈ **7500 字 ⇒ belief 会占到注入的 1/3**。那时就是真问题。

**⇒ 所以第二刀不能只是"接受 N 条"，必须同时有"准入"。三条防膨胀机制：**

| # | 机制 | 形状 |
|---|---|---|
| ① | ⭐ **`subject` 是机制、不是命名习惯** | belief 的数量**应由"维度数"约束，而不是由"事件数"**。今天 `subject` 只是 prompt 里一句纪律（*"子/超集 → 改宽已有 subject, 不新建"*），**没有机制保障**。⇒ 做成**受控小字典**（同 §4.4 的 aspect 字典）：LLM 只能选已有 subject 或**论证为什么需要新增** |
| ② | ⭐ **`add` 的准入问题要换** | 今天问的是"这条**经历**像不像已有的"（排除法）⇒ 换成三选一：**(a) 并入已有的 X**（`same_subject`：不新建，只挂新证据，必要时把 X 的正文改宽）· **(b) 新建**，并说明它是哪个已有 subject 的**更宽/更窄/并列** · **(c) 与 X 矛盾**（`contradicts`：允许并存，但必须显式标记） |
| ③ | ⭐⭐ **link 廉价、belief 昂贵 —— 两者必须解耦** | link 只是"这两条同类"，**不产生节点**；**belief 只在"组跨越质变"时生成**：成员数跨阈值（2→3）· **出现了已有 belief 没有的新侧面** · **出现了张力**。⇒ **"什么时候生成"是独立判断，不能跟"有 link 了"绑死** |

**"数量是否合适"的可测判据（给以后用）**：

1. `belief 数 ≤ subject 数`（一对一或更少）—— 真机 **4/4** ✅
2. `任意两条 belief 的余弦 − 同角色无关对基线 > 0` ⇒ 只看相对差，**且必须让 LLM 复核**
3. ⭐ **跨层重叠率**：belief 的正文有多少被 note / 其他层复述 —— 真机 **3/6 条 note 在复述 belief** ⇒
   **这条才是最实用的膨胀指标**（它同时抓"belief 之间的重复"与"层与层之间的重复"）
4. `belief 总字数 / 注入总字数` —— 真机 **13.7%**（阈值待定；若逼近 1/3 就该查）

**抽象在 `growth` 里，而且已经在注入**：

"带频率/条件词（**总 / 常常 / 就算 / 只要 / 每次**）的句子" = 抽象句。

| belief | 句子数 | 抽象句 | 抽象占比 |
|---|---|---|---|
| `m0003` | 3 | **0** | ⭐ **0%** |
| `e0001` | 4 | 1（"我开口前**常常**先道歉"） | 34% |
| `m0008` | 3 | 1（"所以我**总**把它们收进饼干盒"） | 34% |
| `m0018` | 3 | 1（"**就算**长在没人经过的那一面…"） | 20% |

**跟那句台词对照 —— 配比正好相反**（台词 ≈130 字）：

| | 台词 | 今天的 belief |
|---|---|---|
| 具体 | **7 个花名 + 星期一…星期日**（约 60 字，**46%**） | 1~2 个实例细节 |
| 抽象 | **沉默的爱 / 我这样的杂草 / 自己的太阳 / 不愿只在远处凝望**（约 70 字，**54%**） | `growth` 一句（**挂在括号里**） |
| 关系 | ⭐ **具体是为了支撑抽象** | ⭐ **抽象是引子，叙事才是主体** |

⭐⭐ **最说明问题的一条证据**：**`m0003` 有 7 条证据，却是唯一 0% 抽象的那条。**

因为每次 `update` 的输入是"上一版文本 + 一条新经历"，**唯一安全的加法就是在末尾加一个从句**：

```
老师不只愿意听杂草、要没人在意的我          ← 抽象（很短）
  ，还把我当作想一起吃饭的人                ← +1 条实例
  ，现在他还要我自信一点                    ← +1 条实例
  ，今天他收下了我做的歪兔子                ← +1 条实例
```

⇒ **实例越多，抽象被稀释得越厉害。**
⇒ ⭐ **"不够 abstract" 和 "框架锁死"（§4.5）是同一个病的两个面** —— 都是"每次只并入一条实例"的必然结果。

**还缺一整类抽象**：今天 3 条 `growth` **全是"我自己的成长轨迹"**（从 A 到 B）；
台词里的"**向日葵的花语是沉默的爱**"是另一类 —— **关于他的、关于这段关系的命题**。真机 4 条 belief 里**这一类一条都没有**。

**⇒ 三条修法（已并入三层设计）**：
1. **抽象从附加字段提升为正文主体**（`text` 第一句必须是命题）—— L2 的 prompt + 示例
2. **实例数量有上限**（由注入预算定），**不是"每次加一个"** —— 与 §4.4 的有序列举共用同一份证据指针
3. ⭐ **抽象句占比进验收判据**（今天 0~34%，**至少不该有 0% 的**）· 且 **`growth` 的起点必须能在 `text` 里找到**
   （真机 `m0003` 的 growth 说「从『我不配』」，而 **`text` 里没有"我不配"这个起点** —— 两个字段各写各的，互不约束）


### 4.5 ⭐ 怎么"撞出火花"（"七个类似 events 撞出巨大 belief"）

**先否掉一个我自己的猜测**：我以为 belief 的改写是"追加式"。量了 `evolution.jsonl` 每次正文改写（LCP = 最长公共前缀比）：

| 目标 | 来源 | 长度 | LCP 比 |
|---|---|---|---|
| m0003 | m0006 | 97 → 117 | 0.18 |
| m0008 | m0009 | 94 → 116 | 0.62 |
| **e0001** | m0010 | **40 → 83** | **0.00**（整段重写） |
| **m0003** | m0013 | **117 → 98**（**变短**） | 0.26 |
| m0003 | m0016 | 98 → 103 | 0.19 |
| m0008 | m0017 | 116 → 125 | 0.53 |
| m0018 | m0020 | 93 → 107 | 0.02 |

**它能重写，甚至会变短。** 但看**句首** —— 每一次都死守同一个框架：

```
m0003  永远以「老师不只愿意听杂草、要没人在意的我，还…」开头     （7 条证据，5 次改写）
m0008  永远以「重要的东西放在外面会被拿走、被踩坏，所以我总把它们收进饼干盒…」开头
m0018  永远以「…我也还是一株植物」开头
```

⭐ **结论：不是"追加"，是「框架锁死」。**
**每次改写的起点是"上一版文本 + 这一条新经历"**，而上一版文本已经把框架锁死在**第一条经历的解释**上
（`m0003` 的框架来自 `m0001` **一条**）⇒ 而"沉默的爱"那个框架**在第一条经历里根本不存在**。

**病名**（学术侧第 2 条）：BeliefMem 的 **self-reinforcing error** —— *"agent acts on the stored conclusion,
**never revisits alternatives**"*。**我们的 `update` 就是它的教科书实现。**

**"巨大"可以量化** —— 指标 = **这条 belief 能点名几个实例**：

| | 能点名几个 | 长度 |
|---|---|---|
| 今天最好的 belief（`m0003`，7 条证据） | **1~2 个** | 98~125 字（上限 200） |
| 那句台词 | **7 个**（紫罗兰…向日葵）+ 一个统摄诠释 | ≈130 字 |

⇒ **上限 200 字装得下那句台词；装不下的是"点名 7 个"** —— 因为输入每次只有"上一版 + 一条新的"，
输出自然只多一个。

**能撞出火花的模型 = 四个零件**（缺一不可）：

| # | 零件 | 今天 | 缺了会怎样 |
|---|---|---|---|
| ① | **并置**：整组 N 条的**原文**同时在场 | 输入 = 上一版文本 + 1 条新经历 | ⇒ 只能印证 |
| ② | **分裂维度**：拿什么把 N 条摆一起（同类 → aspect / 相冲 → tension） | 按 `subject`（同一**结论**）聚合 | ⇒ 撞不出东西 |
| ③ | **解放起点**：新产物**不以旧文本为输入** | 起点就是旧文本 ⇒ **框架锁死** | ⇒ 一次只多塞一个例子 |
| ④ | **允许推翻**：旧版**归档不删**（`evolved_from`） | `update` 直接覆盖 | ⇒ 撞错了不敢改 |

**"矛盾事件"多一条前提**：**主动检索反例**。真机 `contradicts` = **0 次**、`evolved_from` = **0 次** ——
不是模型不会写，是**从来没有任何轮次去找反例**（玩家一直给正向经历，增量里永远不出现冲突）。

⭐ **而且用户 ③ 的修正比我的"整组重写"更对**：

> *"我们要的 Link 是相似事件，碰新 belief，不一定是 update 啊，Aepisode→Abelief，碰撞后 Abelief 不一定会被改写，而是生成新东西啊"*

⇒ 三条理由：
1. **两条 belief 可以同时成立** —— "老师接纳我"（`m0003`）与"他每天送不一样的花"是**两件事**，
   重写会把它们混成一条，反而丢信息；
2. ⭐ **不改写任何东西 ⇒ 前面的全部风险消失**（不需要不可变性纪律、不需要 `occurrences` 字段、
   不需要旧版归档 —— 因为旧版根本没被动过）；
3. **天然多候选并存** = BeliefMem 给 `self-reinforcing error` 开的药方。

⇒ **"整组重读、推翻框架"降级成次路**（只在"旧框架本身错了"时用），**主路是"相似事件 ⇒ 生成新 belief"**。

#### （g）⭐⭐ 裁决：**VN 后 digest 要保留，但它从"边界定义者"降级成"提前触发者"**

| 问题 | 真机事实 |
|---|---|
| digest 的硬触发点 | 唯一 = `if completed:`（webgui `_wrapup_inner`），而 `completed` 只来自 `stage:end` ⇒ **没有 end 的章永远不进记忆** |
| 段边界能由"空闲间隔"复现吗 | **4 个真实边界能** —— 真机 ≥1h 的空闲出现在 seq 32 / 83 / 132 / 208 **之前**（间隔 **31h / 24h / 1.77h / 94h**）⇒ 对应今天的段边界 **31 / 82 / 131 / 207** ✅（另有一个 323h 的空闲在 seq 9 之前，今天**没有**对应边界 —— 那是"首次水位从 0 开始"的 artifact） |
| 剩下 2 个呢 | 边界 **261 / 270** 相隔只有 **8 分钟**（无空闲）⇒ **是章结束驱动的** |
| 纯聊天世界会怎样 | ⚠️ `session_start` **只在世界线创建时写一次**（`store.py:205`）；`session_end` **由 `bond_finish` 写** ⇒ **纯聊天世界既无 session_start 也无 session_end ⇒ 永远没有段边界**，只能靠"MMT 每 25 轮"切（**可能切在谈话中间**） |

⇒ **结论（三件）**：
1. **保留 VN 后 digest** —— 它做的是"玩家读完一章**立刻**消化"，这是空闲规则做不到的（真机 261/270 那 8 分钟）；
2. **补"空闲 ≥1h 即换段"** —— 纯聊天世界的唯一出路，且真机能复现 4 个边界；
3. **段的边界统一成一句话：「一个来访单位结束」= 空闲 ≥1h 或 章闭环（先到者）**；
   ⚠️ 顺带修一个今天的洞：现在窗口 = "水位之后全部事件" ⇒ 若 digest 在会话中途触发（25 轮规则），**窗口会切在来访中间**。
4. **四轮固有程式（R1→R4→R2→R3）不动** —— 只是它要能接受两种窗口：**有章的**（章 = 一个确定区间）与**纯聊天的**（全是 MMT）。

#### （h）⭐ 真人是怎么处理长聊天的（四个机制 → 四条落地）

| 机制（心理学成熟理论；⚠️ 本轮**未联网复核**） | 真人怎么做 | 落地 |
|---|---|---|
| **模糊痕迹理论**（Fuzzy-Trace, Reyna & Brainerd） | 逐字痕迹**衰减极快**，要旨痕迹持久，且要旨**分层** | 事件流 = 逐字（**永不删，不进图**）· **episode 不该抢逐字的活**（今天它存 `verbatim` 却只覆盖 60% 轮次） |
| **事件分割理论**（Event Segmentation, Zacks 等） | 切点在**预测失败/意外**，不是固定节拍；且**分层切分** | 切点用"意外/转折"，不用"25 轮到了" |
| **系统巩固 + 离线重放**（replay） | **离线**扫掠**多条**经历、压缩时间、提取统计规律；**多时间尺度**；高唤醒优先 | 全景轮方向对但**输入错**（读旧卡 ≠ 扫掠一组） |
| **图式同化**（schema, Tse 等 2007） | 已有图式时新实例巩固快得多，图式被**加强**而**不被重写** | ⭐ 正是用户 ③ 的修正 |

**例：真机那一晚（段 208..235）三层各写什么**

| 真人的痕迹 | 内容 | 命运 |
|---|---|---|
| 逐字 | "我差点把手机掉进花盆里了" | 几小时后忘掉，但能重建 |
| **要旨** | **一条**：*"那晚她在给苔藓换土；我说了两次『你这样很好』；最后她把杂草屋的位置给了我"* | 持久 |
| **标志性** | *"她第一次主动让我去她的秘密基地"* | 高唤醒 ⇒ **单独存**（significance 0.85+） |
| **图式**（跨会话） | *"她习惯先道歉"*（**第 16 次**了）· *"老师说的话她会信"* | 被**加强**一次，**不被重写** |

⭐ **「道歉」的轮级证据**：真机 `对不起/抱歉/不好意思` 轮级命中 = **16 / 157**，
而 `e0001`「我开口前**常常**先道歉」今天挂的 episode 级证据 = **5 条**
⇒ **16 次被压成 5 条**，而"常常"那个词没有数字支撑，因为**数不出来**。

### 4.7 ⭐⭐ digest 重排：**按「视野」分三层**（不是按「轮」）

> 用户 2026-09-27：*"digest 有些膨胀了，具体说说几层到底要干什么"* —— 同意，而且我上一轮
> 还想加第 5 轮（R5），那是**继续膨胀**。这一节是重排后的形状（用户已认可："有道理，写文档吧"）。

**膨胀的根源：今天是「按轮分层」，每一轮都什么都干一点** ⇒ 每轮的输入都要塞很多东西，
而且**五处都在"隔着一层"干活**：

| 今天的轮 | 视野 | 它实际能做 / 不能做 |
|---|---|---|
| R1 | 本段 | 想切跨段的事件，但只有本段 ⇒ **切得烂**（号码袋，40% 无人认领） |
| R4 | 本段 + 约定名单 | 收口约定（本职，没问题） |
| R2 | 本段 + 候选（**只有 belief**） | 想归纳，但**候选池不含 episode** ⇒ **做不了归纳** |
| R3 | 本段新节点 | 归属（本职，没问题） |
| 全景轮 | 跨段 | **唯一**看得到跨段 ⇒ 但产出被 ≤20 字规格压死（§2.2） |

⇒ **修法不是再加一轮，是按视野重排。**

#### 三层（按视野切）

| 层 | 视野 | 频率 | 干什么 | LLM |
|---|---|---|---|---|
| **L1 本段** | 这一次来访 | **必跑** | ① **episode 抽象**（区间切分）· ④ **note 记账**（约定 + 心境） | 1 次同步 |
| **L2 跨段** | N 条同类单位 | 有新 episode 就跑；**有候选才做真活** | ① **belief 抽象**（分群 → 新 belief）· ② **关系连接**（supports / contradicts / evolved_from / touch / update）· ③ **归属 hint** | 1 次同步 |
| **L3 实体** | 某个 entity 的**全部** mention | **异步** | ③ **动态人设基线**（每个 entity 一份"现在是什么样"）—— **派生缓存、不进事务** | 1 次异步 |

**账：今天的 `4 轮 + 1 旁路` → 提案的 `2 次同步 + 1 次异步`。**
⭐ **R5 消掉了**（分群与生成本来就是同一次调用：给候选 → 输出"群 + 这个群的 belief"，成员原文已在手上）；
⭐ **全景轮退役**（`habits` → L2 的 belief，`on_mind` → L1）。

#### ①–④ 四件事的落点（用户提的四件事）

| 要的 | 落在 | 为什么是这一层 |
|---|---|---|
| **① episode 与 belief 抽象** | episode → **L1** · belief → **L2** | 两者**视野不同**：episode 只要本段（引擎已知边界），belief 必须跨段（N 条同类）。⚠️ **今天把它们挤在同一次调用里，就是膨胀的根源之一** |
| **② belief 与临近 episode 的关系连接** | **L2** | 所有关系连接都要"跨段视野"（要看到已有 belief）⇒ 一律归 L2。⭐ **L1 不碰图**，只产 episode 本体 + note |
| **③ entity 解析 → 动态人设基线** | 归属 → **L2**（`about_hint`）· 摘要 → **L3** | 归属是"这条关于谁"（**随生成一起判最省**）；摘要是"这个人现在是什么样"（要**全部** mention，异步） |
| **④ note 作为 LLM 的记账本** | **L1** | 约定是"当场说定的"、心境是"此刻" —— **本段视野就够**，不需要跨段 |

⚠️ **`habits` 槽删掉**：它是"规律"的劣质替身 ⇒ 归 L2 的 belief。note 只留 **`promise` + `on_mind`**。

#### L1 契约（本段，**进事务**）

```json
{
  "episodes": [{"span": [213, 223], "text": "…", "title": "…",
                "verbatim_seq": [220, 221], "significance": 0.8, "items": ["果酱瓶"]}],
  "promise": [{"action": "add", "text": "…", "refs": ["m0014"], "due": ""},
              {"action": "close", "id": "n1", "state": "kept", "afterwards": "…"}],
  "on_mind": "我给瓦片留了缝让它见光——也想给自己留一道"
}
```

- ⭐ **区间化**：`span: [from, to]` 替代"覆盖哪几个 seq 号"；引擎**展开** + **强制不重叠**（先到先得）
- ⭐ **`unclaimed` 由引擎填**（区间化后剩下的号）⇒ 归闲聊，**不落节点** ⇒ **40% 丢失结构性消失**
- ⭐ **L1 的产出里不许出现 `add`/`update`**（那是 L2 的活）⇒ **L1 不碰图**
- `promise` 与 `on_mind` 合并进这一次调用（同视野，省一次调用）

#### L2 契约（跨段，**进事务**）

```json
{
  "groups": [{"aspect": "苔藓",
              "members": ["m0014", "m0015", "m0016", "m0017", "m0020"],
              "conf": 0.9,
              "belief": {"subject": "被看见",
                         "text": "…",                          // 抽象命题在前，例证在后
                         "growth": "从「没人看」到「有人会来看我」",
                         "about_hint": ["老师", "伊草遥香"],     // ← 两条边：他 + 我
                         "conf": 0.85}}],
  "rejected": [{"members": ["m0009", "m0012"], "why": "只是同一个地点"}],
  "decisions": [{"episode": "m0021", "decision": "touch", "target": "u0002"}],
  "links": [{"from": "u0009", "rel": "contradicts", "to": "u0005"}]
}
```

- ⭐ **`belief` 字段可缺** —— 引擎的 promotion 判据不过（成员 <3 / 全在同段）就**只落边、不落节点**。
  这就是"**link 廉价、belief 昂贵**"的解耦点
- ⭐ **`add` 只在这里**（L1 没有，L2 的 `decisions` 里也不许有 `add` —— 新建只能走 `groups[].belief`）
  ⇒ **"框架锁死"在契约上不可能发生**
- **两条候选通道**：

  | 通道 | 单位 | 产出 | 谁做 |
  |---|---|---|---|
  | **episode 通道**（锚点 tags/entity + 语义近邻） | episode | 事件同类群（例 1 送花） | 复用 `panorama.py` 的锚点池 + 加语义通道 |
  | ⭐ **轮级通道**（玩家回合的语义近邻，读 `events.jsonl` 的 `payload.player`） | **seq 区间** | 他的口癖 / 习惯群（例 2） | **确定性**（embed + 余弦，服务已在跑）⇒ **不增加 LLM 调用** |

  ⇒ ⭐ **证据指针因此有两种：episode id 或 seq 区间** —— **两个例子落进同一个模型**
- **promotion 判据（四条，全部可测）**：成员数 ≥3 · 跨 ≥2 个段 · 与已有 belief 不重复（能并入就不新建）·
  有 `contradicts` 的**优先级更高**（不是更低，真机 0 次 ⇒ 这条支路从未触发过）

#### L3 契约（异步，**不进事务**）

```
真源 = about 边（谁 mention 了谁）
缓存 = soul/entity_summary.json         ← 派生，删掉可重建，失败零损失
内容 = {x0001: {"name": "老师", "summary": "…", "state": [...], "up_to_seq": 314}}
```

- ⭐ **不进事务 = 不膨胀**（同 `notes.json` 的模式：先真源后缓存、可随时重建）
- 它的身份 = **动态人设基线**：静态人设 = `config/characters/*/personality.yml`，动态 = 这份
- 外部对应：Hindsight 的 `S`（**preference-neutral entity summary**）—— **中立的观察，不带她的态度**

#### 今天 → 提案（对照）

| 今天 | 提案 | 变化 |
|---|---|---|
| R1 切 episode（号码袋） | **L1** 区间切分 | 形状修好 |
| R4 收口约定 | **L1** 的 `promise` 段 | **合并**（同视野） |
| R2 组织认知（单条 → touch/update/add） | **L2** 的 `groups` + `decisions` | 升级：`add` → "N 条 → 新 belief" |
| R3 归属 + entity 载荷 | **L2** 的 `about_hint`（归属）· **L3** 摘要 | **拆开**：归属随生成判，摘要异步 |
| 全景轮（写卡） | —— | ⭐ **退役** |
| （上一轮草案里的 R5） | —— | ⭐ **消掉** |

#### ⭐ 外部依据（本轮联网查的，带出处）

- ⭐⭐ **这问题在文献里有名字：consolidation gap** —— *"the step between **'I observed X three times'**
  and **'the general rule is Y'**"*。那份调研的结论：**技术成熟、判据不成熟** ——
  MemoryBank / Generative Agents / Memory OS / AWS AgentCore **都能抽象**，但 promotion 信号全是**启发式**
  （importance 累积 / 遗忘曲线强度 / **heat score** / 目标完成 + confidence）；⚠️
  **没有任何一篇验证过"N 条独立印证就提升"这类规则**，也**没有 benchmark 测 promotion precision**
  ⇒ **我们的 promotion 判据必须真机标定，不能凭感觉。**
- ⭐⭐ **Hindsight（arXiv 2512.12818, 2025-12-14）的四网络**：
  `W` world 事实 / `B` experience（她自己的经历）/ **`S` observation（中立实体摘要）** /
  **`O` opinion（`text + confidence + time`，随证据演化）**。它的核心断言：多数记忆栈把
  **evidence / inference / summary 混为一谈** ⇒ 长程漂移、组织混乱、更新不可追溯。
  ⇒ ⭐ **我们的 `belief` 正是把 `S` 和 `O` 混在一条里** —— 真机 `m0003` 前半是"关于老师的**观察**"、
  后半是"她的**态度**"，而这两半的要求**相反**（观察要具体、态度要抽象）⇒ **今天妥协的是态度**
  （只剩 `growth` 那 30 字，见 §4.4c）。**这就是"不够 abstract"的机制原因。**
- Hindsight 的边是三类：temporal（按时间距离**指数衰减**）/ semantic（**余弦过阈**）/ **causal（LLM 抽，加权最高）**
  ⇒ 我们只要前两类 + `aspect`；causal 可以后面再加。
- ⚠️ Hindsight 的数字（LongMemEval 83.6 vs full-context 39.0）**依赖 LLM-as-judge**，
  原作者自列"judge 依赖 / 基线可比性 / 成本未交代"三条 caveat ⇒ **只借结构，不当结论**。
- 另一条可利用的：**AWS AgentCore 的两段式** = `turns → episodes`（**目标完成时**切）→ `跨 episode 反思`
  ⇒ 产出 **hints + 适用条件 + confidence 0.1~1.0**。与我们 L1 → L2 同形；"**hint + 适用条件**"这个形状值得抄。

**逐条回答"L1 能解决什么"**：

| 疑虑 | 能否 | 怎么解决 |
|---|---|---|
| 无意义闲聊无足轻重 | ✅ | **不写**。只留在 `events.jsonl`，需要时现查 |
| 有意义的谈心独占 episode | ✅ | 区间不许重叠 ⇒ **独占由引擎保证**，不靠 LLM 自觉 |
| **引子要被正确处理** | ✅ | 引子只有两个位置：谈心区间内（起点提前 ⇒ 进 episode 正文）· 区间之前（归入闲聊 ⇒ 留在原文）。**没有"消失"这个选项**（覆盖率被强制） |
| VN 前的 MMT / VN 后的 MMT | ✅ | 都是闲聊区间；VN 本身产出高 significance 的 episode（§4.6f） |
| 长时间贪心 MMT | ⚠️ **一半** | 区间化保证"单次会话内切分正确"；**跨天重复要 L2 的轮级通道** |
| 例 1 / 例 2 | ⚠️ **各一半** | L1 保"材料不丢"；"发现重复 + 生成新 belief"要 L2 |
| 复杂度能不能落成代码 | ✅ | 见上表 |

**L1 的验收判据**（全部可测，**不需要真机**）：
- 区间展开 = 该区间内全部内容 seq
- 重叠区间 → 先到先得 + 告警，不丢内容
- **覆盖率 100%**：`∪episodes.event_seq ∪ unclaimed == seq_set`
- 旧档（只有 `event_seq` 没有 `span`）照旧读得进（向后兼容）
- 真机探针：重跑一次 digest，**密度应为 1.0 / 交错数应为 0 / 覆盖率应为 100%**

#### L1**不解决**什么（诚实）

1. **不解决跨天重复**（要 L2 的轮级通道）；
2. **不解决"生成新 belief"**（要 L2）；
3. **不解决"不够 abstract"**（要 L2 的 `growth`↔`text` 约束 + L3 的观察/态度分离）。

#### L2 的落地细节（改动面比 L1 大，**契约级**）

⭐ **为什么群不需要聚类算法**：**群的身份 = `aspect` 的值，不是连通性** ⇒ `groups_of()` 就是 `group_by(aspect)`。
边只需**链式 N−1 条**（7 个成员 6 条边，不是 21 条）—— 因为组的定义是"共享同一个 aspect"，不是"两两相连"。
⇒ **无监督聚类只在"提候选"那半步有用；分群定案必须 LLM**（真机证据：同角色 belief 两两余弦 0.818~0.877
vs 无关基线 ≤0.753 ⇒ 分数带压缩、硬阈值不可分；且同一条 episode 要**同时在多个 aspect 里**）。
