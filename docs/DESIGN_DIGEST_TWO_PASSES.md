## 2. 为什么这么拆（拆分的**真理由**，别自己另编一个）

> **"对一群经历作总结"与"产出一条 belief"本质是同一件事** ——
> 都是「**从证据里归纳出一句结论**」，差别只是证据是**一条经历**还是**一群经历**。
> ⇒ 所以它们**该在同一趟**（写正文的那一趟）；**关系判断在另一趟**。

⭐ **代码里就留着这次拆分的证据**：`ROUNDS` 表里 `group` 轮的 step 名写着
**「⑤ 分群（L2-a）」** —— 9/27 那次拆分**落了 L2-a 这一半**（分群）；
**没落的那一半（关系轮）= 本文**。

## 3. 两趟的分工

### ⭐⭐ 判据（2026-10-07 用户认可）: **谁手里有两端，谁判这条边。一条边绝不判两遍。**

⇒ 边**不按"关系 vs 正文"分**，也不按"一条 vs 一群"分，而是按 **这条边的两端在哪一趟手里** 分。

| 边 | 两端 | 归谁 |
|---|---|---|
| `supports`（新经历 → **现有**看法）| 已有 × 已有 | **L1** |
| `akin` / `contradicts`（新经历 ↔ **现有**经历）| 已有 × 已有 | **L1** |
| `about`（→ entity）| 已有 × 已有 | **L1** |
| **`supports`（新经历 / 现有经历 → 新看法）** | **新** × 已有 | **L2** |
| **`evolved_from`（新看法 → 旧看法）** | **新** × 已有 | **L2** |
| **`contradicts`（新看法 ↔ 旧看法）** | **新** × 已有 | **L2** |
| **`supports`（新看法 ↔ 旧看法，"看法撑看法"）** | **新** × 已有 | **L2** |
| **`member_of`（经历 → 新经验）** | **新** × 已有 | **L2** |

⭐ 这条判据顺手解释了两件事：
1. **`akin` / `contradicts`（经历↔经历）为什么在 L1** —— 两端都是已有经历，L1 手里有 ✓
2. **"该不该长出一条看法"为什么归 L1** —— 那是**经历侧的判断**（"这条经历有没有值得长出来的话"），
   而 L1 手里正好有这条经历 ✓（⇒ §8 由此收敛）

### 两趟各是什么

| | **L1（第一趟）** | **L2（第二趟）** |
|---|---|---|
| 一句话 | **已有成分之间是什么关系** | **造新认知，并把它接上图** |
| 手里 | 本段每条新经历 + 时间线 + **现有认知 / 现有经历**（候选由引擎摆好）| **它刚造的东西** + 现有认知 / 现有经历 + L1 标出的证据 |
| 她说的词 | `supports`（**佐证**）· `akin`（**同类**）· `contradicts`（**矛盾链**）· `about`（关于某对象）· ⭐ **标记**（"这条经历该长出一条看法" / "该更新那条旧看法"）| `belief`（**造看法** —— 证据一条或一群**是同一件事**）· `evolved_from`（**进化**）· `experience`（**起类名 + 写沉淀**）· **+ 它自己落的那些边** |
| 产出 | **边 + 标记**（零正文）| **节点（正文）+ 它周围的边**（边在造的时候一起落，§5）|
| 不碰 | 正文 | 已有成分之间的关系（L1 已判过）|

⚠️ **L1 的标记只打标记** —— 不写正文、**也不落边**（那条 `evolved_from` 要等 L2 把新看法造出来才成立）。

### ⛔ 被否掉的替代切法（别拾回来）

> ❌ **"关系全给 L1，L1 一个字不写"** —— 那是**让 LLM 想了一遍却只做一半**，
> 然后 L2 **再想一遍**（同一件事判两遍）。用户原话：*"全然交给 R2-1 但不写，
> 反而是让 LLM 想了但是只做一半，然后 R2-2 再想一遍。"*

## 4. 词汇表（键 = 关系名 或 节点 kind）

⭐ **一行的"动作"不用 `decision` 这种判别字段 —— 键本身就是动作**：

```
{"episode": "m0001", "supports": "u0002"}                    // L1 连边（佐证）
{"episode": "m0003", "akin": "m0001", "on": "苔藓"}          // L1 连边（同类，轴必填）
{"episode": "m0007", "evolve": "u0002"}                      // L1 打标记（不写正文）
{"belief": {…}, "evidence": ["m0007", "m0011"]}              // L2 造看法（出生自带证据边）
```

**两条形状规则**：

1. ⭐ **值是字符串 = 引用一个已有节点；值是对象 = 造一个新节点**
2. **键的域 = 图上真实存在的名字**：`graph.RELS`（6 条）+ `nodes.KINDS`（5 种）= **11 个键**，
   ⭐ **两个真源、零第三处维护**（加一个 kind / rel，词汇表自动多一键）。

### 三档：谁定 rel（抄 `graph.classify_pair` 的原文判据）

| 档 | kind 对 | 结论 | 她要表态吗 |
|---|---|---|---|
| **① 唯一** | `episode → belief/experience` = `supports`；`对方 → entity` = `about` | 引擎能定 | 可以不说 |
| **② 多义** | `belief ↔ belief`：`supports`（看法撑看法）/ `contradicts` / `evolved_from` | 引擎**不猜** | ⭐ 必须说 |
| **③ 故意不判** | ⭐ `episode ↔ episode` | 引擎**不猜** | ⭐ 必须说 —— "两条经历相连"有**两种意思**：**时间上接着**（⛔ 不写边）与 **`akin` 同类** |

### 三个格 × 三型（**这张表自己就是完备性检查：缺一格 = 缺一条关系**）

| 格 | 同类 / 支撑 | 对立 | 时序 / 演化 |
|---|---|---|---|
| **episode → belief** | **佐证**（`supports`）| — | — |
| **episode ↔ episode** | **关联**：`akin`（⇒ 产群）| `contradicts`（⇒ 矛盾链）| `continues`（⇒ 加强召回）|
| **belief ↔ belief** | `supports`（看法撑看法）| `contradicts` | **进化**：`evolved_from` |

⚠️ 两处措辞纪律：

- **`belief ↔ belief` 那一格整体不能叫"进化"** —— 同格里有三种，"进化"只是**时序那一型**（整格叫【认知之间】）。
- **`continues` 与另外两个不同族**：`akin` / `contradicts` 是**语义判断**（要她表态）；
  `continues` 的判据是**事实**（区间相接 / 交叠、中间没插进另一件事）⇒ ⭐ **由引擎落**（或先只记账），
  **不进她的判断格**。

## 5. 连接问题：**边在造的时候一起落**（2026-10-07 用户原话）

> *"还是说 R2-1 打标记，R2-2 的 belief 出生自带 episode/group"*

⭐ 这就是"跨轮连不上"的答案：**边不是事后补的，是 L2 造节点时一起落的。**

- L1 打标记（`evolve` / "这一群该出一条看法"）⇒ L2 造节点时**出生自带**证据边（`supports` / `member_of`）✓
- ⚠️ 唯一要放开的限制：`links` 那条「**两端都不能是本轮新建的条目**」——
  L2 内部要落"**新看法 → 旧看法**"的 `evolved_from`（引擎当场知道新节点的本地 id）✓
- ⛔ **不需要**任何"跨轮补边"机制（今天的 `group` 轮连 R1 的 episode 就是日常操作）。

## 6. `topics` 轴（**上限 3**，2026-10-07 用户裁决）

- **写者**：R1（`record`）。逐字段表里长出一格：
  `"topics": ["苔藓", "生日"]` —— 这条经历**关于什么**，1~3 个**具体的东西**（人 / 地方 / 物件 / 事）；
  ⛔ **不写泛词**（"老师""日常""心情"）；写不出 ⇒ 空数组合法。
- **`akin` 必填 `on`**，且 **`on` ∈ 两端 `topics` 的交集**（**形状校验**，写边那一刻挡住 ——
  这就是"链式膨胀"的事先解法：传递只在同值内）。
- **引擎按交集切分量**（只做集合运算，**不推断语义**）—— 分量是 L2 的候选块。

## 8. ✅ 已定：**"该不该出一条看法"归 L1（标记），L2 只写**（2026-10-07）

两种证据规模（**一条经历** / **一群经历**）都该能长出看法 —— 这一点早定
（用户 2026-10-07：*"单条 episode 出 belief 应该挺正常的，本质 abstract"*）。
**由谁说**，现在由 §3 那条判据定下来：**乙**。

| | 甲：全在 L2 | ⭐ **乙：L1 标"该长"，L2 只写** | 丙：两处都能标 |
|---|---|---|---|
| 谁判"该长" | L2 自己看证据 | **L1** | 两处 |
| 为什么不行 / 行 | ⚠️ **有具体缺口**：L2 的输入是引擎按 `topics` 交集切的分量 ⇒ **没有交集、不跟任何东西同类的孤立经历进不了它的视野** —— 而"单条长出看法"最需要它的场景**恰恰是孤立经历**（真机 18 条里大多数不相似）⇒ **系统性漏长** | ✅ 那是**经历侧的判断**，L1 手里正好有这条经历；且与"佐证/关联"**同一批注意力**（都在看这条经历）⇒ 不想两遍 | ⚠️ 两套判据并存 ⇒ **同一件事容易判两遍**，且可能重复长 |

⭐ **判据与 §3 同一条**：**谁手里有两端，谁判** —— "该不该长"的两端是
「**这条经历**」与「**它可能长出的那句话**」，而经历在 **L1** 手里。
L2 拿到的是**已经决定要长**的证据包 ⇒ 它只回答"**怎么把它说成一句**"。

⚠️ 早年 L2 那版的 `ignite` / `covered` / `gap`（*"旧看法覆盖得了这一群吗 / 缺什么"*）
**仍然可以回来，但它的位置变了**：它不再是"要不要新建"的闸（那个由 L1 的标记说了），
而是 **L2 写正文时的一个参考**（"旧的那条说了多少、还差什么"）⇒ 用不用它，是 L2 内部的措辞问题。
