# digest 两趟的**动作词汇表**（DIGEST TWO PASSES）

> 建立 2026-10-07。**它是什么**：`DESIGN_MEMORY_MODES.md` 是**语义地基**（四种模式 + 切开两趟的
> 判据）；本文是**形状规格** —— 那两趟各自要 LLM 说什么、引擎怎么落地。
> 地基 = `DESIGN_SEGMENT.md`（段）· `DESIGN_SPLIT_AND_AXES.md`（切片与两条轴）。

---

## 1. 一个封装：**键 = 关系名 或 节点 kind**

⭐ 一行的"动作"**不用** `decision` 这种判别字段 —— **键本身就是动作**：

```
{"episode": "m0001", "supports": "u0002"}                   // 连边（佐证）
{"episode": "m0009", "belief": {"subject": …, "text": …}}   // 造物（抽象）
{"episode": "m0003", "akin": "m0001", "on": "苔藓"}         // 连边（同类，轴必填）
{"belief": "u0007", "evolved_from": "u0002"}                // 连边（进化）
```

**两条形状规则**：

1. ⭐ **值是字符串 = 引用一个已有节点；值是对象 = 造一个新节点**
   （没有它，`{"belief": …}` 分不出"引用已有看法"还是"造一条新的"）。
2. **键的域 = 图上真实存在的名字**，只有两类：`graph.RELS`（6 条）与 `nodes.KINDS`（5 种）。

### 词汇表（**11 个键**，两个真源，**零第三处维护**）

| 键 | 真源 | 含义 | 值 |
|---|---|---|---|
| `supports` | `REL_SUPPORTS` | **佐证**（经历 → 认知；也用于看法 → 看法）| id |
| `akin` | `REL_AKIN` | **同类**（对称）| id **+ `on`** |
| `contradicts` | `REL_CONTRADICTS` | **对立**（对称）| id |
| `evolved_from` | `REL_EVOLVED_FROM` | **进化**（新 → 旧）| id |
| `member_of` | `REL_MEMBER_OF` | **归类**（成员 → 类）| id |
| `about` | `REL_ABOUT` | **关于某对象**（→ entity）| id |
| `episode` | `nodes.KINDS` | 造一条经历 | 对象 |
| `experience` | 同上 | 造一个类（含"并类"：见 §5）| 对象 |
| `belief` | 同上 | 造一条看法 | 对象 |
| `entity` | 同上 | 造一个对象 | 对象 |
| `profile` | 同上 | 画像那一条 | 对象 |

⇒ 以后加一个新 kind / 新 rel，**词汇表自动多一个键**（契约从真源渲染，不手写）。

### 三档：谁定 rel（`core/brain/graph.py::classify_pair` 的原文判据）

| 档 | kind 对 | 结论 | 她要不要说 rel |
|---|---|---|---|
| **① 唯一** | `episode → belief/experience` = `supports`；`对方 → entity` = `about` | 引擎能定 | 可以不说（说了也对）|
| **② 多义** | `belief ↔ belief`：`supports`（看法撑看法）/ `contradicts` / `evolved_from` —— **三种** | 引擎**不猜** | ⭐ **必须说**（`evolved_from` 还要靠键的方向说"谁盖谁"）|
| **③ 故意不判** | ⭐ `episode ↔ episode` | 引擎**不猜** | ⭐ **必须说** —— 因为"两条经历相连"有**两种意思**：**时间上接着**（⛔ 不写边，时间线自己会说）与 **`akin` 同类** |

⚠️ **纪律**：引擎只在**有唯一答案**的地方替她说。`classify_pair` 原话 ——
*"猜错方向比不判更贵"*（把 `belief↔belief` 猜成 `evolved_from` 会让认知演化链倒着长）。

## 2. 造物动作 ↔ kind：**恒等映射**（这才是"decision 与 kind 结合"）

| 旧形状 | 新形状 | 说明 |
|---|---|---|
| `{"decision": "add", "kind": "belief", …}` | `{"episode": …, "belief": {…}}` | ⭐ 旧形状里 `kind` **恒为 `belief`**（契约自己写着"只有 belief"）⇒ 一个恒定值占一格 ⇒ **合并后只剩 `belief` 一个词** |
| `{"decision": "touch", "target": "u0002"}` | `{"episode": …, "supports": "u0002"}` | 印证 = `supports` 边，正文不动 |
| `{"decision": "update", "target": …, "patch": …}` | **拆解**（见下） | ⛔ `update` 这个词退出词汇表 |

**`update` 的三个去向**：

| 原用途 | 新落法 |
|---|---|
| 并入新例子（只多一条证据）| ⇒ **`supports`**（只加边，正文**不动**）|
| 新角度 / 深化（看法该更宽了）| ⇒ ⭐ **造一条新看法**（`belief`）+ **`evolved_from`** 指向旧的；**旧的原样留着**（它没说错，只是窄）|
| 事实性修正（她写错了）| ⇒ 同上（新版本 + `evolved_from`）|

⇒ **"巨大的 belief"不靠改写旧的，靠新生成一条。**

## 3. ⭐ 单条经历可以 abstract —— 代价由**进化**对冲（2026-10-07 用户裁决）

> 用户原话：*"单条 episode 出 belief 应该挺正常的，本质 abstract。"*

⇒ **不采用**早年 L1/L2 那版的 `ignite`（"新建只能是归纳的产物、要 ≥2 条证据"）。
⇒ 但"框架锁死"（第一条经历就下结论、之后再不更新）**必须有人接住** —— 接它的是 **`evolved_from`（进化）**：

> **允许单条下结论 ⇔ 必须让旧结论能被后来的经历盖掉**（新版落地 + 旧版**归档不删**）。

⇒ 这也正是"进化"住在**第二趟**（成群那一侧）的理由：判"这条新看法把旧的盖过去了"，
需要**新旧一起在场**，而只有成群那一趟的视野里有。

| 轮 | 造物（键 = kind）| 连边（键 = rel）|

## 5. 两趟的判据与各自的活

> **第一趟管「一条经历能做的事」（抽象 · 佐证）；第二趟管「一群经历才能做的事」（经验 · 进化）。**
> —— `DESIGN_MEMORY_MODES §0`

| | 第一趟（R2-1）| 第二趟（R2-2）|
|---|---|---|
| 视野 | **逐条**（本段每条新经历 + 现有认知）| **成群**（引擎切出的候选块 + 已有类 + 本段新看法）|
| 造物 | `belief`（**单条也允许**，见 §3）| `experience`（类名 + ⭐ **沉淀 `text`** —— 今天**没人写**这一格）|
| 连边 | `supports` · `akin`(+`on`) · `about` · `contradicts` | `member_of` · `evolved_from` |
| 料要加的一格 | ⭐ 每条经历的 `topics`（见 §6）| ⭐ **候选块里各成员的标题 + 一句正文**（没有它写不出沉淀）|
| 候选块从哪来 | — | ⭐ **引擎按 `topics` / `akin` 切出的分量**（纯集合运算）—— 这是 `topics` 轴的**消费者** |
| 并类 | — | `{"experience": {"merge_with": "窗台那盆"}}`（并进赢家：收 `aliases` + 边重连）|

⚠️ **`experience.text`（沉淀）是这次新加的**：今天 `group` 轮只写 `title`/`aliases`，
群里**没有一句话** —— 而"经验"这个模式的定义就是"**沉淀**"。

---

## 6. `topics` 轴（**上限 3**，2026-10-07 用户裁决）

- **写者**：R1（`record`），逐字段表里长出一格：
  `"topics": ["苔藓", "生日"]` —— 这条经历**关于什么**，**1~3 个具体的东西**（人 / 地方 / 物件 / 事）；
  ⛔ **不写泛词**（"老师""日常""心情"）；写不出 ⇒ 空数组合法。
- **`akin` 必填 `on`**，且 **`on` ∈ 两端 `topics` 的交集**（引擎**形状校验**，写边那一刻挡住 ——
  这就是"链式膨胀"的事先解法：传递只在同值内）。
- **引擎按交集切分量**（只做集合运算，**不推断语义**）。

## 7. 明确不做（免得下轮又捡回来）

| ❌ | 为什么 |
|---|---|
| **早年 L1/L2 那版的 `ignite` / `covered` / `gap`** | 它建立在"新建只能是归纳的产物"上，而用户 2026-10-07 裁"**单条可以 abstract**" ⇒ 那条闸没有存在的理由 |
| **`update` 这个词** | 三个用途各有新家（§2）；留着它＝留着"一个字段说不清在干什么" |
| **把 `note` 收进这个封装** | 备忘录**不进图** ⇒ 图上才有"类型"可言；混进来会让"11 个键"变成"11 个键 + 一个特例" |
| **entity 的摘要 / `state`**（R3 墓碑说"并进第二趟"）| entity 今天**没有读者**；等它有了再说 |
| **`decision` / `kind` 两个字段并存** | `kind` 恒为一个值 ⇒ 已合并（§2）|
