## 2. 为什么这么拆（拆分的**真理由**，别自己另编一个）

> **"对一群经历作总结"与"产出一条 belief"本质是同一件事** ——
> 都是「**从证据里归纳出一句结论**」，差别只是证据是**一条经历**还是**一群经历**。
> ⇒ 所以它们**该在同一趟**（写正文的那一趟）；**关系判断在另一趟**。

⭐ **代码里就留着这次拆分的证据**：`ROUNDS` 表里 `group` 轮的 step 名写着
**「⑤ 分群（L2-a）」** —— 9/27 那次拆分**落了 L2-a 这一半**（分群）；
**没落的那一半（关系轮）= 本文**。

## 3. 两趟的分工

### ⭐⭐ 判据（2026-10-07 用户认可）: **谁手里有两端，谁判这条边。一条边绝不判两遍。**

⇒ 边**不按"关系 vs 正文"分**，也不按"一条 vs 一群"分，而是按 **这条边的两端在哪一趟手里** 分。

| 边 | 两端 | 归谁 |
|---|---|---|
| `supports`（新经历 → **现有**看法）| 已有 × 已有 | **L1** |
| `akin` / `contradicts`（新经历 ↔ **现有**经历）| 已有 × 已有 | **L1** |
| `about`（→ entity）| 已有 × 已有 | **L1** |
| **`supports`（新经历 / 现有经历 → 新看法）** | **新** × 已有 | **L2** |
| **`evolved_from`（新看法 → 旧看法）** | **新** × 已有 | **L2** |
| **`contradicts`（新看法 ↔ 旧看法）** | **新** × 已有 | **L2** |
| **`supports`（新看法 ↔ 旧看法，"看法撑看法"）** | **新** × 已有 | **L2** |
| **`member_of`（经历 → 新经验）** | **新** × 已有 | **L2** |

⭐ 这条判据顺手解释了 **`akin` / `contradicts`（经历 ↔ 经历）为什么在 L1** —— 两端都是已有经历，L1 手里有 ✓

⚠️ **但它对"该不该长出一条看法"不适用**（2026-10-07 修正）—— 那不是一条边
（它的一端是"**一句还没写下的话**"）⇒ ⛔ **L1 不打标记、不造虚节点**（理由见 §8）。

### 两趟各是什么

| | **L1（第一趟）** | **L2（第二趟）** |
|---|---|---|
| 一句话 | **已有成分之间是什么关系** | **造新认知，并把它接上图** |
| 手里 | 本段每条新经历 + 时间线 + **现有认知 / 现有经历**（候选由引擎摆好）| **它刚造的东西** + 现有认知 / 现有经历 + L1 标出的证据 |
| 她说的词 | `supports`（**佐证**）· `akin`（**同类**）· `contradicts`（**矛盾链**）· `about`（关于某对象）| `belief`（**造看法** —— 证据一条或一群**是同一件事**）· `evolved_from`（**进化**）· `experience`（**起类名 + 写沉淀**）· **+ 它自己落的那些边** |
| 产出 | **只有边**（零正文、零标记）| **节点（正文）+ 它周围的边**（边在造的时候一起落，§5）|
| 不碰 | 正文 | 已有成分之间的关系（L1 已判过）|

⭐ **L1 的输出干净到只剩"关系"；"该不该长"由 L2 自己判** ⇒ **两趟都不重复思考** ✓

### ⭐ L2 的料 = **L1 圈出来的素材**（接力，不是并列）

⚠️ **L2 不该重走 L1 的素材库** —— 它要的是"**刚被动过的那一小堆**"（2026-10-07 用户）：

| L2 的料 | 从哪来 |
|---|---|
| **被 L1 连过的那些经历**（`supports` / `akin` / `contradicts` / `about` 的两端，去重）| ⭐ **L1 落下的边**（纯计算：读边取两端）|
| **L1 指向的那些认知 / 群** | 同左 |
| 少量引擎相似度候选（给 `evolved_from` 找旧看法用）| 引擎 |
| **那些成群经历的正文**（写「经验」的沉淀要靠它）| 同第一行 |

⇒ 好处：**料小而准** · **两趟是接力**（L1 圈素材 → L2 写）· 而且 L2 **照样看得到 episode**（写沉淀要用）✓

⚠️ **孤立经历（L1 一条边都没连的）不进 L2 —— 这不是漏洞，是天然的归纳门槛**：
它跟她的任何已有认知 / 经历**都没有关系** ⇒ 归纳**没有立足点** ✓
⚠️ 等它以后被连上（同类的事再发生 ⇒ `akin` · 或它印证了某条看法 ⇒ `supports`），那时再归纳。
（真要盯它，就记一笔账 —— `TODO_TWO_PASSES` 的 **P6** 就是"孤立经历的账"，那是**观测**，不是闸。）

### ⛔ 被否掉的替代切法（别拾回来）

> ❌ **"关系全给 L1，L1 一个字不写"** —— 那是**让 LLM 想了一遍却只做一半**，
> 然后 L2 **再想一遍**（同一件事判两遍）。用户原话：*"全然交给 R2-1 但不写，
> 反而是让 LLM 想了但是只做一半，然后 R2-2 再想一遍。"*

## 4. 词汇表（键 = 关系名 或 节点 kind）

⭐ **一行的"动作"不用 `decision` 这种判别字段 —— 键本身就是动作**：

```
{"episode": "m0001", "supports": "u0002"}                    // L1 连边（佐证）
{"episode": "m0003", "akin": "m0001", "on": "苔藓"}          // L1 连边（同类，轴必填）
{"episode": "m0007", "evolve": "u0002"}                      // L1 打标记（不写正文）
{"belief": {…}, "evidence": ["m0007", "m0011"]}              // L2 造看法（出生自带证据边）
```

**两条形状规则**：

1. ⭐ **值是字符串 = 引用一个已有节点；值是对象 = 造一个新节点**
2. **键的域 = 图上真实存在的名字**：`graph.RELS`（6 条）+ `nodes.KINDS`（5 种）= **11 个键**，
   ⭐ **两个真源、零第三处维护**（加一个 kind / rel，词汇表自动多一键）。

### 三档：谁定 rel（抄 `graph.classify_pair` 的原文判据）

| 档 | kind 对 | 结论 | 她要表态吗 |
|---|---|---|---|
| **① 唯一** | `episode → belief/experience` = `supports`；`对方 → entity` = `about` | 引擎能定 | 可以不说 |
| **② 多义** | `belief ↔ belief`：`supports`（看法撑看法）/ `contradicts` / `evolved_from` | 引擎**不猜** | ⭐ 必须说 |
| **③ 故意不判** | ⭐ `episode ↔ episode` | 引擎**不猜** | ⭐ 必须说 —— "两条经历相连"有**两种意思**：**时间上接着**（⛔ 不写边）与 **`akin` 同类** |

### 三个格 × 三型（**这张表自己就是完备性检查：缺一格 = 缺一条关系**）

| 格 | 同类 / 支撑 | 对立 | 时序 / 演化 |
|---|---|---|---|
| **episode → belief** | **佐证**（`supports`）| — | — |
| **episode ↔ episode** | **关联**：`akin`（⇒ 产群）| `contradicts`（⇒ 矛盾链）| `continues`（⇒ 加强召回）|
| **belief ↔ belief** | `supports`（看法撑看法）| `contradicts` | **进化**：`evolved_from` |

⚠️ 两处措辞纪律：

- **`belief ↔ belief` 那一格整体不能叫"进化"** —— 同格里有三种，"进化"只是**时序那一型**（整格叫【认知之间】）。
- **`continues` 与另外两个不同族**：`akin` / `contradicts` 是**语义判断**（要她表态）；
  `continues` 的判据是**事实**（区间相接 / 交叠、中间没插进另一件事）⇒ ⭐ **由引擎落**（或先只记账），
  **不进她的判断格**。

> *"还是说 R2-1 打标记，R2-2 的 belief 出生自带 episode/group"*

- ⛔ **不需要**任何"跨轮补边"机制（今天的 `group` 轮连 R1 的 episode 就是日常操作）。

## 8. ✅ 已定：**L1 不打标记，"该不该长"由 L2 自己判**（2026-10-07 用户裁决）

用户原话：*"不需要让 L1 提前标记，也不需要让 L1 造虚节点，因为这其实又踩了我刚说的
那个重复思考的问题。"*

**排查过的四个候选场景 —— 没有一个是"标记极其重要"**：

| 场景 | 没有标记会怎样 | 更便宜的通道 |
|---|---|---|
| **① 孤立经历** | —— | ⭐ **不需要标记**：它**本来就该等**（跟任何已有认知/经历都没关系 ⇒ 归纳**没有立足点**）⇒ 等以后被连上再归纳（§3 那条）|
| **② "这几条是一类"** | — | ⭐ **L1 落的 `akin` 边就在盘上**，L2 跑在后面，读得到 |
| **③ "那条旧看法过时了"** | — | ⭐ 那本来就是 **L2 的活**（§3 边归属表：新看法 ↔ 旧看法 = L2 判）|
| **④ 量大时省注意力** | L2 要多扫几眼 | ⚠️ 唯一有真价值的场景 —— 但它该由**引擎先筛**（纯计算）承担，**不该让 L1 多想一遍** |

⭐ **决定性事实**：**L1 没有任何 L2 拿不到的私有信息**（两者的料可以是同一份）
⇒ 标记是**冗余通道**，而它的成本是「**同一件事想两遍**」（看出"这里有话可说"本身就是一次归纳）。

⚠️ **记档：这条判据（"谁手里有两端"）对"边"成立，对"该不该长"不适用** ——
后者的一端是"一句还没写下的话"，不是一条两端都存在的边。**别再用它推标记。**

⚠️ 早年 L2 那版的 `ignite` / `covered` / `gap` 位置：现在是 **L2 写正文时的参考**
（"旧的那条说了多少、还差什么"），**不是"要不要新建"的闸**（没有闸了 —— L2 自己判）。

## 9. ✅ L1 契约正文（2026-10-07 定稿 · 待落地）

### 9.1 输出形状（LLM 交的东西）

```json
{"relations": [
  {"episode": "m0014", "about": "x0001"},
  {"episode": "m0017", "akin": "m0014", "on": "苔藓"},
  {"episode": "m0017", "supports": "u0003"},
  {"episode": "m0015", "contradicts": "m0009"},
  {"belief": "u0007", "supports": "u0002"}
]}
```

⭐ **性质**：**行里只有 id，没有一个正文** —— 凡是要"写点什么"的东西都不在这一趟。

### 9.2 规则（进契约）

- **一行一条关系**；同一条经历有几条关系就写几行。
- **行首 = 本段新来的那条经历**（`"episode": "m…"`）。
  ⚠️ **例外**：引擎把**两条已有**的东西摆到一起让你看时（候选对），行首可以写 `{"belief": "u…"}`。
- 右边**只能引用上方渲染列表里出现过的 id**（编造 id → **整包拒**）。
- ⭐ **没话说就不写** —— **不要求每条经历都出现**（"这条跟谁都没关系"也是一个结论）。
- ⛔ **这一趟不写正文**：没有 `text` / `subject` 这些键。
  看到"这里有话可说"**不用写出来** —— 下一趟会看到同一批料，由它去写。
- **方向不用你操心**：两端的类型天然定了方向（经历 → 看法 / 经历 → 对象）；
  对称的那两条（`akin` / `contradicts`）写哪边都一样。

### 9.3 四个动作（**类型写在语义里，不加 `ends` 格**）

**1. `supports` —— 这条经历「印证」了那条看法**
- **两端**：左 = 本段的一条**经历**（`m…`）· 右 = 一条**已有的看法 / 经验**（`u…` / `g…`）
- **何时用**：这条经历又一次验证了那条已有结论 —— 不是新角度，也没有推翻它
- ⛔ **别用**：想说"这两条经历像"（那是 `akin`）· 想说"这条是关于某人的"（那是 `about`）

**2. `akin` —— 这两条经历「是同一类事」（**只有平行同类**才算）**
- **两端**：**都是经历**（左 = 本段新经历 · 右 = 已有经历）
- ✅ **算数**：老师**又**送了我一次花（上次也送过）· **又**被老师夸了一次 · 又在同一个地方看见苔藓
- ⛔ **不算数**：**同一件事的先后两段**（刚才那件事的下半截）—— 那是**时间上的接续，不是同类**。
  时间上接续的**什么边都不要写**（时间线自己会说清）
- **必填 `on`**：那个**共同的具体东西**（花 / 夸奖 / 苔藓）—— 必须是**两端 `topics` 交集里**的词

**3. `contradicts` —— 这条和那条「对着来」**
- **两端**：经历 ↔ 经历，**或** 看法 ↔ 看法（对称，方向无所谓）
- **何时用**：她后来发现"不对" / 两边说不通
- ⛔ **别用**："程度不同"（不算对立）· "后来变了"（那是下一趟的 `evolved_from`）
- ⭐ **"两条已有看法互相矛盾"这一格归它，但只在引擎摆出候选对时判**（用户裁"暂时归乙管"）——
  不要求它扫全表

**4. `about` —— 这条经历「是关于」那个对象（人 / 地方 / 东西）的**
- **两端**：左 = 经历 · 右 = **一个对象**（`x…`）—— 对象**永远在右边**
- **何时用**：这条经历的**主要内容**就是它
- ⛔ 只是"提到过一句"不算
- ⚠️ 今天 entity 的写者（R3）在暂停 ⇒ **候选会很少**（只有 `x0000` 她 / `x0001` 老师）⇒ **有候选才写**

### 9.4 料（L1 看什么）

| 今天 | M3 · L1 |
|---|---|
| 本次新经历（含引擎候选标注）· 本段时间线 · **现有认知** · 角色人设 | 同左 **+ ⭐ 现有经历（候选）** |

⚠️ **为什么必须加**：`akin` / `contradicts` 的另一端是**已有的经历**，而今天的料里**根本没有它**
⇒ 这两条边**结构性写不出来**（真机 `akin` = 0 条，这一半是原因）。
⭐ 另外：候选经历的 `topics` 要一起印（否则她判不了 `on` 的交集）。

### 9.5 校验（`parse` 层 · 引擎当场挡）

| 查什么 | 不合法怎么办 |
|---|---|
| 行形状（行首一个 kind 键 + 一个关系键 + 可选 `on`）| 丢这一行 + 记账 |
