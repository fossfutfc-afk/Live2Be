## 1. 为什么"六路加权"确实古怪（四条，都能在代码里指出处）

| # | 症状 | 出处 |
|---|---|---|
| ① | **量纲根本不齐**：`lexical` 是覆盖率（门槛 .35）+ 标题 .85 + tags .60；`semantic` 是**池内 min-max 之后**的 cos；`struct` = 种子 × 边权；`temporal` = freshness(年龄)；`prior` = significance；`name` = 0/1 命中 | `like.PARTS` / `part_*` |
| ② | **分数不是这条记忆的属性**：`semantic` 的池内 min-max + 名次门槛 ⇒ 同一条记忆的分**取决于库里还有谁** ⇒ "她为什么想起这条"不可复现、阈值无法标定 | `like._pool_norm` / `_hit_k` |
| ③ | **先验假装是证据**：`name` / `temporal` / `prior` 在 `Part.axis` 里标的明明是 **PRIOR（只加成）**，却塞进同一个平均参与排序；真正决定"进不进"的是"证据轴至少一路命中" | `like.PART` 的 axis 注释 / `part_name` 的裁决 |
| ④ | **算术平均稀释强证据**：一条极强（名字精确命中 / 正文近乎逐字）会被四条无关路摊平 | `like.like` 的加权平均 |

⭐ ③ 的证据早在代码里：`part_name` 的注释写着*「」老师」车道真机 10/21 条 ⇒ 作准入的话
一句寒暄就凑出 10 条并列* —— **那不是权重该调，那是"它该不该算一路"的问题**。

## 2. 别人怎么做（六类范式）

| 范式 | 代表 | 判据怎么合成 | 启示 |
|---|---|---|---|
| **加权和 + top-k** | Generative Agents（Park 2023）[PDF/HTML](https://dl.acm.org/doi/fullHtml/10.1145/3586183.3606763) | recency + importance + relevance **各自归一后等权相加**，取 top-k | 这是**基线**；它三条的**量纲是刻意统一的**（都 0~1、都"越大越该想起"），且没有多意图问题。我们比它脏 |
| **秩融合（不归一分）** | 混合检索工程惯例 RRF | 每路只出**名次**，`Σ 1/(k+rank)` | ⭐ **要么别混分，要么混名次**。RRF 无量纲、无权重可调（只有一个 k） |
| **图上游走 / 扩散** | HippoRAG（NeurIPS'24）[摘要](https://papers.nips.cc/paper_files/paper/2024/hash/6ddc001d07ca4f319af96a3024f6dbd1-Abstract-Conference.html) | 从 query 实体出发做 **PPR**，沿知识图扩散 | ⭐ **"近邻事件"的正统做法是扩散，不是打分**。我们的 `part_struct` 是它的退化版（只一跳、只走窄门） |
| **认知架构的激活方程** | ACT-R / 扩散激活 [base-level + 联想](https://pmc.ncbi.nlm.nih.gov/articles/PMC2733322/) | `A = 基线(频率×近因，**对数域**) + Σ 联想权重 + 部分匹配 + 噪声`；检索概率 = softmax(A) | ⭐ **独立证据在对数域相加（≈相乘）** —— 这正是"强证据不该被稀释"的形式化。`temporal`+`prior` 该是"基线"那一项，`name`+`struct` 是"联想"那一项 |
| **触发器式注入**（叙事产品最主流） | SillyTavern World Info / lorebook [文档](https://docs.sillytavern.app/usage/worldinfo.md)、AI Dungeon Memory | **键命中 ⇒ 整条注入**（优先级/递归可选），不排序不混分 | ⭐ "什么时候摆哪一条"是**规则/作者的事**，不是相似度的事。我们其实已经在用（`name` 车道、P19 标题清单） |
| **工具式自取** | MemGPT / Letta | 她自己调检索工具 | 我们已经走了：`mmt_look` |

## 3. 我们的形状（用户 2026-10-12 裁）

**多形式并列，⛔ 不混分。** 一次召回 = 一种**形式**（"她为什么想起这件事"）；
形式之间**不竞争名额**、不互相平均。真要出一个总序 ⇒ 混**名次**（RRF），永远不混分数。

两种形状（`Mode.shape`）：

| shape | 执行器 | 判据 | 输出 |
|---|---|---|---|
| `rank` | `like.like(spec=…)` | 六路打分 → 归一 → 证据轴命中 → 加权排序 | 最像的 ≤ k 条 |
| `set` | `find.find(anchors=…)` | **确定**判据（名字命中 / 时间区间 / 图上相邻） | 命中的**全部**（新→旧） |

⇒ **加权和降级**为"`rank` 形状里的一行 spec"（`SPECS["turn"]`），不再是唯一对外 API。

## 4. 形式清单（路线：落一个加一行；⛔ 没接线的**不许**先写进表）

| mode | 形状 | 触发（cue） | 输出 | 段头（她看到的） | 状态 |
|---|---|---|---|---|---|
| `turn` | rank | 总是（兜底） | 最像 1~2 条 | 【你想起的事】 | ✅ 现役 |
| `name` | set | 玩家这句点到某个对象名 | 他车道上**全部** | 【关于他们的】 | ⚠️ 已能跑/有守门, **未接线** |
| `when` | set | 出现时间词 | 区间内全部（新→旧） | 【那阵子的】 | ⏭ |
| `echo` | rank | query 与某条"感觉像"（要 embed 或 n-gram） | **只给一条** | 【这感觉……以前有过】 | ⏭ |
| `mood` | rank | 本轮情绪键非空 | 同情绪 1~2 条 | 【那天的我也是这样】 | ⏭ |
| `near` | set/扩散 | 有种子（lexical 出） | 图上 1~2 跳的邻接 | 【紧接着那件事之后】 | ⏭ |

**四条纪律**：
1. **形式内部尽量用确定判据**（与 `find` 同哲学：不漏即正确）；只有 `echo`/`mood` 需要"像不像"。
2. **不做归一**（池内相对量一律不出现在 set 形状里）。
3. **"为什么想起"进段头** —— 比一个分更有用，也更好排错/守门。
4. ⛔ **别按编号命名**（`recall2/recall3`）：台账、守门、规则书都要引用它，编号改一次全漂。
   按**意图**命名（`name`/`when`/`echo`/`mood`/`near`）。

## 5. 为什么是"多形式"而不是"更好的加权"

1. **可解释 / 可标定**：每形式单独入台账（`pack.ledger_line` 有 `why`），加权和不能。
2. **可关可测**：一形式一行守门 + 一个变异；加权和只能整体测。
3. **成本可控**：`turn` 那条零 LLM 零 embed（真机 2ms 量级）；`echo`/`mood` 需要 embed 时才付代价，
   可"embedder 在就用、不在就静默降级"（既有纪律）。
4. **与"她主动翻"互补**：P19 摆的形式多 ⇒ `look` 的语法就该更少（她不必自己搜）；反之亦然。
   这是**产品取舍**（用户定），不是技术取舍。

## 6. 仍开着的（未结）

- **P19 形式多了注入会变长** ⇒ 谁有保底名额、谁吃剩下的（`render` 的 700 字预算）。
- `echo` / `mood` 要不要 embedder（真机教训：`semantic` 权重 0 是因为"每轮全库重编码" 916ms）。
- `near` 走 `find`（图上取邻接）还是把 `like` 的 `struct` 扩成两跳。
