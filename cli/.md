# cli/ — 终端调试入口

**定位**：产品只有网页壳 `webgui/`。本包是**给人调试用的第二入口**（提示词迭代、命令回归、
不启浏览器跑一遍 MMT）；它不是第二个产品，也不是"同一件事的终端版"。

## 核心文件

| 文件 | 是什么 |
|---|---|
| `main.py` | MomoTalk 终端循环：玩家名引导 → 角色选择 → 对话循环 → 触发羁绊剧情 |
| `vn_cli.py` | 羁绊剧情的终端驱动（逐段打字 + 选项 + 每场写事件流）—— webgui 那套异步状态机的**同步前身** |

启动：`python main.py`（仓根转调壳）或 `python -m cli.main`。

## 不追 webgui

`vn_cli.py` 的章节循环（进章 / 每场落库 / 重试 / 纪念生图 / 收束注记 / 收尾话术）与
`webgui/bond/` 是**两份实现**。产品行为只在 webgui 落地，**本包不同步**——预生成、
链式读前、双路标注、插嘴、回放续写、角色群聊，CLI 都不会跟着实现。

后果要认：CLI 会慢慢落后于 webgui 的行为。这在历史上真发生过一次——收束注记还在教
v1 的 `story_end` 动作，而记录流 v2 里根本没有这个动作。**除非有人拿它当产品用，
否则这种落后不算 bug。**

## 唯一必须双份维护的东西：喂给模型的文案

终端侧不许自己写 LLM 可见的句子，只能调 `core/` 里那一份：

- 先例 = 收束注记 `core/bond/bond_story/closing.py`（cli 与 webgui 共用一份）；
- 守门 = `tests/core/test_vn_cli.py` 的 `test_closing_notes_have_one_source`（这三句
  只许出现在那个文件里）。

其余一切（流程、retry、预生成、并发）**不同步**。

## 两条纪律

1. **没人可以 import 它**：`contract/` `infra/` `llm/` `core/` `tui/` `webgui/` 都不许
   依赖本包（`tests/core/test_import_direction.py` 钉着）。C11 之前 `webgui → vn_cli`
   就是这么反过来的，那是要避免的形态。
2. 终端显示走 `tui/`（`Renderer` / `RenderScene`），别在这里另写一套渲染。
