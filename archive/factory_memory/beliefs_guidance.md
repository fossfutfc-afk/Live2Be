# beliefs.yml 写作指导 — 出厂认知

> 一句话：**beliefs.yml 写的是"她经历了那些事之后，心里形成了什么结论"。**

位置：`config/characters/{角色}/beliefs.yml`（与 experience.yml 同目录）
可选文件：没有它，角色只是"没有出厂认知"，其余一切照常。

---

## 1. 它是什么：角色卡的认知层

一个角色的出厂素材分三层，beliefs 是最高层：

```
experience.yml   她经历过什么（事件：拆炸弹、送杂草、被接纳……）
knowledge.yml    她知道什么（档案：阿露是社长、杂草屋在哪……）
beliefs.yml      她怎么理解（结论：老师是第一个不嫌弃我的人）
```

程序会在世界线创建时把它们整理成角色的出厂记忆：

- experience → 一段段"我记得的事"（episode）
- knowledge → "我知道的事"（fact）
- **beliefs → "我心里渐渐觉得"（belief）——每条 belief 用 links 钉在支撑它的经历上**

belief 是**运行时会演化**的：之后每次剧情消化，新的经历会 touch（印证）或 update
（深化/修正）它。你写的是**出厂基线**——角色在故事开始前就已经形成的认知。

## 2. 文件结构

```yaml
# beliefs.yml — 出厂认知（每个 - 是一条 belief）
- subject: 老师
  content: 老师是第一个不会嫌弃我的人——拆炸弹、送杂草、打碎花盆，他都接纳了真实的我
  links: [self.regular.1, self.regular.2, self.regular.3]
  # significance: 0.95      # 可选。0~1，默认 0.85。越接近 1 越"常驻心头"

- subject: 便利屋68
  content: 无论社团多落魄、我多没用，和大家在一起就是我最珍惜的事
  links: [main.1, main.3]
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `subject` | ✅ | 这条认知**关于谁/什么**。宽维度命名：人（老师/阿露大人）、团体（便利屋68）、自己、或一个关系模式（和老师的相处方式）。不要写"和老师一起拆炸弹的那个下午"——那是事件不是维度 |
| `content` | ✅ | 认知**结论**（≤200 字）。写"她心里怎么想"，不写"发生了什么事" |
| `links` | ✅ | 支撑这条结论的**经历条目**（引用 experience.yml，见 §3）。至少 1 条 |
| `significance` | ❌ | 显著性 0~1，默认 0.85（出厂认知都是重要的）。越接近 1 越优先被想起 |

> 为什么 subject 要"宽"：运行时剧情消化会把新经历往已有认知上挂（印证/深化）。
> subject 太窄（"老师陪我看杂草的那次"）新经历永远挂不上去，只会不断新建认知，
> 角色会变得碎片化。**一条宽结论 + 逐年加深，比十条窄结论更真实。**

## 3. links 怎么引用经历（source_key 规则）

links 引用 **experience.yml 里的条目**，写法是"键路径剥掉前缀 + 序号"。
对着 experience.yml 看最直观：

```yaml
# experience.yml 里长这样（SIG~ 前缀会被剥掉）:
SIG~self:
  - regular:
    - 1: >   # ← 这条的 source_key = self.regular.1
        不小心错误地给sensei发送了消息……
    - 2: >   # ← self.regular.2
        想报答sensei陪她拆炸弹的遥香……
main:
  - 1: >     # ← main.1
      遥香与便利屋68的同伴们接下凯撒集团……
valentine:   # ← 整段纯文本 = 一条, source_key = valentine
  sensei提前把遥香叫过来……
```

规则：`剥掉 SIG~/REQ~ 前缀的顶层键` + 列表项的 `序号`，用 `.` 连接。

```yaml
links: [self.regular.1, self.regular.5, main.1, valentine]
```

注意：
- **顶层键里的 null 值会被跳过**（如 `self.dress: null`）——引用它会报错
- **写错了没关系**：程序会报"links 引用了不存在的条目：xxx"，并在报错里列出
  所有可用的 source_key，照着改即可
- 当前版本 links 只能引用 **experience** 的条目（belief 的支撑必须是"经历"，
  不能是"知道的事"——知道≠经历过）

## 4. 写作规则（写成什么样算好）

1. **content 写结论，不写事件。**
   把事件留给 experience.yml。belief 里出现"那天我们去了甜品店"就是写错了——
   正确的是"和老师待在一起时，我不用觉得自己在添麻烦"。

2. **每条 belief 是"她信了很久的东西"，不是临时感想。**
   出厂认知 = 故事开始前就定型的心智。如果某条认知是"最近才隐隐觉得"的，
   那它属于运行时消化，不该出现在出厂。

3. **content 用第三人称"她"写，不要用"我"。**
   文件是档案（别的角色/系统也在读），程序注入给角色时会自动转第一人称：
   ```yaml
   content: 老师是第一个不会嫌弃她的人    # 作者这样写
   # 渲染后: 对老师：老师是第一个不会嫌弃我的人  # 角色这样读到
   ```

4. **subject 稳定、宽、可挂新经历。**（见 §2 的说明）

5. **links 宁缺毋滥：2~5 条就够。**
   一条被 12 条经历支撑的 belief 和 3 条支撑的效果一样——她早就信了。
   真正的演化价值在于**运行时**新经历的 touch/update，不在出厂堆链接数。

6. **3~5 条最佳，不要超过 7 条。**
   注入时"我心里渐渐觉得"段会按 significance 取前 5 条。写得太多，
   低优先级的永远不被想起，还浪费注入预算。

7. **可以写对自己的认知。**
   subject: 自己 完全合法——而且往往是最重要的一条
   （遥香"我这样的人配不上好东西"就是她的行为总开关）。

## 5. 完整范例

一个虚构角色"示例学生"（她的 experience.yml 有 self.regular.1~2、main.1）：

```yaml
# beliefs.yml — 示例学生
- subject: 老师
  content: 老师是第一个没有嫌弃她的人——无论她搞砸多少事，老师都会留下来教她重新来过
  links: [self.regular.1, self.regular.2]
  significance: 0.95

- subject: 自己
  content: 她总是把事情搞砸，但老师说过"地砖里的苔花也是花"——她决定试着相信一次
  links: [self.regular.2]
  significance: 0.9

- subject: 便利屋68
  content: 社团是她的容身之处——就算她再没用，大家也没有丢下过她
  links: [main.1]
```

角色实际读到的注入（程序自动完成人称转换与排版）：

```
我心里渐渐觉得：
- 对老师：老师是第一个没有嫌弃我的人——无论我搞砸多少事，老师都会留下来教我重新来过
- 对自己：我总是把事情搞砸，但老师说过"地砖里的苔花也是花"——我决定试着相信一次
- 对便利屋68：社团是我的容身之处——就算我再没用，大家也没有丢下过我
```

## 6. 反面例子（常见错误）

```yaml
- subject: 和老师去甜品店的那天        # ✗ subject 是事件不是维度
  content: 老师请我吃了草莓蛋糕         # ✗ content 是事件不是结论
  links: [self.regular.1]

- subject: 老师
  content: 老师对我很好，那天拆炸弹的时候他陪着我，还送我去医院，后来……  # ✗ 写成记叙文了
  links: [self.regular.1]

- subject: 老师
  content: 老师是最好的
  links: []                            # ✗ 没有支撑（程序会拒绝：belief 必须 links ≥1）

- subject: 老师
  content: 我觉得老师人很好             # △ 太泛——"好"没有行为含义, 运行时无法印证/深化
  links: [self.regular.1]
```

好 content 的检验法：**把它反过来当行为指令读**——"因为她相信 X，所以在 Y 情境下
她会 Z"。比如"老师是第一个不嫌弃我的人"→ 她犯错时会向老师坦白而不是逃走。
写不出行为含义的 belief 就是太泛了。

## 7. LLM 作者自查清单

- [ ] 每条 content 是结论不是事件？（检验：能否当行为指令读）
- [ ] subject 是稳定宽维度（人/团体/自己/关系模式）？
- [ ] links 全部存在、且是 experience 的条目？
- [ ] content ≤200 字、第三人称"她"口吻？
- [ ] 总数 3~5 条？significance 是否反映真实优先级？
- [ ] 这些认知是"故事开始前就定型"的，不是最近才发生的？
