## ★ 粒度实测（2026-09-20，回答"一章要不要一条"）

用户怀疑 *"episode 最好与 bond 一一对应，这样召回才好"*。用 14 章 / 31 条实测
（`ba_recall_probe.py`，本机 `nomic-embed-text-v1.5`）：

```
同章对 0.836 / 跨章对 0.760 / 域外 query 0.560   ← 分层只有 +0.076
留一法: top1 是同章 11/26, top3 内有同章 15/26
片段认回自己的章（都排除 query 自己）: 原子 11/26 | 带标签原子 8/26 | **章拼接 10/26**
章拼接分层: 章内 0.848 / 章外 0.755（略好）    章均值向量之间 0.807（比跨章片段还高 = 揉成一团）
```

**三条结论**：

1. **粒度对检索没有可测影响**（11 / 8 / 10，n=26，差 1~3 例是噪声）⇒ 决定粒度的
   是"**单位该是什么**"，不是"RAG 准不准"。用户那句 *"添加更多文本说不定反而会
   增加 RAG 能力"* 在这个量级（≤461 字）**测不出收益**，但也**不构成反证**
   （没测整章原文那种长文本）。
2. **瓶颈是模型**：韩文章（1600005）章内 0.927~0.950 vs 章外 0.637，中文章
   （1600002）章内 0.838 vs 章外 0.787 ⇒ **语言在主导 cos**（nomic 是英文中心）。
   换多语模型之前，任何"粒度/权重"的调参都在噪声里。
3. **粒度裁决另有三条结构证据**（见 `docs/DESIGN_WIKI_V3.md §2.3.1′`）: 官方剧本
   第 1 条就是 `#title;…`（每章自带总结）; AgentGal 是"**闭合主题一条**"
   （它要 closure detector 是因为它跑连续大会话、**没有**结构断点）; A-Mem 是原子
   note 但靠 **context + evolution** 保连贯。

⚠️ 过程坑：第一版逐条 `embed_fn([txt])` 打了 300+ 次 HTTP 把脚本跑死 —— **批式**。
⚠️ 过程坑：`max(_cos(q, v) for v in 该章所有条)` 会把 query 自己算进去（cos=1.0）
    → 印出 31/31 的假象。**算"认自己的章"必须先排除 query 那条**。

## 官方剧本形态（重建叙事必读）

一条记录 = 一个指令，块类型由**首个 token** 决定：

| 形态 | 含义 |
|---|---|
| `#title;X` | 标题 |
| `#na;(…)` | 旁白 |
| `#st;{pos};{mode};{n};{txt};{delay}` | **台词碎片**——一句跨多条记录，遇 `#clearST`/转场/旁白才断开 |
| `N;{char};{emo};{txt}` | **以数字开头**（如 `3;하루카;04;…`）也是台词；但 `3;하루카;08`（无文本）是立绘指令 |
| `[sN] {txt}` / `[nsN] {txt}` | 台词槽 / 动作槽 —— **选项文本就在这**（`[s]` 无编号的是台词，不是选项） |
| `SelectionGroup=N` | 挂在**落地记录**上；连续两号若文本逐字相同 → 该表态点复用同一反应段 |
| `#wait;` `#clearST` `#all;hide` `#3;em;[?!]` | 时序 / 清屏 / 转场 / 立绘表情 |

⚠️ **两个坑**（都踩过）：
1. `Event.from_dict` **丢弃 `ts` 为空的事件**——构造事件时忘了 `ts`，整段时间线会静默变 0 字
2. 表态点语义是"**槽在板尾、反应在下一板**"——反应段不属于选项所在板

## 实测结果（2026-09-13，14 档 / 31 条 episode）

```
SIG : min .55 max .90 mean .74  sd .101
span: min .30 max .90 mean .63  sd .163
int : min .40 max .85 mean .70  sd .121
val : min −.60 max .85 mean .38 sd .384     ← 正 25 / 负 6 / 零 0
|span−int|: mean .088 max .300, ≤0.10 占 23/31
```

**三条结论**：
1. **`emo_valence` 不是恒正**——真机那 8 条全正是**小样本假象**，这里 6/31 为负
2. **`span` 与 `int` 语义独立**——8/31 处 |diff| ≥ 0.10，最大 0.300。
   个案：`1600002 m0001`（误发短信叫来老师）span .50 / int .80 = 峰值高但没有弧
3. **角色自称会泄漏进 digest**——mutsuki 的产出用"我身为女仆的称呼坚持"，
   LLM 用的是角色词汇表。这反过来印证了注入人设卡的必要性

**已知不忠实处**：官方剧本没有情绪标注，故时间线里没有 `(情绪键)`，Round A 只靠
文本推 — 即本语料的输入比生产**更少依据**。要更忠实需先跑我方标注层。
