# contract/ — 契约地基

**作用**：定义"LLM 能输出什么形状、谁来判它"，并提供两侧共用的最小原语（槽填充、md 加载、错误、问题清单）。
不含业务判断：配额、状态机、标注门控都在引擎里。它是全仓最底层——不 import 任何项目内模块，
`llm/` 与 `core/` 都依赖它。对外只认 `contract/__init__.py` 这一个门面。

## 核心文件

| 文件 | 是什么 |
|---|---|
| `registry.py` · `spec.py` · `model.py` | 动作契约：注册表 / 动作规格（payload 描述、审批态）/ wire 数据对象 |
| `records/` | VN 记录流：文法常量、行解析、块内结构校验（群 / 位置） |
| `streams/` | 域无关的行流骨架 + 增量缓冲，MMT 与 VN 共用 |
| `digest/` | 消化各轮的输出契约（轮次真源 = `core/digest/rounds/`）：一份 spec 同时驱动 prompt 渲染与结构校验 |
| `schema/` | LLM 可见文本的渲染（行流 / 记录流），文案在 `schema/prompts/*.md` |
| `errors.py` · `issues.py` | 错误原语（`Live2BeError` / `err`）· 问题清单（硬 / 软分级） |
| `slots.py` · `prompt_files.py` | `{{槽}}` 填充（模板与值两个方向都对账）· md 加载 |
| `constants.py` · `json_cleaner.py` · `timeline_index.py` | 审批与域常量 · 纯 JSON 修复 · 时间线行号词汇表 |

## 两条纪律

1. **判据只有一处**。LLM 可见的文案是数据（`*.md`），代码只负责取哪份、填什么槽、怎么拼。
   改任何进 prompt 的字都要跑 `.testtmp/` 下那几份逐字节判据（`capture_1e.py` / `verify_1c.py`）。
2. **示例才是形状的来源**。改规则书时必须同批改示例，否则模型只学会示例那个形状。
