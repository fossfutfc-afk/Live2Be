decisions 规则: 每个 episode 恰好一行; 必须覆盖全部 episode;
id 只能引用上方渲染列表里出现的 id（编造 id → 整包拒）;
引擎候选标注'疑似印证/疑似重复'时必须遵守（印证→touch, 重复→update）。

links 规则（**可选的补充边**, 别拿它当主力）:
  supports      —— 「**这条看法**支撑**那条看法**」（两端都是看法;
                    「经历支撑看法」那种由决策表的 touch 写, 别在这里重复）;
  contradicts   —— 「这两条互相打架」（无向: 写一次就够）;
  evolved_from  —— 「这条是新的, 它把旧的盖过去了」（新 → 旧）;
  ⚠️ 方向别写反（`from` 是新/被支撑的那一头）; 两端都不能是本轮新建的条目
    （列表是这一轮**开始前**的样子 —— 新建的下一轮才连得上）。

两层写法（别混, 2026-09-20 用户定）:
  episode = **informative but single**（信息量足, 但只讲一件事）;
  认知（belief/experience）= **brief but descriptive**（简短, 但描述性 ——
  写的是模式/结论/看法, 不是事件; 不要复述剧情）;

【add 释义】无同主题认知——新建一条 belief 并连回 episode。
语义:
何时用: 候选里没有同主题认知, 且新经历形成了稳定结论或可复用模式;
怎么改: subject 用稳定维度命名（人/关系/互动模式/性格特征）; text 写结论/模式不写事件 —— ⭐ **反复出现的模式也写成 belief 的模式句**（没有单独的 kind: 模式 = 她的看法, 见 DESIGN_GRAPH_V4 §5.1/§9-10）;
禁什么: 与已有认知同抽象层或更窄 → 应 update 已有而非 add; 只印证不新增 → 应 touch; 引擎标注'疑似重复'仍 add → 整包拒。
【范例】
{"episode": "m0003", "decision": "add", "kind": "belief", "subject": "我对老师的信任", "text": "老师是第一个不嫌弃我的人——把猫抱到我腿边这种小事, 都让我 觉得自己也被放在心上。", "significance": 0.9}

【touch 释义】episode 只是再次印证了某条已有认知——连一条边即可。
语义:
何时用: 引擎候选标注'疑似印证'或你判断新经历只是重复已知相处模式;
怎么改: 什么都不改——引擎自动把 episode 链到 target 认知;
禁什么: 禁止带 patch/content——印证不动原文（改动只发生在 update）。
【范例】
{"episode": "m0001", "decision": "touch", "target": "u0002", "note": "又是老师带猫粮来喂, 印证了猫粮约定"}

【update 释义】新经历带来新角度/修正/深化——改写既有认知并连接。
语义:
何时用: 找到同主题认知, 新经历改变/丰富了它;
怎么改: patch 部分字段合并改写——只写要变的字段, 空=保留旧值; 新认知是已有认知的子/超集 → 改宽已有 subject, 不新建;
 新 text 应覆盖新旧理解, 重新表述为连贯结论;
禁什么: 不复制原文进 text; 不改来源（observer）; 不碰出厂基座(canon 只读)。
