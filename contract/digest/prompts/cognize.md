cognitions 规则:
  · **一行一件事**: 一条看法写一行;
  · ⭐ **带 `id` = 改那条已有的 · 不带 `id` = 造一条新的**（`id` 用上方渲染列表里的 `u…`）;
  · ⭐ **改的时候只改你写出来的格子** —— 空 = 不改（`text` 留空 = 正文一个字不动）;
  · ⭐ **边只增加**: `supports` / `contradicts` 是"**再加**这几条", ⛔ 漏写不会删掉任何证据;
  · ⛔ **没有"删证据"这个动作** —— 写错了就再写一行把它说清楚;
  · 带 `id` 的行**至少要写一格**（正文 / 边 / 别的格子）, 否则那一行是空转;
  · ⭐ **没话说就不写** —— 一条都不写也完全合法（`"cognitions": []`）;
  · **一段最多造 {{max_cognitions}} 条新看法**（⭐ **改已有的不算在里面**）—— 造多了就是流水账;
  · 右边只能引用**上方渲染列表里出现过**的 id（编造 id → **整包拒**）;
  · ⛔ **别写 ts / event_seq**（新节点的号由**引擎发**）;
  · ⛔ **已有成分之间的关系不用你判** —— 上一趟已经判过了; 这一趟只写"这一行跟谁相连";
  · **方向不用你操心**: 两端类型天然定了方向（经历 → 看法; 进化那条你只写"从哪条旧看法
    长出来", 图上落成 **旧 → 新**）;
  · ⚠️ **看法 ≠ 经历**: 经历是"这一次发生了什么"（上一趟写完了）; 看法是从它里面看出来的**结论** ——
    写不出一句站得住的结论, 就别造这一条;
  · ⚠️ **一条证据都指不出来的**新看法别造（`supports` / `evolved_from` 至少给一个）——
    在图里没有任何连接的看法, 她以后再也想不起来。

【撞上了就给个交代】【跟这条撞上的现有看法】里有一条跟你这条说的是**同一个结论**时, 别写第二条 ——
  · 差不多、只是要**补细节 / 改措辞** ⇒ 带上它的 `id` **改它**;
  · 只是**又多了一条证据** ⇒ 带上它的 `id` + `supports` 挂上去;
  · **你变了、旧的那句不再成立** ⇒ 造新的 + `evolved_from`;
  · **打架** ⇒ `contradicts`。

【belief 释义】这一段的经历**说出了一个结论** —— 把这个结论写下来。
语义:
何时用: 从**已有的经历**里看得出一个站得住的结论（模式 / 判断 / 她对某件事的看法）;
怎么写: `brief but descriptive` —— **短, 但描述性**（写模式与结论, ⛔ 不复述事件、
  不写成"今天老师又…"那种记叙）;
⭐ **带 `id` 就是改那条已有的**: 看法会随经历变细、变宽、换措辞 —— 那时**只写你要改的格子**,
  其余原样留着; ⛔ 只有"旧的那句**不再成立**"才另造一条（那才是取代, 用 `evolved_from`）;
⭐ **出生自带证据边**: `supports` 点名这条结论是**被哪几条经历**支撑的 ——
  这是它与图连接的唯一方式（没有立足点的看法谁也召不回它）;
⭐ **【这一类事】里印出来的那几条也算数** —— 那是她自己早先认过的"同一类事"
  （引擎会把它们一并算作证据）: 该写"总是 / 每次"就别只写"这一次"; 它们的钥匙
  照样能写进 `supports`;
`contradicts`（可选）: 这条新结论**跟哪几条已有看法打架** —— 写在一行里落**对称边**
  （打架就是打架, 没有方向）; ⛔ 它**不算立足点**: 光跟人打架不构成一条看法;
禁什么: ⛔ 经历本身（"发生了什么"是上一趟的活）· ⛔ 已有成分之间的关系
  （上一趟已经判过了; 只有"这条**新**结论跟谁打架"归你）· ⛔ 空泛的感悟（"要珍惜当下"不是她的结论）。
